# 五维度风险评分计算技能

## 功能

综合五个维度的风险指标，通过加权算法计算每个漏洞的综合风险评分，生成修复优先级排序，并识别高危风险组合。

## 适用场景

当需要从大量漏洞中找出最该先修的、排出修复优先级时，调用本技能。

## 输入

- **漏洞分析结果**：含 CVSS、EPSS、KEV 等基础数据
- **VEX评估结果**：含 VEX 状态和置信度
- **业务影响评估**：各组件对应的业务重要性等级

## 五维度说明

### 维度1：CVSS基础分（权重 30%）

漏洞本身的严重程度，基于 CVSS v3.x 评分。

| CVSS评分 | 映射到0-100 | 说明 |
|---------|-----------|------|
| 9.0 - 10.0 | 90 - 100 | Critical，可远程代码执行 |
| 7.0 - 8.9 | 70 - 89 | High，高危 |
| 4.0 - 6.9 | 40 - 69 | Medium，中危 |
| 0.1 - 3.9 | 1 - 39 | Low，低危 |

**计算公式**：`cvss_score_norm = cvss_score * 10`

### 维度2：EPSS利用概率（权重 20%）

漏洞被利用的可能性，基于 EPSS 评分。

| EPSS | 映射到0-100 | 说明 |
|------|-----------|------|
| ≥ 0.8 | ≥ 80 | 极高，几乎确定正在被利用 |
| 0.5 - 0.8 | 50 - 80 | 高，有公开利用代码 |
| 0.1 - 0.5 | 10 - 50 | 中，理论可利用 |
| < 0.1 | < 10 | 低，利用难度高 |

**计算公式**：`epss_score_norm = epss_score * 100`

### 维度3：CISA KEV已知利用（权重 20%）

漏洞是否已被确认在野外被真实利用。

| KEV状态 | 映射到0-100 | 说明 |
|---------|-----------|------|
| true | 100 | 已知在野利用，实战高风险 |
| false | 0 | 暂无已知在野利用记录 |

**计算公式**：`kev_score_norm = in_kev ? 100 : 0`

### 维度4：VEX可达性状态（权重 15%）

漏洞在当前业务环境中是否实际可达、可利用。

| VEX状态 | 映射到0-100 | 说明 |
|---------|-----------|------|
| affected | 100 | 确定受影响 |
| under_investigation | 60 | 待定，先按中等风险算 |
| not_affected | 10 | 基本不受影响，但保留记录 |
| fixed | 0 | 已修复，无风险 |

**计算公式**：
- affected → 100
- under_investigation → 60
- not_affected → 10
- fixed → 0

> 注意：not_affected 不给 0 分是因为 VEX 判定可能有误，保留一点权重作为安全裕度。

### 维度5：业务影响等级（权重 15%）

受影响组件对应的业务系统重要性。

| 业务等级 | 映射到0-100 | 说明 |
|---------|-----------|------|
| 核心系统 | 100 | 交易、支付、用户核心数据 |
| 重要系统 | 70 | 运营、管理、内部关键流程 |
| 一般系统 | 40 | 内部工具、非关键服务 |
| 测试系统 | 10 | 开发测试环境 |

**计算公式**：按等级直接映射。

## 综合评分算法

```
综合风险分 = 
  CVSS × 0.30 + 
  EPSS × 0.20 + 
  KEV × 0.20 + 
  VEX × 0.15 + 
  业务影响 × 0.15
```

**结果范围**：0 - 100 分

### 优先级分级

根据综合风险分划分优先级：

| 综合分 | 优先级 | 建议行动 |
|-------|--------|---------|
| ≥ 80 | P0 - 紧急 | 立即修复，24小时内 |
| 60 - 79 | P1 - 高 | 本周内修复 |
| 40 - 59 | P2 - 中 | 本迭代内修复 |
| 20 - 39 | P3 - 低 | 下个迭代修复 |
| < 20 | P4 - 可忽略 | 定期跟踪 |

## 高危组合识别

除了单个漏洞的评分，还要识别高危风险组合：

### 组合1：同一组件多漏洞

同一组件有 ≥ 2 个高危及以上漏洞 → 标记为"高危组件"，优先整体升级。

### 组合2：同一调用链多漏洞

多个有漏洞的组件在同一条调用链上 → 可能形成漏洞利用链，组合风险高于单个漏洞之和。

### 组合3：KEV + 公网暴露

在 KEV 目录中 + 公网可达 + 高 CVSS → 极高优先级，立即处理。

## 处理步骤

1. 收集五个维度的原始数据
2. 每个维度归一化到 0-100 分
3. 按权重计算综合风险分
4. 按综合分降序排列
5. 分配优先级等级（P0-P4）
6. 识别高危风险组合
7. 输出最终优先级清单

## 注意事项

- 权重是可以调整的——不同企业、不同业务阶段的风险偏好不同，权重可以根据实际情况调整
- 评分算法必须**透明可解释**——每个漏洞的分数怎么来的，要能拆开给人看，不能是黑盒
- VEX 状态对评分影响很大——not_affected 和 affected 差了 90 分，所以 VEX 判定一定要准，拿不准的标 under_investigation
- 业务影响等级需要业务方确认——安全团队自己拍的业务等级不一定靠谱，最好和业务方对齐
- 高危组合识别是"经验性"的——有些组合风险确实高于单个漏洞之和，但具体高多少不好量化，仅供参考
- 评分是"相对优先级"不是"绝对风险值"——P0 比 P1 更该先修，但不代表 P0 的"实际损失"一定是 P1 的两倍
