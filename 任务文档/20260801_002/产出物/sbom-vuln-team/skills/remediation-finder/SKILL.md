# 修复方案检索技能

## 功能

针对漏洞优先级清单，检索官方修复方案，评估兼容性，输出标准化的修复建议。

> **说明**：本技能基于公开的安全公告知识库提供模拟修复方案。真实生产环境应接入厂商安全公告 API、CVE 详情数据库等权威数据源。

## 适用场景

当需要为已识别的漏洞提供具体的修复方案和升级建议时，调用本技能。

## 输入

- **优先级清单**：按优先级排序的漏洞列表
- **环境信息（可选）**：当前技术栈、框架版本、兼容性约束等

## 修复方案类型

### 类型1：版本升级（Upgrade）

最推荐的修复方式，升级到官方发布的修复版本。

| 升级类型 | 版本变化示例 | 兼容性风险 |
|---------|-------------|-----------|
| 补丁升级 | 2.14.1 → 2.14.2 | 低 —— 通常只修bug，无API变更 |
| 小版本升级 | 2.14 → 2.17 | 中 —— 可能有新功能，偶有废弃API |
| 大版本升级 | 1.x → 2.x | 高 —— 架构变化大，可能大量API不兼容 |

### 类型2：临时缓解（Workaround）

无法立即升级时的临时防护措施。

常见方式：
- 配置安全开关（如设置 JVM 参数禁用危险功能）
- WAF 规则拦截（在网关层拦截攻击载荷）
- 网络隔离（限制受影响组件的网络访问）
- 删除危险功能模块（如移除有漏洞的 jar 包中的特定类）

### 类型3：替代方案（Alternative）

如果组件已停止维护或升级成本太高，考虑替换为其他组件。

## 兼容性评估维度

1. **API兼容性**：新版本是否有破坏性变更？废弃了哪些API？
2. **依赖兼容性**：升级后是否会与其他依赖产生版本冲突？
3. **配置兼容性**：配置文件格式是否变化？
4. **行为变更**：默认行为是否变化？会不会影响业务逻辑？
5. **Java/Python/Node版本要求**：新版本是否要求更高的运行时版本？

## 处理步骤

### 第1步：检索官方修复方案

对每个漏洞，查找官方权威修复信息：
- 厂商安全公告（如 Apache Security Bulletins）
- CVE 详情页（NVD、CVE Details）
- 项目 CHANGELOG / Release Notes
- GitHub Security Advisories

### 第2步：提取修复版本

从官方信息中提取：
- 最早的修复版本号
- 推荐的修复版本（可能不是最早的，而是更稳定的版本）
- 是否有多个维护分支的修复版本（如 2.12.4 / 2.16.0 都修了）

### 第3步：评估升级兼容性

根据版本跨度和组件特性评估兼容性风险：

| 版本跨度 | 兼容性风险 | 评估依据 |
|---------|-----------|---------|
| 补丁级（x.y.z → x.y.z+1） | 低 | 通常只修安全bug，不改功能 |
| 次版本级（x.y → x.y+n） | 中 | 可能有新功能和废弃API，需看changelog |
| 主版本级（x → x+n） | 高 | 架构级变化，通常不兼容 |

**额外加分项**：
- 如果官方明确说"无破坏性变更" → 风险降一级
- 如果是 widely-used 的基础组件（如 log4j、spring）→ 社区资料多，升级踩坑少 → 风险降一级
- 如果项目深度定制了该组件（如大量扩展、继承）→ 风险升一级

### 第4步：查找临时缓解方案

如果升级有困难，查找官方推荐的临时缓解措施：
- 官方安全公告中的 "Workaround" / "Mitigation" 节
- 社区验证过的防护方案
- 注意：临时缓解必须是**官方推荐**的，不能用野路子

### 第5步：标注来源和工作量估算

每个方案必须标注：
- 来源链接（官方公告URL）
- 预估工作量（人天/小时）
- 风险提示（需要注意什么）

## 注意事项

- **永远优先推荐官方修复版本升级**——临时缓解只是权宜之计，不能替代真正的修复
- **兼容性评估是"预判"不是"保证"**——实际升级前必须在测试环境验证，特别是大版本跨越
- **必须标注来源**——修复方案必须有官方出处，不能瞎编。客户问"这个方案靠谱吗"，要能拿出官方链接
- **预估工作量是参考值**——实际工作量取决于项目复杂度、测试覆盖度、部署流程等因素
- 对于高兼容性风险的升级方案，必须明确标注"建议充分测试后再上线"
- 临时缓解方案必须说明局限性——不能让客户误以为"加个配置就万事大吉了"
- 有些漏洞有多个修复版本（不同维护分支），要根据客户当前版本推荐最合适的，不一定是最新的
