# 第6轮：4种工业级多Agent策略深度解析

## 用户提问

专家请详细讲解一下上面你表格中提及的四种模式，他们实现方式 优势 劣势 应用场景等所有内容。越深入越好。

## 专家回答

### 策略1：预设层级（Preset Hierarchy）

**实现方式**：
- 在代码中预先定义好所有Agent角色和汇报关系
- 类似MetaGPT的产品经理→架构师→工程师→QA的固定流水线
- CrewAI的Sequential/Hierarchical Process
- AutoGen的GroupChat预设角色

**优势**：
- 行为可预测，调试容易
- 不会出现递归陷阱
- 每个角色职责明确
- Token消耗可控

**劣势**：
- 灵活性差，遇到未预设的任务类型就失效
- 不能根据任务复杂度动态调整
- 角色定义需要人工精心设计
- 扩展性差，加新角色需要改代码

**应用场景**：
- 标准化流程任务（如软件开发流水线）
- 需求明确、步骤固定的业务流程
- 对可预测性要求高的场景

**代表框架**：MetaGPT、CrewAI、固定流程AutoGen

---

### 策略2：有限扇出（Limited Fan-out）

**实现方式**：
- 主Agent动态创建子Agent（扇出）
- 子Agent完成后结果汇总回主Agent（扇入）
- **关键限制：子Agent不能再创建子Agent（不递归）**
- AgentScope的FanoutPipeline、LangGraph的Map-Reduce模式

**优势**：
- 比预设层级灵活，能动态分配任务
- 天然并行，多个子Agent同时工作
- 不会递归爆炸，深度固定为2层
- 实现相对简单

**劣势**：
- 只能2层，子任务仍然复杂时无法再分解
- 主Agent成为瓶颈，需要处理所有子Agent的结果
- 子Agent之间无法直接协作（除非通过主Agent中转）
- 扇出数量需要控制（通常3-7个）

**应用场景**：
- 批量处理任务（如分析多个文件、处理多个数据源）
- 可以并行的独立子任务
- 研究型任务（多角度并行调研）

**代表框架**：AgentScope FanoutPipeline、LangGraph Map-Reduce、Claude Code Sub Agent

---

### 策略3：上下文压缩（Context Compression）

**实现方式**：
三个压缩级别：
1. **摘要压缩**：子Agent结果由LLM生成摘要，只传递摘要而非完整内容
2. **结构化压缩**：将结果转为结构化格式（JSON/表格），去除冗余
3. **标签化记忆**：用Mark标签标记重要信息，检索时只召回相关片段

**优势**：
- 显著减少Token消耗
- 保留关键信息，去除噪音
- 可以和其他策略组合使用
- Anthropic的实践证明有效

**劣势**：
- 压缩本身消耗Token（需要额外LLM调用）
- 过度压缩导致信息丢失
- 摘要可能引入偏差（LLM可能错误总结）
- 需要精心设计压缩策略

**应用场景**：
- 长文档处理
- 多轮对话历史管理
- 多层Agent间信息传递
- Memory模块的长期记忆检索

**代表框架**：AgentScope Memory压缩、LangGraph Checkpointer、Anthropic Claude上下文管理

---

### 策略4：动态子Agent（Dynamic Sub-Agents）

**实现方式**：
- 允许Agent动态创建子Agent，类似策略2
- 但加了三层硬限制：
  1. **深度限制**：最多递归N层（通常2-3层）
  2. **数量限制**：同时存在的子Agent不超过M个（通常5-10个）
  3. **步骤限制**：每个子Agent最多执行K步ReAct循环
- Claude Code的Sub Agent模式、LangGraph的动态子图

**优势**：
- 最灵活，能处理真正复杂的任务
- 有限递归避免无限爆炸
- 子Agent可以有独立上下文（隔离房间）
- 子Agent完成后自动清理（生命周期管理）

**劣势**：
- 实现最复杂，需要考虑大量边界条件
- 调试困难，多层嵌套时难以追踪问题
- 成本仍然较高（虽然有上限）
- 递归深度超过2层时信息失真严重

**应用场景**：
- 软件工程（主Agent创建前端/后端/测试子Agent）
- 复杂研究任务（调研→分析→撰写各层子Agent）
- 需要深度分解的复杂问题

**代表框架**：Claude Code、LangGraph（子图）、AgentScope 2.0 Agent Team

---

### 关键洞察：策略是可组合的

工业界生产级系统通常**组合使用多种策略**：
- 外层：预设层级（CEO→部门经理）
- 中层：有限扇出（经理→员工并行）
- 内层：上下文压缩（员工结果摘要回传）
- 局部：动态子Agent（特殊复杂任务临时招人）

### 决策矩阵

| 场景 | 推荐策略 |
|------|----------|
| 流程固定、可预测 | 预设层级 |
| 并行独立子任务 | 有限扇出 |
| 长文档/多轮对话 | 上下文压缩 |
| 复杂且不确定的任务 | 动态子Agent（带限制） |
| 生产级复杂系统 | 策略组合 |

## 本轮核心知识点

- 预设层级：固定角色，可预测但不灵活（MetaGPT/CrewAI）
- 有限扇出：动态创建但不递归，天然并行（AgentScope/LangGraph）
- 上下文压缩：3级压缩（摘要/结构化/标签化），减少Token消耗
- 动态子Agent：允许递归但有3层硬限制（深度/数量/步骤）
- 生产级系统：策略组合而非单一策略
