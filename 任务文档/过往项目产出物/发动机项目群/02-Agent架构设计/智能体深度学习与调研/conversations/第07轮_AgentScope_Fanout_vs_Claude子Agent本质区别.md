# 第7轮：AgentScope Fan-out vs Claude Code 子Agent本质区别

## 用户提问

我还是不太理解 AgentScope 的这个模式。不也是主 Agent 和子 Agent 吗？它和下边你写的那个Claude Code 的那个主 Agent 子 Agent 这俩本质上有什么区别呀？我这块还是不太理解。

## 专家回答

### 核心区别：信息流方向不同，不是结构不同

表面上看，两者都是"主Agent+子Agent"结构，但本质区别在于**信息流模式**：

### Claude Code模式："独立房间"（Isolated Rooms）

```
主Agent
  ├── 子Agent A（独立房间，只有A和主Agent能看到）
  │     └── A的工作过程对其他人完全不可见
  │     └── A完成后只向主Agent返回结果摘要
  ├── 子Agent B（独立房间，只有B和主Agent能看到）
  │     └── B看不到A在做什么
  └── 子Agent C（独立房间）
        └── C看不到A和B
```

**特点**：
- 每个子Agent有**完全独立的上下文窗口**
- 子Agent之间**互不可见**，完全隔离
- 子Agent看不到主Agent的完整对话历史，只收到分配给自己的任务描述
- 子Agent完成后，只向父Agent返回**结果摘要**，不返回中间过程
- 类比：领导把你叫到办公室单独布置任务，你不知道同事在做什么，完成后只交报告给领导

### AgentScope模式："微信群"（MsgHub）

```
MsgHub（共享消息空间）
  ├── 主Agent（发消息到群里）
  ├── 子Agent A（在群里，能看到所有消息）
  ├── 子Agent B（在群里，能看到所有消息）
  └── 子Agent C（在群里，能看到所有消息）
```

**特点**：
- 所有Agent在一个**共享消息空间（MsgHub）**中
- 任何Agent发的消息，**所有其他Agent都能看到**
- 每个Agent自己决定是否回复某条消息
- 类比：公司微信群，所有人在一个群里，所有消息广播给所有人，你可以选择回应或沉默

### 六维技术对比

| 维度 | Claude Code（独立房间） | AgentScope（微信群） |
|------|------------------------|---------------------|
| **上下文隔离** | 完全隔离，各自独立窗口 | 完全共享，一个广播域 |
| **信息可见性** | 子Agent互不可见 | 所有消息全员可见 |
| **通信方式** | 父子间单向传递 | 广播式多向通信 |
| **并行效率** | 高，互不干扰 | 中，需判断消息相关性 |
| **协作能力** | 弱，需通过父Agent中转 | 强，自然协作 |
| **Token消耗** | 子Agent只看自己的任务 | 每个Agent都要处理所有消息 |
| **适合场景** | 独立任务、需要隔离 | 协作任务、需要信息共享 |

### 生活类比

- **Claude模式**：考试时每个学生在独立考场，只看到自己的试卷，答完交卷给老师。学生之间不能交流。
- **AgentScope模式**：小组讨论，大家围坐一桌，每个人的发言所有人都听到，可以随时插话回应。

### 什么时候用哪个？

| 任务特征 | 推荐模式 |
|----------|----------|
| 子任务高度独立，不需要协作 | Claude隔离房间 |
| 子任务需要紧密协作、共享信息 | AgentScope MsgHub |
| 任务涉及敏感数据（各部门数据隔离） | Claude隔离房间 |
| 需要头脑风暴、多角度讨论 | AgentScope MsgHub |
| 并行执行减少等待时间 | Claude隔离房间 |
| 需要互相纠错、补充 | AgentScope MsgHub |

## 本轮核心知识点

- 本质区别不是结构，是**信息流**
- Claude模式：独立房间，上下文隔离，子Agent互不可见，只返回摘要给父Agent
- AgentScope模式：微信群，MsgHub共享广播，全员可见所有消息
- 6个维度对比：隔离性、可见性、通信、效率、协作、Token消耗
- 选择依据：任务独立性vs协作需求
