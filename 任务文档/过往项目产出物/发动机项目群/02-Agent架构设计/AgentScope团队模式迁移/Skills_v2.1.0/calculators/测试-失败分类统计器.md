# 测试-失败分类统计器

## name
测试-失败分类统计器

## description
对测试失败记录按类别（缺陷类型）、模块（功能模块）和严重度（致命/严重/一般/轻微）进行多维度分类统计，输出失败分布图表和热点分析。适用场景：测试报告生成、缺陷分析会议、质量趋势回顾、回归测试策略制定。触发词：失败分类、测试失败统计、缺陷分类、bug分布。排除词：根因分析、缺陷趋势预测。

## inputs
### 必填参数
| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| 失败记录列表 | array[object] | 每条失败记录包含模块、类别、严重度 | [{module:"支付模块", category:"逻辑错误", severity:"严重", desc:"金额计算异常"}] |

### 可选参数
| 参数名 | 类型 | 说明 | 估值逻辑 |
|--------|------|------|----------|
| 时间段 | string | 统计分析的时间范围 | 默认"最近一周"，可选"当天"/"最近一周"/"最近一月"/"本迭代" |
| 分类维度 | array[string] | 选定的分类维度 | 默认["类别","模块","严重度"]，可组合选择 |
| 排序方式 | string | 排序维度 | 默认"失败数降序" |
| 对比基准 | string | 是否与上一周期对比 | 默认"否"，可选"上一迭代"/"上一版本" |

## formula
按类别统计: 类别_i_失败数 = COUNT(失败记录 WHERE 类别 = 类别_i)
按模块统计: 模块_j_失败数 = COUNT(失败记录 WHERE 模块 = 模块_j)
按严重度统计: 严重度_k_失败数 = COUNT(失败记录 WHERE 严重度 = 严重度_k)

各类别占比 = 类别_i_失败数 / 总失败数 × 100%
各模块占比 = 模块_j_失败数 / 总失败数 × 100%
严重度占比 = 严重度_k_失败数 / 总失败数 × 100%

热点模块 = 失败数最多的模块
热点类别 = 失败数最多的类别

## output
| 字段名 | 类型 | 说明 |
|--------|------|------|
| 总失败数 | int | 失败记录总数 |
| 按类别分布 | array[object] | 各缺陷类型的失败数及占比 |
| 按模块分布 | array[object] | 各功能模块的失败数及占比 |
| 按严重度分布 | array[object] | 各严重度等级的失败数及占比 |
| 热点模块 | string | 失败数最多的模块 |
| 热点类别 | string | 失败数最多的缺陷类型 |
| 致命/严重失败占比 | float | 致命和严重级别失败占总数的比例 |
| 分析总结 | string | 基于分布的结论和建议 |

## example
【输入】
失败记录列表: [
  {module:"支付模块", category:"逻辑错误", severity:"严重", desc:"金额计算异常"},
  {module:"支付模块", category:"边界条件", severity:"一般", desc:"0元订单未拦截"},
  {module:"登录模块", category:"兼容性", severity:"轻微", desc:"iOS 15样式异常"},
  {module:"订单模块", category:"逻辑错误", severity:"致命", desc:"重复下单未去重"},
  {module:"订单模块", category:"性能问题", severity:"严重", desc:"列表加载超时"},
  {module:"支付模块", category:"并发问题", severity:"严重", desc:"并发扣款重复"},
  {module:"登录模块", category:"逻辑错误", severity:"严重", desc:"SSO回调失败"},
  {module:"订单模块", category:"数据一致", severity:"致命", desc:"库存扣减不一致"}
]

【输出】
总失败数: 8

按类别分布:
- 逻辑错误: 3 (37.5%)
- 并发问题: 1 (12.5%)
- 边界条件: 1 (12.5%)
- 兼容性: 1 (12.5%)
- 性能问题: 1 (12.5%)
- 数据一致: 1 (12.5%)

按模块分布:
- 支付模块: 3 (37.5%)
- 订单模块: 3 (37.5%)
- 登录模块: 2 (25.0%)

按严重度分布:
- 致命: 2 (25.0%)
- 严重: 4 (50.0%)
- 一般: 1 (12.5%)
- 轻微: 1 (12.5%)

热点模块: 支付模块、订单模块（并列）
热点类别: 逻辑错误
致命/严重失败占比: 75.0%

分析总结: 支付和订单模块是质量重灾区，合计占75%的失败。致命和严重级别失败占比高达75%，发布风险极高。逻辑错误是最突出的缺陷类型（37.5%），建议加强代码审查和单元测试。
