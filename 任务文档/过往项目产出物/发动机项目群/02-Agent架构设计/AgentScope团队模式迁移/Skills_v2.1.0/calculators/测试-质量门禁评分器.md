# 测试-质量门禁评分器

## name
测试-质量门禁评分器

## description
对测试通过率、代码覆盖率、性能SLA达成率和缺陷密度等多个质量指标进行加权综合评分，判定是否通过质量门禁，输出各维度得分和综合判定。适用场景：CI/CD流水线质量门禁、发布前质量评审、版本质量评估。触发词：质量门禁、质量评分、发布评审、版本质量。排除词：代码覆盖率、缺陷密度、性能测试。

## inputs
### 必填参数
| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| 测试通过率 | float | 测试用例执行通过的比例（%） | 95.5 |
| 代码覆盖率 | float | 代码行覆盖率（%） | 85.0 |
| 性能SLA达成率 | float | 性能指标满足SLA的比例（%） | 98.0 |
| 缺陷密度 | float | 每千行代码缺陷数 | 1.5 |

### 可选参数
| 参数名 | 类型 | 说明 | 估值逻辑 |
|--------|------|------|----------|
| 测试通过率权重 | float | 测试通过率在综合评分中的权重 | 默认0.30 |
| 代码覆盖率权重 | float | 代码覆盖率在综合评分中的权重 | 默认0.25 |
| 性能SLA权重 | float | 性能SLA在综合评分中的权重 | 默认0.25 |
| 缺陷密度权重 | float | 缺陷密度在综合评分中的权重 | 默认0.20 |
| 通过率阈值 | float | 测试通过率最低门槛 | 默认95% |
| 覆盖率阈值 | float | 代码覆盖率最低门槛 | 默认80% |
| 性能SLA阈值 | float | 性能SLA最低达成率 | 默认95% |
| 缺陷密度上限 | float | 缺陷密度最高上限 | 默认3.0个/KLOC |
| 最低综合评分 | float | 通过门禁的最低综合评分 | 默认75分 |
| 附加指标 | array[object] | 额外质量指标及权重 | 默认空，按需添加如安全漏洞数、技术债务率等 |

## formula
各指标得分计算:
- 测试通过率得分 = min(测试通过率 / 通过率阈值 × 100, 100)
- 代码覆盖率得分 = min(代码覆盖率 / 覆盖率阈值 × 100, 100)
- 性能SLA得分 = min(性能SLA达成率 / 性能SLA阈值 × 100, 100)
- 缺陷密度得分 = max(0, (1 - 缺陷密度/缺陷密度上限) × 100)

综合评分 = Σ(指标_i得分 × 权重_i)

门禁判定:
- 综合评分 ≥ 80: 通过（优秀）
- 75 ≤ 综合评分 < 80: 通过（有条件）
- 综合评分 < 75: 不通过

一票否决: 任一必填指标低于其最低门槛，直接判定不通过。

## output
| 字段名 | 类型 | 说明 |
|--------|------|------|
| 综合评分 | float | 加权综合质量评分 |
| 测试通过率得分 | float | 测试通过率维度得分 |
| 代码覆盖率得分 | float | 代码覆盖率维度得分 |
| 性能SLA得分 | float | 性能SLA维度得分 |
| 缺陷密度得分 | float | 缺陷密度维度得分 |
| 门禁判定 | string | 通过（优秀）/通过（有条件）/不通过 |
| 一票否决项 | array[string] | 触发一票否决的指标列表 |
| 薄弱项 | array[string] | 得分最低的维度 |
| 改进建议 | string | 针对薄弱项的具体改进建议 |

## example
【输入】
测试通过率: 95.5%
代码覆盖率: 85.0%
性能SLA达成率: 98.0%
缺陷密度: 1.5 个/KLOC
各权重: 默认
各阈值: 默认

【输出】
测试通过率得分: 100.0 (95.5% vs 阈值95%)
代码覆盖率得分: 100.0 (85.0% vs 阈值80%)
性能SLA得分: 100.0 (98.0% vs 阈值95%)
缺陷密度得分: 50.0 (1.5 vs 上限3.0)

综合评分: 30×1.0 + 25×1.0 + 25×1.0 + 20×0.5 = 90.0

门禁判定: 通过（优秀）
一票否决项: 无
薄弱项: 缺陷密度（得分50.0，尚有改进空间）

改进建议: 综合评分90分，质量门禁通过。缺陷密度1.5个/KLOC处于良好水平，但得分仅50分，建议下一迭代将缺陷密度目标降至1.0以下，进一步提升整体质量评分。
