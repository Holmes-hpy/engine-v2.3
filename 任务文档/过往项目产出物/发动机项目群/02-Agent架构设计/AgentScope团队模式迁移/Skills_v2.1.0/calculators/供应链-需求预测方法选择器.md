# 供应链-需求预测方法选择器

## name
供应链-需求预测方法选择器

## description
根据历史需求数据的特征（趋势性、季节性、促销频率、数据量等），自动推荐最合适的预测方法及置信度。作为预测方法的决策路由引擎，帮助供应链团队在ARIMA、Holt-Winters、促销增量等预测方法之间做出最优选择。适用于需求预测体系搭建、预测方法选型、预测准确率优化等场景。触发词：预测方法选择、预测模型选型、需求预测方法、预测推荐、预测路由。排除词：预测执行（指具体预测计算）、模型训练（指机器学习模型训练）。

## inputs
### 必填参数
| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| data_features | object | 历史数据特征描述 | {"trend":true,"seasonality":true,"promo_frequency":"high","data_points":36} |

### 可选参数
| 参数名 | 类型 | 说明 | 估值逻辑 |
|--------|------|------|----------|
| forecast_horizon | string | 预测周期（short/medium/long） | 默认short（短期1-4周）；中期(1-3月)、长期(3-12月) |
| data_granularity | string | 数据粒度（daily/weekly/monthly） | 默认monthly |
| business_context | string | 业务场景（regular/promotion/new_product/spare_parts） | 默认regular（常规品）；促销品/新品/备件场景影响方法选择 |
| accuracy_requirement | string | 精度要求（high/medium/low） | 默认medium；高精度要求偏向集成方法 |
| computational_resource | string | 计算资源（limited/moderate/abundant） | 默认moderate；资源受限时偏向简单方法 |

## formula
推荐矩阵（基于数据特征的方法选择）：

| 趋势性 | 季节性 | 促销频率 | 数据量 | 推荐方法 | 置信度 |
|--------|--------|----------|--------|----------|--------|
| 有 | 有 | 低 | ≥24 | Holt-Winters | 高 |
| 有 | 无 | 低 | ≥24 | ARIMA | 高 |
| 有 | 有 | 高 | ≥36 | 促销增量 + Holt-Winters | 高 |
| 有 | 无 | 高 | ≥36 | 促销增量 + ARIMA | 高 |
| 无 | 有 | 低 | ≥24 | 季节分解 + 移动平均 | 中 |
| 无 | 无 | 低 | ≥12 | 简单指数平滑 | 中 |
| 无 | 无 | 高 | ≥24 | 促销增量 + 指数平滑 | 中 |
| 任意 | 任意 | 任意 | <12 | 简单移动平均 | 低 |
| 任意 | 任意 | 任意 | <6 | 朴素预测（naive） | 极低 |

特殊场景方法推荐：
- 新品：没有历史数据 → 类比法（参考同类老品上市曲线）
- 备件：间歇性需求 → Croston方法
- 高促销+大促：配合促销日历的促销增量预测
- 长尾SKU：聚合预测再分解（Top-Down方法）

方法选择流程图：
1. 数据量 < 6 → 朴素预测（使用上期值作为预测）
2. 数据量 6-12 → 简单移动平均（3-6期窗口）
3. 数据量 ≥ 12：
   a. 检测趋势性 → 有趋势进入步骤b，无趋势进入步骤c
   b. 检测季节性 → 有季节性优先Holt-Winters，无季节性优先ARIMA
   c. 检测促销影响 → 有促销叠加促销增量模块
   d. 新品场景 → 使用类比法
   e. 备件场景 → 使用Croston方法

计算步骤：
1. 解析data_features中的各项特征
2. 按推荐矩阵逐条件匹配
3. 确定首选推荐方法和备选方法
4. 计算置信度（基于数据量和特征完整性）
5. 输出推荐理由和方法使用说明

## output
| 字段名 | 类型 | 说明 |
|--------|------|------|
| primary_method | string | 首选推荐方法 |
| alternative_method | string | 备选推荐方法 |
| confidence | float | 推荐置信度（0-1） |
| reasoning | string | 推荐理由 |
| data_requirements | object | 该方法的数据要求 |
| limitations | array[string] | 方法局限性 |
| implementation_notes | string | 实施注意事项 |

## example
**输入：**
```
data_features: {
  "trend": true,
  "seasonality": true,
  "promo_frequency": "high",
  "data_points": 48
}
forecast_horizon: "medium"
data_granularity: "monthly"
business_context: "regular"
```

**计算过程：**
1. 数据量48 ≥ 36 → 足够
2. 趋势性：有 → 需要趋势处理方法
3. 季节性：有 → 需要季节性处理方法
4. 促销频率：高 → 需要促销增量模块
5. 匹配推荐矩阵：有趋势+有季节+高促销+数据量≥36 → 促销增量 + Holt-Winters
6. 置信度：数据量充足(48个月)、特征明确 → 高置信度

**输出：**
```
primary_method: "促销增量 + Holt-Winters"
alternative_method: "促销增量 + SARIMA"
confidence: 0.88
reasoning: "该需求数据具有明显趋势和季节性，且促销频率高。推荐使用Holt-Winters作为基线的原因是：(1)对趋势和季节性的捕捉能力强；(2)相比SARIMA更易解释和调参；(3)与促销增量模块结合时表现稳定。48个月数据量充足，推荐置信度高。"
data_requirements: {
  "minimum_data_points": 24,
  "seasonality_cycles": "至少2个完整季节周期",
  "promo_calendar": "需要促销日历数据"
}
limitations: [
  "Holt-Winters对突发事件（如疫情封控）敏感度低，需人工干预",
  "促销增量模块依赖准确的弹性系数估算",
  "长期预测（>12个月）置信度会显著下降"
]
implementation_notes: "建议每月更新一次模型参数，促销弹性系数需根据每次大促的实际表现进行校准。新品上市期间建议暂停自动预测，使用人工判断辅助。"
```
