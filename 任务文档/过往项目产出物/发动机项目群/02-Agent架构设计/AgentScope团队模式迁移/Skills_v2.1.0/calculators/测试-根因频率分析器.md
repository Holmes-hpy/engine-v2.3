# 测试-根因频率分析器

## name
测试-根因频率分析器

## description
对已标注根因的测试失败记录进行频率统计和帕累托分析，排序识别最频繁的根因，输出根因排序和帕累托图表，帮助团队聚焦解决核心问题。适用场景：缺陷复盘会议、根因分析报告、质量改进计划、技术债务优先级排序。触发词：根因分析、Root Cause Analysis、帕累托分析、缺陷根因统计。排除词：失败分类、缺陷密度、缺陷趋势。

## inputs
### 必填参数
| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| 根因标注的失败记录 | array[object] | 至少包含失败描述和根因标签 | [{failure:"支付超时", root_cause:"第三方接口超时", count:15}] |

### 可选参数
| 参数名 | 类型 | 说明 | 估值逻辑 |
|--------|------|------|----------|
| 帕累托阈值 | float | 累积占比达到多少时视为"主要根因" | 默认80%，遵循帕累托80/20原则 |
| 时间范围 | string | 分析的时间范围 | 默认"本迭代"，可选"最近一月"/"最近一季度" |
| 根因层级 | int | 根因分析的层级深度 | 默认1层，更深层级需提供层级数据 |
| 团队维度 | string | 是否按团队分组统计 | 默认"否"，需提供团队归属信息 |

## formula
根因_i_频率 = COUNT(失败记录 WHERE 根因 = 根因_i)
根因_i_占比 = 根因_i_频率 / 总失败数 × 100%
累积占比 = 按频率降序排列后的累积占比

帕累托判定:
- 累积占比 ≤ 80%: 主要根因（少数关键）
- 累积占比 > 80%: 次要根因（多数琐碎）

## output
| 字段名 | 类型 | 说明 |
|--------|------|------|
| 总失败记录数 | int | 根因标注的总失败数 |
| 根因排序表 | array[object] | 按频率降序的根因列表，含频率、占比、累积占比 |
| 主要根因列表 | array[string] | 累积占比在帕累托阈值内的根因 |
| 次要根因列表 | array[string] | 累积占比超出帕累托阈值的根因 |
| 主要根因占比 | float | 主要根因的累积占比 |
| 根因类别数 | int | 不同的根因类别总数 |
| 改进建议 | string | 针对主要根因的改进建议 |

## example
【输入】
根因标注的失败记录: [
  {failure:"支付超时", root_cause:"第三方接口超时", count:35},
  {failure:"空指针异常", root_cause:"缺乏空值校验", count:28},
  {failure:"数据不一致", root_cause:"事务边界不当", count:18},
  {failure:"并发冲突", root_cause:"锁粒度不足", count:12},
  {failure:"样式错乱", root_cause:"CSS全局污染", count:7},
  {failure:"性能降级", root_cause:"缓存策略失效", count:5},
  {failure:"权限绕过", root_cause:"鉴权中间件遗漏", count:3}
]

【输出】
总失败记录数: 108

根因排序表（帕累托）:
1. 第三方接口超时: 35次 (32.4%, 累积32.4%)
2. 缺乏空值校验: 28次 (25.9%, 累积58.3%)
3. 事务边界不当: 18次 (16.7%, 累积75.0%)
4. 锁粒度不足: 12次 (11.1%, 累积86.1%)
5. CSS全局污染: 7次 (6.5%, 累积92.6%)
6. 缓存策略失效: 5次 (4.6%, 累积97.2%)
7. 鉴权中间件遗漏: 3次 (2.8%, 累积100%)

主要根因列表（80%阈值）:
- 第三方接口超时
- 缺乏空值校验
- 事务边界不当

次要根因列表:
- 锁粒度不足、CSS全局污染、缓存策略失效、鉴权中间件遗漏

主要根因占比: 75.0%
根因类别数: 7

改进建议: 3个主要根因贡献了75%的失败，应优先解决：(1)针对第三方接口超时，增加超时重试和熔断机制；(2)针对空值校验，在代码规范中强制空值检查，引入静态分析工具；(3)针对事务边界，梳理业务流程事务边界，统一事务管理规范。
