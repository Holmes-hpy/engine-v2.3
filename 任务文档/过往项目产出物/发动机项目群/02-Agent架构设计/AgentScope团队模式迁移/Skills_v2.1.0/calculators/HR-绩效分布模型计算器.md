# HR-绩效分布模型计算器

## name
HR-绩效分布模型计算器

## description
根据选定的绩效分布模型（阿里361/华为ABC/字节FIMO）和团队人数，自动计算各绩效等级的人数分布方案，输出绩效分布表和强制分布方案。适用场景：绩效评估、人才盘点、绩效考核方案设计、强制分布实施。触发词：绩效分布、361分布、强制分布、绩效等级、人才九宫格。排除词：OKR评分、KPI计算、绩效奖金。

## inputs
### 必填参数
| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| 模型选择 | string | 绩效分布模型 | "阿里361" / "华为ABC" / "字节FIMO" |
| 团队人数 | int | 参与绩效评估的团队总人数 | 30 |

### 可选参数
| 参数名 | 类型 | 说明 | 估值逻辑 |
|--------|------|------|----------|
| 自定义比例 | object | 自定义各等级的比例 | 默认按选定模型的标准比例 |
| 人数取整方式 | string | 非整数人数时的取整方式 | 默认"四舍五入"，可选"向上取整"/"向下取整"/"四舍五入" |
| 管理层级 | string | 团队管理层级 | 默认"全员"，可选"基层"/"中层"/"高层" |
| 特殊人员 | array[string] | 不参与强制分布的人员 | 默认空，如试用期员工、产假员工等 |
| 调整因子 | float | 等级比例的微调系数 | 默认1.0，范围0.8-1.2 |

## formula
阿里361模型:
- 3（优秀/前30%）: 人数 = 团队人数 × 30%
- 6（良好/中间60%）: 人数 = 团队人数 × 60%
- 1（待改进/后10%）: 人数 = 团队人数 × 10%

华为ABC模型:
- A（杰出贡献者/前10-15%）: 人数 = 团队人数 × 15%
- B+（优秀贡献者/15-25%）: 人数 = 团队人数 × 25%
- B（扎实贡献者/50-60%）: 人数 = 团队人数 × 50%
- C（待改进/后10%）: 人数 = 团队人数 × 10%

字节FIMO模型:
- F（Fantastic/杰出/前10%）: 人数 = 团队人数 × 10%
- I（Influential/影响/15-20%）: 人数 = 团队人数 × 20%
- M（Meeting/胜任/60-65%）: 人数 = 团队人数 × 60%
- O（Opportunity/待提升/后10%）: 人数 = 团队人数 × 10%

## output
| 字段名 | 类型 | 说明 |
|--------|------|------|
| 模型名称 | string | 选定的绩效分布模型 |
| 团队总人数 | int | 参与评估的总人数 |
| 分布方案 | array[object] | 各等级的名称、比例和人数 |
| 实际总人数 | int | 取整后的实际总人数 |
| 人数偏差 | int | 取整后与原始团队人数的偏差 |
| 分布说明 | string | 该模型的核心理念和使用场景 |
| 实施建议 | string | 实施该模型的注意事项 |

## example
【输入】
模型选择: "阿里361"
团队人数: 30

【输出】
模型名称: 阿里361模型
团队总人数: 30

分布方案:
- 3（优秀）: 30 × 30% = 9人
- 6（良好）: 30 × 60% = 18人
- 1（待改进）: 30 × 10% = 3人

实际总人数: 30（无需调整）
人数偏差: 0

分布说明: 阿里361模型是阿里巴巴经典的绩效分布模型，将团队分为前30%优秀、中间60%良好、后10%待改进三个等级。核心逻辑是"奖优罚劣"，前30%获得大部分奖金和晋升机会，后10%可能面临绩效改进计划或淘汰。

实施建议: (1)30人团队"1"等级仅3人，需确保评价标准客观公正；(2)建议结合360度反馈和量化指标避免主观偏见；(3)对"1"等级员工需制定明确的绩效改进计划(PIP)；(4)注意小团队(少于10人)不宜强制使用361模型。
