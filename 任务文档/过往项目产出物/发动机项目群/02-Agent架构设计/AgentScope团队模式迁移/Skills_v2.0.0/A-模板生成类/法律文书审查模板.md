## 二、执行逻辑

### 步骤1：文件摘要提取

**提取规则：**

| 要素 | 提取方法 | 输出格式 |
|------|---------|---------|
| 签约方 | 匹配"甲方/乙方"、"合同主体"、"签约方"等段落 | 甲方：{name}（注册地/统一社会信用代码） |
| 核心条款 | 提取"标的"、"服务内容"、"供货范围"等段落 | 摘要50字以内 |
| 合同金额 | 匹配金额数字+货币单位模式 | {currency} {amount}（含税/不含税） |
| 合同期限 | 匹配"生效日期"、"终止日期"、"期限" | {start} 至 {end}（含续约条款） |
| 管辖条款 | 匹配"争议解决"、"管辖"、"仲裁" | 管辖法院/仲裁机构：{name} |
| 付款条件 | 匹配"付款"、"支付"、"结算" | 付款方式/周期/条件 |
| 违约责任 | 匹配"违约"、"赔偿"、"罚款" | 违约金/赔偿上限 |
| 保密条款 | 匹配"保密"、"机密"、"商业秘密" | 保密期限/范围/例外 |

**关键词匹配算法：**
```
1. 基于特定合同类型加载关键词库
2. 逐段扫描，标记包含关键词的段落
3. 使用正则提取关键信息模式：
   - 金额：/(\d+[\d,]*\.?\d*)\s*(元|人民币|USD|EUR|SGD)/
   - 日期：/\d{4}[年\-\/]\d{1,2}[月\-\/]\d{1,2}日?/
   - 期限：/(\d+)\s*(年|月|日|天)/
4. 对于无法自动提取的要素，标注"需人工确认"
```

### 步骤2：风险条款分级标记

**高风险条款库（红色标记）：**

| 风险类型 | 触发关键词/模式 | 风险等级 | 审查要点 |
|---------|---------------|---------|---------|
| 无限赔偿责任 | "全部损失"、"无限责任"、"所有损害" | 高 | 是否约定了责任上限 |
| 单方终止权 | "甲方有权单方解除"、"任意解除" | 高 | 终止条件是否对等 |
| 知识产权归属不明确 | "知识产权"但未明确归属 | 高 | 成果归属是否清晰 |
| 过度保密义务 | 保密期限"永久"、"无限期" | 高 | 保密期限是否合理 |
| 竞业限制过宽 | 竞业范围覆盖"全部业务" | 高 | 竞业限制是否合理 |
| 管辖不利 | 约定对方所在地管辖 | 高 | 管辖是否公平 |
| 自动续约 | "自动续期"、"自动续约" | 中 | 是否有退出机制 |
| 模糊的验收标准 | 验收标准使用"满意"、"合理"等主观词 | 中 | 验收标准是否客观 |

**风险评分算法：**
```
for each 条款:
    风险基础分 = 0
    if 匹配高风险关键词:
        风险基础分 = 80
    elif 匹配中风险关键词:
        风险基础分 = 50
    elif 匹配低风险关键词:
        风险基础分 = 20
    
    # 风险容忍度调整
    if risk_tolerance == "conservative":
        风险基础分 ×= 1.2
    elif risk_tolerance == "aggressive":
        风险基础分 ×= 0.8
    
    if 风险基础分 >= 70:
        风险等级 = "高"
    elif 风险基础分 >= 40:
        风险等级 = "中"
    else:
        风险等级 = "低"
```

**修改建议生成：**
```
for 每个高风险条款:
    建议 = 行业最佳实践条款 + 管辖区合规要求
    谈判策略 = if our_role == "服务提供方":
        建议责任上限 = "合同金额的1-2倍"
    elif our_role == "采购方":
        建议责任上限 = "合同金额的2-3倍"
```

### 步骤3：版本比对

**比对算法：**
```
1. 文本分段：按条款编号/标题拆分为段落
2. 段落对齐：使用最长公共子序列（LCS）算法匹配对应段落
3. 差异检测：
   - 新增条款：版本B中有，版本A中无
   - 删除条款：版本A中有，版本B中无
   - 修改条款：相同位置的条款，内容有差异
4. 逐项变更对比：
   - 金额变更：{old_value} → {new_value}（变化幅度{delta}%）
   - 期限变更：{old_term} → {new_term}
   - 条款文字变更：使用diff算法高亮差异
```

**比对输出格式：**

| 条款编号 | 变更类型 | 版本A | 版本B | 风险评估 | 建议 |
|---------|---------|-------|-------|---------|------|
| 第X条 | 修改 | {原文} | {新文} | 低/中/高 | {说明} |
| 第Y条 | 新增 | - | {新文} | 中 | {说明} |
| 第Z条 | 删除 | {原文} | - | 高 | {说明} |

### 步骤4：合规审查

**管辖区检查清单：**

**中国（china）：**
| 审查项 | 依据 | 检查要点 |
|--------|------|---------|
| 合同形式要件 | 《民法典》合同编 | 是否具备必备条款（当事人/标的/数量） |
| 违约金上限 | 《民法典》第585条 | 违约金是否超过损失的30% |
| 格式条款 | 《民法典》第496-498条 | 是否存在无效格式条款 |
| 个人信息保护 | 《个人信息保护法》 | 是否涉及个人信息处理，是否合规 |
| 数据出境 | 《数据出境安全评估办法》 | 是否涉及数据出境 |
| 知识产权 | 《专利法》《著作权法》《商标法》 | 知识产权归属及许可是否明确 |

**美国（us）：**
| 审查项 | 依据 | 检查要点 |
|--------|------|---------|
| 责任限制 | UCC/Common Law | 间接损失排除是否有效 |
| 赔偿条款 | Common Law | 赔偿范围是否合理 |
| 保密条款 | DTSA/State Law | 保密定义是否充分 |
| 管辖/仲裁 | FAA/State Law | 仲裁条款是否可执行 |
| 数据隐私 | CCPA/State Laws | 数据处理是否符合州法 |

**欧盟（eu）：**
| 审查项 | 依据 | 检查要点 |
|--------|------|---------|
| GDPR合规 | GDPR | 数据处理协议是否充分 |
| 标准合同条款 | SCC | 跨境数据传输机制 |
| 消费者保护 | Consumer Rights Directive | B2C合同特殊要求 |
| 不公平条款 | Unfair Contract Terms Directive | 是否存在不公平条款 |
| AI法案 | EU AI Act | 是否涉及AI系统 |

**新加坡（singapore）：**
| 审查项 | 依据 | 检查要点 |
|--------|------|---------|
| 合同确定性 | Contract Law | 条款是否明确 |
| 违约金 | Penalty Rule | 违约金是否构成惩罚性条款 |
| 个人数据 | PDPA | 数据保护义务 |
| 仲裁 | IAA/AA | 仲裁条款可执行性 |

## 四、异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 合同文本为空 | 返回错误提示，要求提供合同文本 |
| 合同文本为扫描件/图片 | 提示需要OCR识别，建议使用结构化文本 |
| 合同类型与管辖区组合不常见 | 使用通用审查模板，标注"该管辖区/合同类型组合无专用模板，使用通用标准" |
| 版本比对两文档差异过大（>50%段落不同） | 提示可能不是同一合同的不同版本，建议确认 |
| 无法识别合同结构（无条款编号） | 使用段落聚类方法自动分段，标注"自动分段，建议人工复核" |
| 特殊关注条款在合同中不存在 | 标注"合同中未涉及{条款类型}，无需审查" |
| 合同语言非中文/英文 | 使用通用字符匹配，标注"非中英文合同，部分关键词匹配可能不准确" |
