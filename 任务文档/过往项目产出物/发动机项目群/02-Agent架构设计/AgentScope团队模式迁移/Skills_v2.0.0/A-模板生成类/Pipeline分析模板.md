## 二、执行逻辑

### 步骤1：Pipeline速度分析（四变量模型）

**核心公式：**

```
1. 阶段平均时长（Days in Stage）：
   AvgDays_stage = Σ(每个商机在该阶段的停留天数) / 该阶段商机数
   异常判定：若某商机停留天数 > 平均 × 2，标记为"停滞"

2. 阶段转化率（Stage Conversion Rate）：
   ConvRate_stage = 进入下一阶段商机数 / 进入当前阶段商机总数
   加权转化率 = 各阶段转化率之积（用于端到端预测）

3. Pipeline流速（Velocity）：
   Velocity = 当前阶段商机数量 × 平均单子金额 × 阶段转化率 / 阶段平均时长
   单位：元/天

4. 加权单子大小（Weighted Deal Size）：
   WeightedDealSize = Σ(单子金额 × 阶段转化率向后连乘) / 商机总数
```

**速度健康度评级：**

| 指标 | 健康 | 警告 | 危险 |
|------|------|------|------|
| 线索→MQL转化率 | >30% | 20%-30% | <20% |
| MQL→SQL转化率 | >40% | 25%-40% | <25% |
| SQL→商务转化率 | >50% | 35%-50% | <35% |
| 商务→成交转化率 | >60% | 40%-60% | <40% |
| 平均销售周期 | <行业p50 | p50-p75 | >p75 |

**决策逻辑：**
```
if 某阶段转化率 < 警告线:
    生成"阶段瓶颈分析"建议，该阶段为重点干预对象
    if 该阶段停留时长 > 平均 × 1.5:
        问题类型 = "效率问题"（流程卡点）
    else:
        问题类型 = "质量/数量问题"（线索质量或商机数量不足）
```

### 步骤2：单子健康评分模型

**三维评分体系：**

| 维度 | 权重 | 子指标 | 评分标准 | 数据来源 |
|------|------|--------|---------|---------|
| 资质深度（40分） | 40% | 预算确认 | 有明确预算=15分，口头确认=8分，未确认=0分 | CRM |
| | | 决策权覆盖 | 对接决策者=10分，影响者=5分，使用者=2分 | CRM |
| | | 需求紧迫度 | 3个月内=10分，6个月内=5分，12个月+ =2分 | 销售判断 |
| | | 采购流程了解 | 清晰流程=5分，模糊=2分，未知=0分 | CRM |
| 互动强度（30分） | 30% | 近30天互动次数 | ≥5次=10分，3-4次=7分，1-2次=3分，0次=0分 | 邮件/电话/会议 |
| | | 决策者参与度 | 参与过会议=10分，仅邮件=5分，未参与=0分 | 会议记录 |
| | | 内容互动深度 | 打开过提案/报价=10分，仅看营销内容=3分 | 文档系统 |
| 推进速度（30分） | 30% | 阶段推进速度 | 快于平均=15分，正常=10分，慢于平均=5分 | 速度分析 |
| | | 推进节点 | 有明确下一步+日期=15分，有下一步无日期=8分，无计划=0分 | CRM |

**健康分计算公式：**
```
HealthScore = 资质深度得分 × 0.40 + 互动强度得分 × 0.30 + 推进速度得分 × 0.30

健康等级：
- ≥80分：健康（绿灯），正常推进
- 60-79分：关注（黄灯），需要额外干预
- 40-59分：风险（橙灯），需要立即介入
- <40分：高危（红灯），可能需要清理
```

### 步骤3：营收预测模型

**三级预测体系：**

```
Commit（承诺）：
  = Σ(健康分≥80的单子金额 × 商务→成交历史转化率 × 0.95)
  （仅纳入健康商机，转化率取近4个季度均值，置信因子0.95）

Best Case（最佳）：
  = Σ(健康分≥60的单子金额 × 商务→成交历史转化率 × 0.85)
  （纳入所有健康+关注商机，置信因子0.85）

Upside（乐观）：
  = Σ(健康分≥40的单子金额 × 商务→成交历史转化率 × 0.70)
  + Σ(新线索预期金额 × 线索→MQL转化率 × MQL→SQL转化率 × SQL→商务转化率 × 商务→成交转化率)
  （纳入所有非红灯商机 + 新线索预期贡献，置信因子0.70）
```

**速度加权调整：**
```
if 平均销售周期 缩短/延长 > 20%:
    Commit 调整 = Commit × (1 + 速度变化率 × 0.5)
    （速度加快→上调预测，速度减慢→下调预测）
```

**季度达成率预测：**
```
QTR达成率 = (Commit + Best Case) / 2 / quota_target
```

### 步骤4：健康看板与干预建议

**看板维度：**
1. Pipeline覆盖倍数 = Pipeline总额 / 当期目标
2. Pipeline健康度 = 绿灯单子金额 / Pipeline总额
3. 阶段集中度 = 最大阶段商机金额占比
4. 销售周期趋势 = 近3个月平均销售周期变化
5. 赢单率趋势 = 近3个月赢单率变化

**干预建议生成逻辑：**
```
if Pipeline覆盖倍数 < 3.0:
    建议 = "Pipeline不足：需增加Top-of-Funnel投入，建议增加线索量X%"
    if 线索→MQL转化率 < 30%:
        建议 += "；同时提升线索质量，优化MQL定义"

if 阶段集中度 > 50%:
    建议 = "阶段集中度过高：存在断流风险，重点推动前阶段商机向后流转"

if 健康度 < 0.6:
    建议 = "Pipeline健康度不足：建议清理红灯商机，释放销售精力"

if 销售周期 > 行业p75:
    建议 = "销售周期过长：建议引入加速器（POC/试用/ROI计算器），缩短决策周期"
```

## 四、异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| Pipeline数据为空 | 返回空报告，提示"当前无活跃商机"，建议检查CRM数据同步 |
| 历史转化率数据缺失 | 使用行业基准值替代，标注"基于行业基准估算，实际可能偏差±15%" |
| 某些商机缺少阶段信息 | 将该商机默认归入"线索"阶段，标注"阶段信息缺失，已按线索处理" |
| 商机金额为0或负数 | 排除该商机，记录异常日志，提示用户检查数据质量 |
| 当期目标未设置 | 仍可生成分析报告，但不计算达成率，标注"目标未设置，达成率无法计算" |
| 团队数据不完整 | 仅展示有数据的团队分析，缺失部分标注"数据待补充" |
| 阶段定义与数据不匹配 | 自动映射最接近的阶段名称，输出映射关系表供用户确认 |
