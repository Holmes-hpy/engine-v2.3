## 二、执行逻辑

### 步骤1：核心循环设计

**循环分析框架：**

```
主要循环（Core Loop）：
  定义：玩家每次游玩的核心行为循环
  结构：Action → Reward → Progression → Challenge
  示例（RPG）：
    战斗 → 获得经验/掉落 → 升级/装备 → 挑战更强敌人

次要循环（Secondary Loop）：
  定义：跨越多次主要循环的长期行为循环
  结构：Session → Accumulation → Milestone → New Content
  示例（RPG）：
    每日任务 → 积攒资源 → 解锁新角色/章节 → 新挑战

外围循环（Meta Loop）：
  定义：跨越游戏生命周期的超长循环
  结构：Season/Battle Pass → Event → Limited Content → Retention
```

**循环间关系分析：**

| 循环层 | 时间跨度 | 玩家投入 | 奖励类型 | 留存机制 |
|--------|---------|---------|---------|---------|
| 主要循环 | 1-5分钟 | 即时操作 | 即时反馈（经验/掉落） | 爽感/成就感 |
| 次要循环 | 1天-1周 | 每日投入 | 累计奖励（成就/解锁） | 期待感/进度感 |
| 外围循环 | 1月-3月 | 持续投入 | 稀有奖励（限定/赛季） | 稀缺感/社交压力 |

**按游戏类型适配：**

| 游戏类型 | 主要循环 | 次要循环 | 外围循环 |
|---------|---------|---------|---------|
| RPG | 战斗→获取→养成 | 日任→抽卡→练角色 | 版本活动→限定池→新剧情 |
| FPS | 对战→击杀→结算 | 排位→段位→赛季奖励 | 通行证→皮肤→新地图 |
| 策略 | 建造→收集→扩张 | 科技树→领土→联盟 | 跨服战→新文明→新机制 |
| 休闲 | 消除→得分→解锁 | 关卡→收集→装扮 | 社交活动→限时关卡→新玩法 |
| 模拟 | 经营→收入→扩张 | 建筑→成就→排名 | 新主题→联动活动→新机制 |

**循环平衡检查：**
```
for 每个循环层:
    投入产出比 = 平均奖励价值 / 平均投入时间
    if 投入产出比 递减:
        标注"循环疲劳风险：奖励递减，可能导致玩家流失"
        建议 = "增加里程碑奖励" or "缩短循环间隔"
    if 投入产出比 递增:
        标注"循环加速风险：奖励递增过快，可能导致内容消耗过快"
        建议 = "增加难度梯度" or "引入资源消耗机制"
```

### 步骤2：经济平衡表

**经济变量定义：**

| 变量名 | 基础值 | 最小值 | 最大值 | 增长率 | 调参备注 |
|--------|--------|--------|--------|--------|---------|
| 战斗经验获取 | 100/场 | 50 | 500 | 随等级+10% | 控制升级速度 |
| 金币掉落 | 50/场 | 20 | 300 | 随关卡+15% | 关联商店物价 |
| 角色升级所需经验 | 100/级 | 50 | 10000 | 指数增长 | 控制养成曲线 |
| 装备强化成功率 | 80% | 30% | 100% | 每级-5% | 控制资源消耗 |
| 体力恢复速度 | 1点/5分钟 | 0.5 | 3 | 固定 | 控制每日游戏时长 |
| 抽卡概率(SSR) | 3% | 1% | 5% | 保底机制 | 控制付费深度 |

**经济平衡公式：**

```
每日可获取金币 = (体力上限 / 单次体力消耗) × 单次金币获取 × 活跃系数
每日必需金币消耗 = 每日任务消耗 + 养成消耗 + 其他消耗
金币健康度 = 每日可获取金币 / 每日必需金币消耗

健康度标准：
- 1.2-1.5：健康（有盈余，玩家有选择空间）
- 1.0-1.2：紧张（刚好够用，玩家需精打细算）
- 0.8-1.0：不足（需要氪金或延长游戏时间）
- <0.8：严重不足（逼氪感强，流失风险高）
```

**养成曲线设计：**
```
等级n所需总经验 = 基础经验 × 增长率^(n-1)
升到满级所需天数 = Σ(每级所需经验) / (每日可获取经验)
目标养成周期 = 根据游戏范围设定：
  - prototype: 1-2天
  - indie: 7-14天
  - aa: 14-30天
  - aaa: 30-90天
```

### 步骤3：机制规格书

**单一机制规格书模板：**

| 维度 | 内容 |
|------|------|
| 机制名称 | {name} |
| 目的（Why） | 这个机制要解决什么玩家需求/设计目标 |
| 玩家幻想（Fantasy） | 玩家使用这个机制时的心理体验 |
| 输入（Input） | 玩家的操作输入（按键/手势/指令） |
| 处理（Process） | 系统如何处理输入（算法/规则） |
| 输出（Output） | 玩家看到的反馈（视觉/音效/数值） |
| 前置条件 | 触发该机制需要的条件 |
| 后置条件 | 机制执行后的状态变化 |
| 边界情况 | 极端/异常情况处理 |
| 调参杠杆 | 哪些参数可以调整来改变机制感受 |
| 与其他机制的关系 | 与哪些机制有交互 |

**边界情况检查清单：**
- 数值溢出：最大/最小值边界
- 并发操作：玩家同时触发多个操作
- 网络中断：离线/弱网时的行为
- 快速连续触发：连点/连击
- 资源不足：金钱/体力/道具不足
- 异常中断：战斗中退出/切换应用

**调参杠杆设计：**
```
每个机制需要暴露至少2个可调参数：
1. 强度参数（影响数值强度）：如伤害倍率、掉落概率
2. 节奏参数（影响时间节奏）：如冷却时间、动画时长
3. 感知参数（影响玩家感受）：如震动强度、特效强度
```

### 步骤4：玩家新手引导检查清单

## 四、异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 游戏类型不在枚举值内 | 使用最接近的已有类型模板，标注"自定义类型，基于{nearest_type}模板适配" |
| 经济变量之间存在矛盾 | 检测变量间依赖关系，提示矛盾点并建议调整方向 |
| 核心循环描述过于模糊 | 提示用户补充具体行为-奖励-消耗的对应关系 |
| 养成曲线过于陡峭或平缓 | 计算满级所需天数，若超出范围则建议调整增长率 |
| 机制数量>20个 | 建议按优先级（P0/P1/P2）分组，P0机制详细编写，P1/P2可简化 |
| 变现模式与游戏类型不匹配 | 给出行业常见组合建议，标注"当前组合与行业常见模式有差异" |
