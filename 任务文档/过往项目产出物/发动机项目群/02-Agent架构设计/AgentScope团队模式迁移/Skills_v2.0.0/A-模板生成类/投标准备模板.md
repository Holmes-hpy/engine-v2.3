## 二、执行逻辑

### 步骤1：模板初始化与参数校验

```
1. 校验必填参数完整性：
   - project_name, industry, client_name, bid_deadline 非空
   - bid_requirements.tech_score + bid_requirements.price_score = 100
   - win_themes 长度 ≥ 3 且 ≤ 5
   - solution_modules 长度 ≥ 3

2. 根据 industry 加载行业模板预设：
   - IT 行业：强调技术架构、系统集成、数据安全
   - 工程行业：强调施工组织、工期保障、质量安全
   - 咨询行业：强调方法论、团队经验、交付保障
   - 医疗行业：强调合规认证、数据安全、临床价值

3. 根据 template_type 选择输出范围：
   - full：输出完整方案（所有章节）
   - executive_summary：仅输出执行摘要
   - compliance_checklist：仅输出合规检查清单
```

### 步骤2：赢标主题矩阵构建

```
对每个赢标主题，自动填充完整矩阵：

| 主题编号 | 主题名称 | 映射客户需求 | 差异化论证 | 证据链 | 出现章节 | 针对竞对 |
|---------|---------|-------------|-----------|--------|---------|---------|
| Theme 1 | [theme] | [need] | [diff] | [evidence] | 第[chapter]章 | [against] |
| Theme 2 | ... | ... | ... | ... | ... | ... |

主题验证规则：
  1. 每个主题必须映射到至少一个客户需求
  2. 每个主题必须有至少一条证据链
  3. 主题之间不重复（差异化论证不可雷同）
  4. 主题必须覆盖技术评分的主要得分点
  5. 至少有一个主题针对头号竞对设计

主题出现频率设计：
  执行摘要：所有主题简要提及（1-2句）
  方案概述：所有主题展开（1-2段）
  分模块方案：各主题深度展开（1-2页）
  总结：所有主题回顾强化
```

### 步骤3：执行摘要生成（五段式）

```
【第一段 - 背景与挑战】
在当前[行业趋势]的背景下，[客户名称]正面临着[核心挑战1]和[核心挑战2]。
这些挑战不仅影响着[业务影响]，更对[战略目标]构成了制约。

生成规则：
  - 行业趋势：从 industry 参数自动匹配行业背景描述
  - 核心挑战：从 client_name + bid_requirements 推断
  - 字数控制：2-3句，80-120字

【第二段 - 需求理解】
基于对招标文件的深入研读和对贵方业务的充分调研，我们深刻理解[项目名称]
的核心需求在于：[需求1]——[具体说明]、[需求2]——[具体说明]、[需求3]——
[具体说明]。这些需求不仅是技术层面的要求，更是[业务层面的深层诉求]。

生成规则：
  - 需求数量：3-5个
  - 每个需求格式：需求名称——具体说明
  - 字数控制：3-4句，120-150字

【第三段 - 解决方案】
为此，我们为贵方量身定制了[方案名称]。
该方案从[维度1]、[维度2]、[维度3]三个核心维度切入：
  - [维度1]：通过[核心方法/技术]，实现[具体目标]
  - [维度2]：通过[核心方法/技术]，实现[具体目标]
  - [维度3]：通过[核心方法/技术]，实现[具体目标]
整体方案以[核心理念]为设计原则，确保[关键承诺]。

生成规则：
  - 维度数量：3个
  - 每个维度格式：维度名——方法——目标
  - 字数控制：4-5句，150-200字

【第四段 - 差异化优势】
区别于其他方案，我们的核心优势在于：
  1. [赢标主题1简述]：[具体优势，1-2句]
  2. [赢标主题2简述]：[具体优势，1-2句]
  3. [赢标主题3简述]：[具体优势，1-2句]
这些优势不是空洞的承诺，而是建立在[证据链支撑]的基础上。

生成规则：
  - 优势数量：与赢标主题数量一致（3-5个）
  - 字数控制：3-4句，120-150字

【第五段 - 行动号召】
我们已组建由[核心人员]领衔的[团队规模]人专业团队，制定了详细的
[实施计划]，可在[时间]内完成交付。我们期待与贵方携手，共同实现[愿景]。
选择[我方公司名称]，不仅是选择一个供应商，更是选择一个[价值定位]的长期伙伴。

生成规则：
  - 字数控制：2-3句，80-100字
  - 必须包含：团队、时间、愿景
```

### 步骤4：三幕式方案叙事框架

**第一幕：理解挑战（占方案篇幅 20%）**

```
章节结构：
  1.1 行业背景与趋势
    - 行业宏观数据（市场容量/增长率/政策环境）
    - 技术发展趋势（新技术/新模式/新要求）
    - 行业最佳实践（头部企业做法）

  1.2 客户现状与挑战
    - 客户业务现状分析（业务流程/系统现状/组织架构）
    - 核心痛点识别（按紧迫性排序，至少3个）
    - 痛点量化分析（不解决问题的损失量化）

  1.3 变革的必要性与愿景
    - 不变革的后果（竞争力下降/成本增加/合规风险）
    - 变革后的理想状态（效率提升/成本降低/体验改善）
    - 变革路线图（短期/中期/长期目标）

  IT行业定制：
    - 强调技术债务、系统孤岛、安全风险
    - 引用 Gartner/IDC 等行业权威数据
  ```

**第二幕：方案旅程（占方案篇幅 55%）**

```
章节结构：
  2.1 总体方案架构
    - 方案全景图（一张图说清楚）
    - 设计原则（5-6条）
    - 方案与需求的对应关系矩阵

  2.2-2.N 分模块方案（每个 solution_module 一个章节）
    每个模块包含：
    - 模块目标（解决什么问题）
    - 设计思路（为什么这样设计）
    - 详细方案（How）
    - 与竞对的差异（通常做法 vs 我们的做法）
    - 收益量化（预期效果）

  2.N+1 实施路径
    - 实施方法论（瀑布/敏捷/混合）
    - 项目里程碑（甘特图）
    - 关键节点与交付物

  2.N+2 风险管控与质量保障
    - 风险识别与应对（风险矩阵）
    - 质量管理体系（ISO/CMMI等）
    - 沟通与变更管理机制

  2.N+3 团队配置
    - 项目组织架构图
    - 关键人员简历（突出经验/证书/成功案例）
    - 团队协作机制

  IT行业定制：
    - 强调架构图（业务架构/应用架构/数据架构/技术架构）
    - 强调安全性（等保/数据安全/隐私合规）
    - 强调扩展性（未来3-5年可扩展）
```

**第三幕：转变后的状态（占方案篇幅 25%）**

```
章节结构：
  3.1 预期收益量化
    - ROI计算（投资回报分析）
    - 效率提升（量化各个维度的改善）
    - 成本节约（TCO对比分析）
    - 回收周期

  3.2 成功案例
    - 案例1：客户名称/项目规模/核心成果/客户评价
    - 案例2：客户名称/项目规模/核心成果/客户评价
    - 案例3：客户名称/项目规模/核心成果/客户评价
    - 每个案例格式：项目背景 → 解决方案 → 实施效果 → 客户证言

  3.3 售后服务与持续优化
    - 服务承诺（SLA/响应时间/解决时间）
    - 维护方案（预防性维护/应急响应/升级策略）
    - 持续优化机制（定期回顾/持续改进/知识转移）

  3.4 行动号召
    - 为什么选择我们（总结差异化优势）
    - 为什么是现在（紧迫性）
    - 下一步行动（明确可行的第一步）
```

### 步骤7：报价策略

```
根据 pricing_strategy 和评分规则自动计算：

价格评分公式（以价格分最低者得满分，其他按比例扣分）：
  价格得分 = 价格满分 × (最低有效报价 / 我方报价)

若价格分权重 ≥ 40%：
  建议报价策略：低价渗透
  报价 = 成本 × (1 + 最低利润率)
  在保证利润底线的同时，尽可能接近最低价

若价格分权重 30-40%：
  建议报价策略：中价高质
  报价 = 行业平均价 × 0.95
  用技术分优势弥补价格分劣势

若价格分权重 < 30%：
  建议报价策略：高价高质
  报价 = 行业平均价 × 1.05
  强调品质和服务，弱化价格竞争

价格矩阵：
  我方技术评分预估 / 价格分权重 / 建议溢价率
  领先 > 15分 / 任意 / +5%至+10%
  领先 5-15分 / 高 / 0%至+5%
  持平 / 高 / -5%至0%
  落后 / 低 / -10%至-5%
```

## 四、异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 赢标主题数量 < 3 | 提示"赢标主题至少需要3个，当前仅有N个，请补充" |
| 技术分+价格分 ≠ 100 | 提示"评分权重之和必须为100，当前为X，请修正" |
| 行业不在预设范围内 | 使用通用模板，提示"该行业暂无专用模板，已使用通用模板，可手动调整" |
| 截标日期已过 | 提示"截标日期已过，请确认是否需要继续生成方案" |
| 方案模块与赢标主题无对应关系 | 生成映射建议，提示"模块X 未对应任何赢标主题，建议关联或删除" |
| 缺少竞对信息 | 标注"以下差异化分析基于我方优势，未结合竞对信息，建议补充竞对分析" |
| 报价超过预算约束 | 提示"报价超出行业建议范围，请确认定价策略" |
