# 绩效管理模板

## 一、输入要求

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| `template_type` | string | 是 | 模板类型，`okr` / `calibration` / `distribution` / `pip` / `full_suite` | `full_suite` |
| `company_name` | string | 是 | 公司名称 | `XX科技有限公司` |
| `company_size` | string | 是 | 企业规模，`startup` / `growth` / `enterprise` | `growth` |
| `performance_cycle` | string | 是 | 绩效周期，`quarterly` / `semi_annual` / `annual` | `quarterly` |
| `distribution_model` | string | 否 | 绩效分布模型，`ali_361` / `huawei_abc` / `bytedance_fimo` / `custom`，默认按企业规模推荐 | `ali_361` |
| `role_level` | string | 否 | 目标角色/层级，`individual` / `team_lead` / `director` / `vp` | `team_lead` |
| `department` | string | 否 | 部门名称 | `产品研发部` |
| `headcount` | number | 否 | 团队人数，用于绩效分布计算 | `50` |
| `okr_count` | number | 否 | 生成的OKR示例数量，默认3个O，每个O配3个KR | `3` |
| `pip_employee` | object | 否 | PIP对象信息，生成PIP时必填 | `{"name":"张三","role":"高级工程师","issue":"连续两季度未达标"}` |
| `output_language` | string | 否 | 输出语言，默认中文 | `zh` / `en` |

### 绩效分布模型说明

| 模型 | 来源 | 分布规则 | 适用场景 |
|------|------|----------|----------|
| 阿里361 | 阿里巴巴 | 前30%优秀 / 60%合格 / 后10%需改进 | 竞争激烈、快速迭代的互联网企业 |
| 华为ABC | 华为 | A(杰出)10-15% / B(良好)70-75% / C(需改进)10-15% | 强调持续改进、技术驱动型企业 |
| 字节FIMO | 字节跳动 | F(远超预期)~10% / I(符合预期)~70% / M(部分符合)~15% / O(未达预期)~5% | 重视过程管理、扁平化组织 |
| 自定义 | 用户定义 | 用户自定义比例和标签 | 有成熟绩效文化的企业 |

## 二、执行逻辑

### 整体流程

```
输入 template_type
├── full_suite → 执行全部四个模块（§2.1→§2.2→§2.3→§2.4）
├── okr → 仅执行§2.1 OKR模板生成
├── calibration → 仅执行§2.2 绩效校准会议纪要
├── distribution → 仅执行§2.3 绩效分布模型
└── pip → 仅执行§2.4 PIP绩效改进计划
```

### 2.1 OKR模板生成

**步骤1：确定OKR结构**

根据 `role_level` 确定OKR的层级定位：

| 角色层级 | OKR定位 | O(目标)数量 | 每O对应KR | 对齐关系 |
|----------|---------|------------|-----------|----------|
| Individual | 个人贡献者 | 2-3个O | 2-4个KR | 向上对齐团队OKR |
| Team Lead | 团队负责人 | 3-4个O | 2-4个KR | 向上对齐部门OKR，向下分解到个人 |
| Director | 部门负责人 | 3-5个O | 2-5个KR | 向上对齐公司OKR，向下分解到团队 |
| VP | 高管 | 4-5个O | 3-5个KR | 对齐公司战略，向下分解到部门 |

**步骤2：OKR模板结构**

```
每个O（Objective）包含：
- 目标描述：定性描述，鼓舞人心，方向明确
- 权重：该O在整体中的权重（总和100%）
- 对齐关系：该O对齐到哪个上级O

每个KR（Key Result）包含：
- 关键结果描述：定量描述，可衡量
- 衡量标准：具体的数值指标及达成标准
- 评分标准：0.0(未启动) / 0.3(显著落后) / 0.7(基本达成) / 1.0(超额完成)
- 时间节点：里程碑日期
```

**步骤3：中期回顾（Mid-term Review）**

为OKR模板生成中期回顾部分：

```
中期回顾内容：
- 当前完成度：每个KR的当前进度百分比
- 信心指数：负责人对达成目标的信心（1-10分）
- 障碍与风险：当前遇到的阻碍
- 调整建议：是否需要调整KR或目标
- 下阶段重点：Q3-Q4冲刺计划
```

### 2.2 绩效校准会议纪要

**步骤1：会议框架**

```
校准会议议程：
1. 会议目的（5分钟）——确保评价标准一致性
2. 各部门逐个汇报（30分钟/部门）——部门负责人陈述下属绩效评估结果
3. 跨部门校准（20分钟）——横向对比，消除"手松手紧"偏差
4. 争议案例讨论（15分钟）——针对特殊案例深入讨论
5. 确认最终结果（10分钟）——输出校准后的绩效分布
```

**步骤2：校准原则**

- **相对评价原则**：不是看绝对产出，而是看相对贡献
- **证据驱动**：每个评级必须有具体事例支撑
- **破除近因效应**：回顾整个周期，而非仅最近1-2个月
- **消除宽容偏差**：识别并纠正"老好人"式评分

### 2.3 绩效分布模型

**步骤1：模型推荐**

根据 `company_size` 和 `company_name` 推荐分布模型。

| 企业规模 | 推荐模型 | 原因 |
|----------|----------|------|
| startup（<50人） | 字节FIMO | 扁平化，重视过程，对创业公司更友好 |
| growth（50-500人） | 阿里361 | 需要适度竞争激发活力，末尾淘汰鞭策 |
| enterprise（500+人） | 华为ABC | 成熟体系，持续改进，人才梯队建设 |

**步骤2：分布计算**

根据 `headcount` 和选定模型计算具体人数分布：

```
阿里361示例（headcount=50）：
前30% = 15人（优秀）
中60% = 30人（合格）  
后10% = 5人（需改进）

华为ABC示例（headcount=50）：
A = 5-8人（杰出）
B = 35-38人（良好）
C = 5-8人（需改进）

字节FIMO示例（headcount=50）：
F = 5人（远超预期）
I = 35人（符合预期）
M = 7-8人（部分符合）
O = 2-3人（未达预期）
```

**步骤3：配套措施**

针对不同评级输出配套管理措施：

| 评级 | 薪酬调整 | 晋升资格 | 培养资源 | 退出机制 |
|------|----------|----------|----------|----------|
| 优秀/A/F | 调薪幅度大+高额奖金 | 优先晋升 | 高管导师+重点项目 | 无 |
| 合格/B/I | 标准调薪+标准奖金 | 正常晋升通道 | 常规培训 | 无 |
| 需改进/C/M | 不调薪/微调+低奖金 | 暂停晋升 | 绩效改进计划 | 连续两季度则启动 |
| 未达标/O | 不调薪+无奖金 | 无资格 | PIP | 连续两季度则淘汰 |

### 2.4 PIP绩效改进计划

**步骤1：PIP触发条件判断**

```
PIP触发条件（满足其一即可）：
1. 连续两个季度绩效处于末位档
2. 单季度出现重大工作失误
3. 360度反馈中多维度评分显著低于预期
4. 直线经理提出正式PIP申请
```

**步骤2：PIP文档结构**

```
PIP包含：
- 改进目标：具体、可衡量、有时限的改进目标（SMART原则）
- 改进计划：分阶段行动步骤，每周/每两周的里程碑
- 支持资源：培训、导师、工具等
- 检查节点：每周1次正式回顾
- 评估标准：PIP结束时如何判定"通过"或"未通过"
- 结果说明：通过则撤销PIP，未通过则进入离职流程
```

**步骤3：PIP期间的沟通节奏**

| 周期 | 沟通内容 | 参与者 | 文档 |
|------|----------|--------|------|
| 第1周 | PIP启动沟通 | 员工+直线经理+HRBP | PIP协议签署 |
| 每周 | 周度回顾 | 员工+直线经理 | 周度进展记录 |
| 第2周 | 中期评估 | 员工+直线经理+HRBP | 中期评估表 |
| 第4周 | 最终评估 | 员工+直线经理+HRBP+部门负责人 | 最终评估结果 |
