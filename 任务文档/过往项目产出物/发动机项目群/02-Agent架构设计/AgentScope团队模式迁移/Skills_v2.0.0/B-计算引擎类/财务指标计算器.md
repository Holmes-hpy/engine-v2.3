# 财务指标计算器

## 一、输入要求

### 基础数据输入

| 参数名 | 类型 | 说明 | 必填 |
|--------|------|------|------|
| paying_customers | number | 付费客户总数 | 是 |
| arpu | number | 平均每用户收入（月度，单位：元） | 是 |
| new_customers | number | 本期新增付费客户数 | 是 |
| churned_customers | number | 本期流失付费客户数 | 是 |
| total_cac_cost | number | 本期总获客成本（含市场+销售薪酬+工具，单位：元） | 是 |
| gross_margin_rate | number | 毛利率（百分比，如80表示80%） | 是 |
| cash_balance | number | 当前现金余额（单位：元） | 是 |
| monthly_net_burn | number | 月净烧钱率（支出-收入，单位：元） | 是 |

### 高级参数

| 参数名 | 类型 | 说明 | 必填 |
|--------|------|------|------|
| scenario_mode | string | 场景模式，可选值：baseline（基准，默认）、optimistic（乐观）、pessimistic（悲观）、all（三场景对比） | 否 |
| benchmark_comparison | boolean | 是否进行同业对比，默认false | 否 |
| benchmark_segment | string | 同业对比细分，可选值：early_stage（早期，ARR<10M）、growth（成长期，ARR 10M-50M）、scale（规模化，ARR>50M） | 否 |
| expansion_revenue | number | 扩展收入（增购/升级带来的增量收入，单位：元） | 否 |
| contraction_revenue | number | 收缩收入（降级带来的收入减少，单位：元） | 否 |
| avg_customer_lifespan | number | 平均客户生命周期（月），如不填则通过流失率自动计算 | 否 |
| period | string | 计算周期，可选值：monthly（月度）、quarterly（季度）、annual（年度），默认monthly | 否 |

### 场景模式参数调整系数

| 指标 | 乐观系数 | 基准系数 | 悲观系数 |
|------|----------|----------|----------|
| 新增客户数 | ×1.3 | ×1.0 | ×0.7 |
| 流失率 | ×0.7 | ×1.0 | ×1.5 |
| ARPU增长率 | +5% | +0% | -5% |
| CAC增长率 | -10% | +0% | +15% |

## 二、执行逻辑

### 步骤1：数据校验与预处理

**校验规则**：
```
1. paying_customers >= 0
2. arpu > 0
3. new_customers >= 0
4. churned_customers >= 0 且 churned_customers <= paying_customers
5. total_cac_cost >= 0
6. 0 <= gross_margin_rate <= 100
7. cash_balance >= 0
8. monthly_net_burn 可为正（烧钱）或负（盈利）
```

**预处理**：
- 如果 `period=quarterly`，所有月度指标乘以3
- 如果 `period=annual`，所有月度指标乘以12
- 如果未提供 `avg_customer_lifespan`，则通过流失率自动计算

### 步骤2：计算核心SaaS指标

#### 2.1 收入指标

**MRR（月度经常性收入）**：
```
MRR = paying_customers × arpu
```

**ARR（年度经常性收入）**：
```
ARR = MRR × 12
```

**扩展MRR（Expansion MRR）**（如果提供了expansion_revenue）：
```
Expansion MRR = expansion_revenue
```

**净新增MRR（Net New MRR）**：
```
New MRR = new_customers × arpu
Churned MRR = churned_customers × arpu
Net New MRR = New MRR - Churned MRR + Expansion MRR - Contraction MRR
```

**MRR增长率（Month-over-Month）**：
```
MRR Growth Rate = (Net New MRR / (MRR - Net New MRR)) × 100%
```

#### 2.2 客户指标

**客户流失率（Logo Churn Rate）**：
```
Logo Churn Rate = (churned_customers / (paying_customers - new_customers + churned_customers)) × 100%
```

**收入流失率（Gross Revenue Churn）**：
```
Gross Revenue Churn = (Churned MRR / MRR) × 100%
```

**净收入留存率（NDR, Net Dollar Retention）**：
```
NDR = ((MRR - Churned MRR - Contraction MRR + Expansion MRR) / MRR) × 100%
```

> NDR > 100% 表示现有客户收入在增长（负流失），是SaaS最健康的信号之一。
> NDR > 120% 为优秀，NDR > 140% 为顶级。

**平均客户生命周期**（如果未直接提供）：
```
Avg Customer Lifespan (months) = 1 / (Logo Churn Rate / 100)
```

#### 2.3 单位经济学（Unit Economics）

**LTV（客户生命周期价值）**：
```
LTV = ARPU × Gross Margin Rate × Avg Customer Lifespan (months)
```

**CAC（客户获取成本）**：
```
CAC = total_cac_cost / new_customers
```

**LTV/CAC比率**：
```
LTV/CAC Ratio = LTV / CAC
```

> 健康标准：LTV/CAC >= 3（优秀），LTV/CAC >= 5（顶级）
> 警戒线：LTV/CAC < 1（商业模式不可持续）

**CAC回收期（CAC Payback Period）**：
```
CAC Payback (months) = CAC / (ARPU × Gross Margin Rate)
```

> 健康标准：< 12个月（优秀），< 18个月（可接受）
> 警戒线：> 24个月（需要优化获客效率或定价）

#### 2.4 盈利与现金流指标

**毛利率**：
```
Gross Margin = gross_margin_rate（输入值）
```

**现金流Runway（现金流跑道）**：
```
Runway (months) = cash_balance / monthly_net_burn
```

> 健康标准：> 18个月（安全），12-18个月（需关注），< 6个月（危险）
> 如果 monthly_net_burn <= 0（盈利），则显示"现金流为正，跑道无限"

**烧钱效率（Burn Multiple）**：
```
Burn Multiple = monthly_net_burn / Net New MRR
```

> 健康标准：< 1.0（优秀），< 1.5（良好），< 2.0（可接受）
> 警戒线：> 2.5（烧钱效率低）

**Rule of 40**：
```
Rule of 40 = MRR Growth Rate + Gross Margin Rate
```

> 健康标准：>= 40%（健康），>= 30%（可接受）
> 警戒线：< 20%（需要关注）

**ARPU趋势**：
```
ARPU Change = (本期ARPU - 上期ARPU) / 上期ARPU × 100%
```

### 步骤3：多场景模拟

当 `scenario_mode=all` 时，输出三场景对比表：

```
| 指标 | 乐观场景 | 基准场景 | 悲观场景 |
|------|----------|----------|----------|
| 新增客户数 | 基准×1.3 | 基准值 | 基准×0.7 |
| 流失率 | 基准×0.7 | 基准值 | 基准×1.5 |
| ARPU | 基准×1.05 | 基准值 | 基准×0.95 |
| CAC | 基准×0.9 | 基准值 | 基准×1.15 |
| --- | --- | --- | --- |
| MRR | 计算值 | 计算值 | 计算值 |
| ARR | 计算值 | 计算值 | 计算值 |
| NDR | 计算值 | 计算值 | 计算值 |
| LTV/CAC | 计算值 | 计算值 | 计算值 |
| Runway | 计算值 | 计算值 | 计算值 |
```

### 步骤4：同业对比（可选）

当 `benchmark_comparison=true` 时，根据 `benchmark_segment` 进行同业对比：

| 指标 | 早期阶段 (ARR<10M) | 成长期 (ARR 10M-50M) | 规模化 (ARR>50M) | 你的值 | 评级 |
|------|-------------------|---------------------|-----------------|--------|------|
| MRR增长率(月) | 8-15% | 5-10% | 2-5% | 计算值 | 优/良/中/差 |
| NDR | 90-105% | 100-115% | 110-125% | 计算值 | 优/良/中/差 |
| 毛利率 | 65-75% | 70-80% | 75-85% | 输入值 | 优/良/中/差 |
| LTV/CAC | ≥3 | ≥4 | ≥5 | 计算值 | 优/良/中/差 |
| CAC回收期(月) | <18 | <15 | <12 | 计算值 | 优/良/中/差 |
| Rule of 40 | ≥25% | ≥35% | ≥40% | 计算值 | 优/良/中/差 |
| 流失率(月) | <3% | <2% | <1.5% | 计算值 | 优/良/中/差 |

评级标准：
- 优：超过行业前25%分位
- 良：在行业中位数以上
- 中：在行业中位数附近
- 差：低于行业后25%分位

### 步骤5：诊断与建议

基于指标计算结果，自动生成诊断建议：

**诊断规则引擎**：

```
IF LTV/CAC < 3:
  建议: "LTV/CAC偏低，建议优化：(1)提升ARPU或扩展收入 (2)降低客户流失率 (3)优化获客渠道降低CAC"

IF NDR < 100%:
  建议: "NDR低于100%，存在收入流失。建议：(1)加强客户成功团队 (2)建立健康度评分进行主动干预 (3)开发增值功能驱动增购"

IF CAC Payback > 18:
  建议: "CAC回收期过长，获客效率需提升：(1)优化转化漏斗 (2)提升SEO/内容营销占比降低付费获客 (3)引入PLG自服务获客"

IF Runway < 12:
  建议: "现金流跑道不足12个月，建议：(1)立即启动融资流程 (2)控制烧钱速度 (3)关注高CAC渠道并暂停低效投放"

IF Rule of 40 < 30:
  建议: "Rule of 40不达标，增长与效率需平衡：(1)如果增长低，加大市场投入 (2)如果效率低，优化成本结构"

IF Burn Multiple > 2.0:
  建议: "烧钱效率低，每1元新MRR耗费超过2元：(1)审查各渠道ROI (2)暂停低效渠道 (3)提升销售团队人效"
```

### 输出示例

当输入以下参数时：
```
paying_customers=500, arpu=2000, new_customers=80, churned_customers=25,
total_cac_cost=400000, gross_margin_rate=80, cash_balance=15000000,
monthly_net_burn=800000, scenario_mode=baseline
```

```markdown
## 1. 核心指标总览

| ARR | ¥12,000,000 | ✅ | - |
| 月MRR增长率 | 3.5% | ✅ | 良 |
| NDR | 96.5% | ⚠️ | 中 |
| 毛利率 | 80% | ✅ | 优 |

## 2. 收入分析

### 2.1 MRR拆解
- 期初MRR：¥966,000
- 新增MRR：¥160,000（80客户 × ¥2,000）
- 流失MRR：¥50,000（25客户 × ¥2,000）
- 净新增MRR：¥110,000
- 期末MRR：¥1,000,000

### 2.3 NDR分析
- NDR：96.5%
- 分析：NDR低于100%，存在净收入流失。月流失25个客户，月流失率约5.0%。
- 风险提示：如果NDR持续低于100%，ARR增长将主要依赖新客获取，获客压力增大。

- LTV/CAC：38.4
- 分析：LTV/CAC远超行业优秀标准（≥5），单位经济学非常健康。
- 建议：可以考虑加大获客投入，加速增长。

### 4.4 CAC回收期
- CAC回收期：3.1个月
- 分析：CAC回收期极短，获客效率极高。
- 建议：当前获客效率优秀，可以适度增加销售团队规模。

## 5. 现金流分析

### 5.1 现金流Runway
- Runway：18.75个月

1. 【高优先级】提升NDR至100%以上：加强客户成功团队，建立健康度评分主动干预
2. 【中优先级】控制客户流失率：分析流失客户特征，建立流失预警模型
3. 【持续关注】维持获客效率优势，同时关注烧钱速度

### 8.3 监控指标建议
```
