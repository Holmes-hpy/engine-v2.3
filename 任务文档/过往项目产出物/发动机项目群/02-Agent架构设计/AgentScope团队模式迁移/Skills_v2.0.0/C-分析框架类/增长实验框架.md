name: 增长实验框架
version: 2.0.0
category: C-分析框架类
description: >
  提供增长实验方法论，包含ICE优先级评分（Impact×Confidence×Ease，
  含0-10评分标准和权重配置）、A/B测试设计与分析（假设/样本量计算/
  统计显著性/决策标准/实验跟踪看板）、实验管理流程（提出→设计→执行
  →分析→决策→扩散），适用于产品增长、用户转化优化、营销策略迭代场景，
  支持按业务阶段（0-1/1-10/10-100）和实验类型（获客/激活/留存/变现/
  推荐）定制实验模板。
---

## 一、输入要求

| 参数名 | 类型 | 说明 | 必填 | 示例 |
|--------|------|------|------|------|
| `business_stage` | string | 业务阶段 | 是 | `"0-1"` / `"1-10"` / `"10-100"` |
| `experiment_type` | string | 实验类型 | 是 | `"acquisition"` / `"activation"` / `"retention"` / `"revenue"` / `"referral"` |
| `current_metric` | float | 当前核心指标值 | 是 | `0.15`（如转化率15%） |
| `target_metric` | float | 目标核心指标值 | 是 | `0.20`（如转化率20%） |
| `ideas` | array | 实验想法列表 | 是 | `[{"name":"...","description":"...","hypothesis":"..."}]` |
| `traffic_volume` | int | 可用流量（日活/日访客） | 是 | `50000` |
| `experiment_duration_days` | int | 允许实验时长（天） | 否 | `14`（默认）/ `28` |
| `ice_weights` | object | ICE权重配置 | 否 | `{"impact":0.4,"confidence":0.35,"ease":0.25}` |
| `alpha` | float | 显著性水平 | 否 | `0.05`（默认） |
| `power` | float | 目标统计功效 | 否 | `0.80`（默认） |
| `mde` | float | 最小可检测效应 | 否 | `0.02`（相对提升2%） |
| `baseline_conversion` | float | 基线转化率 | 条件 | `0.15`（acquisition/activation/revenue类型必填） |
| `current_retention` | float | 当前留存率 | 条件 | `0.30`（retention类型必填） |

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| `name` | string | 实验名称 | 是 |

| `ease_score` | int | 实现难度评分（0-10） | 否 |
| `owner` | string | 实验负责人 | 否 |
| `dependencies` | array | 依赖项 | 否 |

## 二、执行逻辑

### 步骤1：ICE优先级评分

```
ICE评分标准：

Impact（影响，0-10分）：
  10分：可能使核心指标提升 > 50%
  8分：可能使核心指标提升 20-50%
  6分：可能使核心指标提升 10-20%
  4分：可能使核心指标提升 5-10%
  2分：可能使核心指标提升 < 5%
  0分：无影响或不可衡量

Confidence（信心，0-10分）：
  10分：有A/B测试数据或案例支持
  8分：有用户研究/问卷数据支持
  6分：有行业基准数据支持
  4分：有逻辑推理但无数据支撑
  2分：纯直觉或猜测
  0分：完全不确定

Ease（实现难度，0-10分，分数越高越容易）：
  10分：无需开发，配置即完成
  8分：前端改动，1天完成
  6分：前后端改动，3天完成
  5分：中等改动，1周完成
  3分：较大改动，2周完成
  1分：需要重构，1个月以上
  0分：需要架构变更

ICE Score = I × w_i + C × w_c + E × w_e
默认权重：w_i=0.4, w_c=0.35, w_e=0.25

按ICE分数降序排列，确定实验优先级队列
```

### 步骤2：样本量计算

```
根据 experiment_type 和 metric_type 计算所需样本量：

比例类指标（转化率等）：
  n = (Z_{1-α/2} + Z_{power})² × (p_baseline×(1-p_baseline) + p_expected×(1-p_expected)) / (p_expected - p_baseline)²
  其中 p_expected = p_baseline × (1 + mde)

连续类指标（客单价等）：
  n = 2 × (Z_{1-α/2} + Z_{power})² × σ² / δ²
  其中 δ = mde × μ_baseline（最小可检测差异）

留存类指标：
  使用对数秩检验（Log-rank test）样本量公式：
  n = (Z_{1-α/2} + Z_{power})² / (p₁ × p₂ × (ln(HR))²)
  其中 HR = 目标留存率 / 当前留存率

可行性校验：
  实验可行天数 = 每组所需样本量 / (日流量 × 分流比例)
  若 实验可行天数 > experiment_duration_days：
    提示：建议增加流量、降低MDE、或延长实验周期
```

### 步骤3：A/B测试设计

```
实验设计清单：
  1. 对照组：现有方案（control）
  2. 实验组：新方案（treatment）
  3. 分流比例：默认 50/50，也可 80/20（保守）
  4. 随机化单元：user_id（用户级）/ device_id（设备级）/ session_id（会话级）
  5. 主要指标（Primary Metric）：直接衡量实验假设的核心指标
  6. 护栏指标（Guardrail Metrics）：不能显著恶化的指标（如收入、加载时间、崩溃率）
  7. 次要指标（Secondary Metrics）：辅助观察的指标

SRM检验（Sample Ratio Mismatch）：
  在实验开始24小时后执行：
  χ² = Σ (O_i - E_i)² / E_i
  若 p < 0.01，则存在分流不均，需排查

AA测试（可选）：
  在正式实验前，对两组施加相同处理，验证系统无偏差
  若AA测试p < 0.05，则系统存在偏差，需修复
```

### 步骤4：实验执行与跟踪

```
实验跟踪看板字段：
  - 实验名称
  - 实验ID
  - 开始时间
  - 已运行天数
  - 当前样本量（对照/实验）
  - 主要指标当前值（对照/实验）
  - 相对提升
  - p值（逐日）
  - 置信区间（逐日）
  - 是否达到统计显著性
  - 是否达到样本量要求
  - 护栏指标状态（绿/黄/红）

Peeking（偷看）规则：
  - 不建议每天查看p值（增加第一类错误风险）
  - 若必须查看，使用序贯检验（Sequential Testing）：
    调整后的α = α / (1 + (t/T)²) 其中t为当前天数，T为计划天数
  - 或使用固定样本量，达到样本量后一次性做决策
```

### 步骤5：统计分析与决策

```
决策标准矩阵：

                    显著性 显著        显著性 不显著
样本量 充足      [上线]             [终止]
样本量 不足      [继续实验]         [继续实验或终止]

详细决策规则：
  1. 达到显著性 + 样本量充足 + 护栏指标正常 → 上线
  2. 达到显著性 + 样本量充足 + 护栏指标恶化 → 不通过，分析原因
  3. 达到显著性 + 样本量不足 → 继续实验（警惕假阳性）
  4. 未达到显著性 + 样本量充足 → 终止（效应量太小或无效应）
  5. 未达到显著性 + 样本量不足 → 判断是否继续：若CI范围包含有意义的效应量则继续
  6. 实验运行超过计划天数2倍 → 强制终止并分析

Novelty Effect（新奇效应）检测：
  比较实验前1/3时段和后1/3时段的效应量
  若后段效应量显著小于前段 → 可能存在新奇效应，需延长观察
```

### 步骤6：实验管理流程

```
六阶段实验管理流程：

阶段1 - 提出（Propose）：
  - 填写实验卡片：假设/ICE评分/预期指标/所需资源
  - 提交实验委员会评审
  - 输出：实验待办池（Backlog）

阶段2 - 设计（Design）：
  - 确定实验设计（对照组/实验组/分流比例/指标）
  - 计算样本量和实验时长
  - 编写实验方案文档
  - 输出：实验方案（Experiment Design Doc）

阶段3 - 执行（Execute）：
  - 开发实验变体
  - 内部QA（功能测试/埋点验证/分流验证）
  - 灰度发布（1%→5%→50%）
  - 输出：实验上线

阶段4 - 分析（Analyze）：
  - 执行SRM检验
  - 计算显著性/置信区间/效果大小
  - 护栏指标检查
  - 分维度下钻分析（设备/地域/用户分层）
  - 输出：实验分析报告

阶段5 - 决策（Decide）：
  - 实验委员会评审
  - 做出上线/继续/终止决策
  - 输出：实验决策记录（Experiment Decision Record）

阶段6 - 扩散（Scale）：
  - 上线方案全量发布
  - 知识沉淀（实验结论录入知识库）
  - 团队分享（实验复盘会）
  - 输出：全量上线 + 知识文档
```

### 步骤7：业务阶段定制

**0-1阶段（PMF探索）：**
```
特征：核心目标找PMF，用户量小，容忍度高
实验策略：
  - 实验频率：高（每周2-3个实验）
  - MDE设置：较大（10-20%），关注大效应
  - 统计显著性：放宽到α=0.10
  - 实验类型侧重：获客 > 激活 > 留存
  - 关键：快速试错，不求完美，找到方向比验证更重要
  - 推荐ICE权重：Impact=0.5, Confidence=0.2, Ease=0.3
```

**1-10阶段（增长加速）：**
```
特征：核心目标高速增长，用户量增长中，需要平衡速度和严谨
实验策略：
  - 实验频率：中（每周1-2个实验）
  - MDE设置：中等（5-10%）
  - 统计显著性：标准α=0.05
  - 实验类型侧重：激活 > 留存 > 变现
  - 关键：建立实验文化，培养数据驱动决策习惯
  - 推荐ICE权重：Impact=0.4, Confidence=0.35, Ease=0.25
```

**10-100阶段（规模优化）：**
```
特征：核心目标效率优化，用户量大，风险容忍度低
实验策略：
  - 实验频率：低（每两周1个实验）
  - MDE设置：较小（1-2%），可以检测微小效应
  - 统计显著性：严格α=0.01
  - 实验类型侧重：变现 > 留存 > 推荐
  - 关键：避免伤害核心体验，护栏指标比主要指标更重要
  - 推荐ICE权重：Impact=0.35, Confidence=0.4, Ease=0.25
```

### 步骤8：AARRR实验类型定制

| 实验类型 | 典型实验 | 主要指标 | 护栏指标 | 建议MDE | 建议时长 |
|---------|---------|---------|---------|---------|---------|
| 获客 Acquisition | 落地页优化/广告文案/渠道测试 | 注册转化率/CAC | 留存率/用户质量 | 5-10% | 7-14天 |
| 激活 Activation | 新手引导/首次体验/功能教育 | 激活率/首日关键行为 | 卸载率 | 5-10% | 7-14天 |
| 留存 Retention | 推送策略/功能优化/内容推荐 | 次日/7日/30日留存率 | DAU/使用时长 | 3-5% | 14-30天 |
| 变现 Revenue | 定价策略/促销设计/付费引导 | ARPU/付费率/LTV | 留存率/用户满意度 | 3-5% | 14-28天 |
| 推荐 Referral | 分享激励/邀请机制/口碑传播 | K因子/邀请转化率 | 用户体验/NPS | 5-10% | 14-21天 |

## 四、异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 流量不足（无法在计划时间内达到样本量） | 建议：降低MDE、延长实验周期、合并流量（跨渠道）、或使用贝叶斯方法 |
| 实验期间外部事件干扰（如竞品活动/节假日） | 标注干扰事件，在分析中做敏感性分析，排除干扰时段重新计算 |
| 护栏指标显著恶化但主要指标显著提升 | 红灯警告，建议不上线，重新设计实验平衡主要指标和护栏指标 |
| 实验组之间相互干扰（如社交产品） | 使用网络分簇（Cluster-based）随机化，或切换到开关实验（Switchback） |
| 实验周期内用户行为发生结构性变化 | 使用CUPED（Controlled-experiment Using Pre-Experiment Data）方法降低方差 |
| SRM检验失败 | 暂停实验，排查分流系统Bug，排查后重新启动 |
| 实验超过2倍计划时长仍未显著 | 强制终止，分析原因（效应量太小/方差太大/样本量不足），形成结论 |
