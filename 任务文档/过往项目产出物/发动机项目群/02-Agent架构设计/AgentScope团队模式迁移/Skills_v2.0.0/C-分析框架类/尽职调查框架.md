# 尽职调查框架

## 一、输入要求

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| `target_company` | string | 是 | 尽调目标公司名称 | `XX科技有限公司` |
| `deal_type` | string | 是 | 交易类型，`equity_investment` / `merger_acquisition` / `venture_capital` / `ipo` | `merger_acquisition` |
| `dd_stage` | string | 是 | 尽调阶段，`preliminary` / `interim` / `final` | `preliminary` |
| `focus_areas` | array | 否 | 重点关注领域，默认全部，可选：`financial` / `operational` / `market` / `legal` | `["financial", "legal"]` |
| `industry` | string | 否 | 目标行业，用于加载行业特定检查项 | `SaaS` / `制造业` / `医疗` |
| `investment_amount` | number | 否 | 投资金额（万元），用于确定尽调深度 | `5000` |
| `red_flags` | array | 否 | 已知风险点，需重点验证 | `["关联交易占比高","大客户依赖"]` |
| `timeline` | object | 否 | 尽调时间安排 | `{"start_date": "2026-08-01", "end_date": "2026-09-15"}` |
| `output_language` | string | 否 | 输出语言，默认中文 | `zh` / `en` |

### 尽调阶段与深度对应

| 阶段 | 覆盖维度 | 深度要求 | 交付物 |
|------|----------|----------|--------|
| preliminary（初步） | 财务 | 桌面研究为主，基于公开/提供资料 | 初步尽调问题清单 |
| interim（中期） | 财务 + 运营 | 增加访谈、现场走访 | 中期尽调报告 + 问题跟进 |
| final（最终） | 财务 + 运营 + 法律 + 市场 | 全面核查，含第三方验证 | 最终尽调报告 + 风险矩阵 |

## 二、执行逻辑

### 整体流程

```
输入尽调参数
├── 步骤1：确定检查维度（根据阶段和focus_areas）
├── 步骤2：按阶段加载对应深度的检查清单
├── 步骤3：整合行业特定检查项
├── 步骤4：针对已知风险点生成专项核查清单
├── 步骤5：按维度组织输出，标注各检查项优先级
└── 步骤6：生成风险矩阵和工作计划
```

### 步骤1：确定检查维度

根据 `dd_stage` 和 `focus_areas` 的交集确定要输出的维度。

```
阶段映射：
preliminary → [financial]
interim      → [financial, operational]
final        → [financial, operational, legal, market]

最终维度 = 阶段映射结果 ∩ focus_areas（若focus_areas未指定则取全部）
```

### 步骤2：四大维度检查清单

#### 2.1 财务尽调（Financial Due Diligence）

**初步阶段检查项：**

| 编号 | 检查项 | 优先级 | 验证方式 | 说明 |
|------|--------|--------|----------|------|
| F-01 | 收入确认政策 | P0 | 审计报告/合同抽样 | 是否存在提前确认收入、渠道压货等行为 |
| F-02 | 收入质量分析 | P0 | 客户清单/账龄分析 | 客户集中度、关联交易占比、退货率 |
| F-03 | 毛利率趋势 | P0 | 损益表/分产品毛利 | 近3年毛利率变化原因，是否可持续 |
| F-04 | 费用率合理性 | P1 | 费用明细 | 研发资本化政策、销售费用与收入匹配度 |
| F-05 | 应收账款质量 | P1 | 账龄表/坏账政策 | 账龄超过1年的应收账款占比、坏账计提是否充分 |
| F-06 | 关联交易 | P0 | 关联方清单/交易合同 | 关联交易定价公允性、占比及趋势 |

**中期阶段新增检查项：**

| 编号 | 检查项 | 优先级 | 验证方式 | 说明 |
|------|--------|--------|----------|------|
| F-07 | 现金流质量 | P0 | 现金流量表 | 经营现金流与净利润的匹配度 |
| F-08 | 资产负债表质量 | P0 | 明细账/实物盘点 | 存货跌价准备、固定资产减值、商誉减值 |
| F-09 | 表外负债 | P0 | 对外担保/诉讼 | 对外担保、未决诉讼、对赌协议 |
| F-10 | 税务合规 | P1 | 纳税申报表 | 税收优惠依赖度、税务稽查风险 |

**最终阶段新增检查项：**

| 编号 | 检查项 | 优先级 | 验证方式 | 说明 |
|------|--------|--------|----------|------|
| F-11 | 盈利预测合理性 | P0 | 财务模型/订单储备 | 预测假设是否合理，与历史增长是否匹配 |
| F-12 | 营运资金需求 | P1 | 现金流模型 | 完成交易后企业正常运营所需的额外资金 |
| F-13 | 财务内控体系 | P1 | 内控审计报告 | 财务系统、审批流程、职责分离 |

#### 2.2 运营尽调（Operational Due Diligence）

**中期阶段开始引入：**

| 编号 | 检查项 | 优先级 | 验证方式 | 说明 |
|------|--------|--------|----------|------|
| O-01 | 核心团队评估 | P0 | 访谈/背景调查 | 创始人/高管背景、稳定性、竞业限制 |
| O-02 | 组织架构与人力 | P1 | 员工名册/薪酬体系 | 人员结构、流失率、薪酬竞争力 |
| O-03 | 供应链分析 | P1 | 供应商清单/合同 | 供应商集中度、议价能力、替代方案 |
| O-04 | 技术/产品评估 | P0 | 技术文档/产品演示 | 技术壁垒、研发管线、产品迭代速度 |
| O-05 | IT系统与数据 | P1 | 系统架构/安全审计 | 系统稳定性、数据安全、技术债务 |
| O-06 | 客户满意度 | P1 | 客户访谈/NPS | 客户续约率、投诉记录、口碑 |

#### 2.3 法律尽调（Legal Due Diligence）

**最终阶段引入：**

| 编号 | 检查项 | 优先级 | 验证方式 | 说明 |
|------|--------|--------|----------|------|
| L-01 | 公司治理与股权 | P0 | 工商档案/股东协议 | 股权结构、表决权安排、优先权条款 |
| L-02 | 知识产权 | P0 | 专利/商标/著作权清单 | 核心IP归属、授权情况、侵权风险 |
| L-03 | 重大合同 | P0 | 合同审查 | 客户/供应商合同中的控制权变更条款 |
| L-04 | 诉讼与仲裁 | P0 | 裁判文书/律师函 | 未决诉讼、潜在纠纷、行政处罚 |
| L-05 | 合规与资质 | P1 | 许可证/资质证书 | 行业准入资质、环保合规、数据合规 |
| L-06 | 劳动人事 | P1 | 劳动合同/社保记录 | 用工合规性、竞业限制、期权计划 |

#### 2.4 市场尽调（Market Due Diligence）

**最终阶段引入：**

| 编号 | 检查项 | 优先级 | 验证方式 | 说明 |
|------|--------|--------|----------|------|
| M-01 | 市场规模与增速 | P0 | 第三方报告/专家访谈 | TAM/SAM/SOM，市场增速及驱动力 |
| M-02 | 竞争格局 | P0 | 竞品分析/市场份额 | 主要竞争对手、替代品威胁、进入壁垒 |
| M-03 | 客户画像 | P1 | 客户数据分析 | 客户分层、获客成本CAC、客户生命周期价值LTV |
| M-04 | 商业模式验证 | P0 | 单客经济模型 | 盈利模式是否跑通，UE模型是否为正 |
| M-05 | 行业趋势与政策 | P1 | 政策文件/行业报告 | 监管政策变化、技术替代风险 |

### 步骤3：行业特定检查项

根据 `industry` 参数追加行业特定检查项。

| 行业 | 特定检查项 |
|------|-----------|
| SaaS | 续费率(NDR)、客户获取成本回收期、大客户流失风险 |
| 制造业 | 产能利用率、设备成新率、环保合规 |
| 医疗 | 产品注册证、临床数据、医保定价 |
| 消费 | 渠道库存、品牌认知度、复购率 |
| 金融 | 不良率、资本充足率、监管合规 |

### 步骤4：风险点专项核查

如果 `red_flags` 中包含已知风险点，为其生成专项核查清单。例如：

- **"关联交易占比高"**：核查关联方清单完整性、交易定价公允性、是否存在利益输送
- **"大客户依赖"**：核查前5大客户贡献比例、合同期限、客户关系稳定性

### 步骤5：生成风险矩阵

```
风险矩阵 = {
  风险描述 + 发生概率(高/中/低) + 影响程度(高/中/低) + 风险等级 + 缓释措施 + 责任人
}
```

### 异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 目标公司不配合提供资料 | 标记为"资料缺失"，标注风险等级升级，建议通过侧面渠道验证 |
| 发现重大风险（如财务造假嫌疑） | 生成"重大风险预警"，立即中止后续常规检查，建议启动专项调查 |
| 尽调时间不足 | 按优先级排序输出，确保P0检查项100%覆盖，P1/P2酌情压缩 |
| 行业信息不明确 | 使用通用检查项，标注"建议补充行业专家意见" |
| 跨境交易 | 额外增加"外汇管制/国家安全审查/跨境税务"检查项 |
