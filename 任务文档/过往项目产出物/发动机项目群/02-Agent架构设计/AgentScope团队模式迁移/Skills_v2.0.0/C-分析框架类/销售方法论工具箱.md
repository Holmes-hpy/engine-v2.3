# 销售方法论工具箱

## 一、输入要求

| 参数名 | 类型 | 说明 | 必填 |
|--------|------|------|------|
| sales_stage | string | 当前销售阶段，可选值：discovery（发现需求）、qualification（资质审查）、objection（异议处理）、closing（推进成交） | 是 |
| industry | string | 行业类型，可选值：SaaS、manufacturing（制造）、professional_services（专业服务）、healthcare（医疗）、finance（金融） | 否 |
| customer_size | string | 客户规模，可选值：enterprise（企业级）、mid-market（中端市场）、SMB（中小企业） | 否 |
| methodology | string | 指定方法论，可选值：auto（自动推荐，默认）、SPIN、Gap、Sandler、AECR、MEDDPICC、all（输出全部） | 否 |
| specific_pain | string | 客户已知痛点描述（用于Gap Selling和Sandler Pain Funnel深度分析） | 否 |
| deal_size | string | 交易金额范围（用于MEDDPICC评估权重调整） | 否 |
| competitor_info | string | 竞品信息（用于异议处理和竞争策略） | 否 |

## 二、执行逻辑

### 步骤1：识别销售阶段并推荐方法论

根据 `sales_stage` 参数，自动匹配适用的方法论组合。当 `methodology=auto` 时，按以下规则推荐：

| 销售阶段 | 主推荐方法论 | 辅助方法论 | 推荐理由 |
|----------|-------------|-----------|---------|
| discovery（发现需求） | SPIN Selling | Gap Selling, Sandler Pain Funnel | 需要系统化提问挖掘客户隐性需求，构建差距认知 |
| qualification（资质审查） | MEDDPICC | SPIN Selling（验证维度） | 需要结构化评估商机质量，确定资源投入优先级 |
| objection（异议处理） | AECR | Sandler Pain Funnel（深挖异议根源） | 需要标准化异议处理流程，化阻力为推进动力 |
| closing（推进成交） | Gap Selling（价值确认） | MEDDPICC（最终验证）, AECR（最后异议） | 需要量化价值差距，推动决策紧迫感 |

### 步骤2：生成对应方法论的结构化框架

根据推荐/指定的方法论，依次输出以下内容：

#### 2.1 SPIN Selling 提问框架

**定义**：SPIN Selling 是由 Neil Rackham 提出的大型B2B销售提问方法论，通过四类递进式问题引导客户从"隐性需求"走向"显性需求"。

**四类问题定义与使用时机**：

| 问题类型 | 英文 | 定义 | 使用时机 | 占提问比例 |
|----------|------|------|----------|-----------|
| 情境问题 | Situation | 了解客户当前基本情况的事实性问题 | 售前准备阶段，通话前5分钟 | 10-15% |
| 难点问题 | Problem | 挖掘客户当前面临的问题、困难、不满 | 建立初步信任后，需求探索阶段 | 20-25% |
| 暗示问题 | Implication | 将问题的影响放大，揭示问题不解决的连锁后果 | 客户已认知问题但未感到紧迫时 | 30-35% |
| 需求-效益问题 | Need-Payoff | 引导客户自己说出解决方案带来的价值和收益 | 客户已认同问题严重性，准备讨论方案时 | 30-35% |

**示例（以SaaS CRM系统为例）**：

```
情境问题：
  "贵司目前销售团队规模多大？使用什么工具管理客户跟踪？"
  "销售周期平均多长？每个销售同时跟进多少商机？"

难点问题：
  "销售离职时，客户跟进记录是否完整保留？"
  "管理者能否实时掌握每个销售的pipeline健康度？"
  "是否存在商机漏跟或重复跟进的情况？"

暗示问题：
  "如果客户交接存在信息断层，新人上手需要多久？这段空窗期对客户续约率影响多大？"
  "管理者无法实时看到pipeline，是否导致季度末才发现业绩缺口，来不及补救？"
  "商机漏跟导致的损失，一年下来金额大概是多少？"

需求-效益问题：
  "如果新人接手后30分钟内就能了解客户全貌，对onboarding效率提升有多大？"
  "如果能实时监控pipeline健康度，在季度第二周就发现风险并调整，达成率能提升多少？"
  "自动分配商机规则避免漏跟，这部分节省的隐性收入对团队意味着什么？"
```

#### 2.2 Gap Selling 差距诊断

**定义**：Gap Selling 由 Keenan 提出，核心逻辑是"人们不会为解决方案买单，而是为消除差距买单"。通过量化"当前状态"与"未来状态"之间的差距，驱动客户做出改变决策。

**三层结构**：

```
【当前状态 Current State】
- 量化当前的问题指标（如：客户流失率15%、平均响应时间4小时、NPS得分32）
- 描述当前流程/工具的瓶颈
- 记录客户对现状的负面情绪表述

【未来状态 Future State】
- 量化期望达到的目标指标（如：客户流失率<5%、平均响应时间<15分钟、NPS得分>60）
- 描述理想流程/工具应该具备的能力
- 记录客户对未来的期待表述

【差距 Gap】
- 差距 = 未来状态 - 当前状态
- 量化差距的财务影响：年度损失 = 差距 × 影响系数
- 构建紧迫感：如果维持现状，6个月/12个月/24个月后的后果
```

**示例（以制造业设备维护为例）**：

```
当前状态：
  - 设备非计划停机率：8%（行业平均3%）
  - 每次停机平均损失：4.2万元（含产能损失+紧急维修+人工空转）
  - 月均停机次数：3.5次
  - 年度总损失：3.5 × 12 × 4.2万 = 176.4万元

未来状态：
  - 设备非计划停机率：<2%（引入预测性维护后）
  - 年度总损失：<40万元

差距：
  - 年度可避免损失：176.4万 - 40万 = 136.4万元
  - 如果维持现状24个月：累计损失 352.8万元
  - 解决方案投资回报周期：方案投入/136.4万 = ROI周期
```

#### 2.3 Sandler Pain Funnel（痛点漏斗）

**定义**：Sandler Pain Funnel 是 Sandler Selling System 的核心工具，通过三层递进式提问，从表面痛点深入到个人利害关系，建立客户的情感连接和决策动机。

**三层漏斗结构**：

```
第一层：表面痛点（Surface Pain）
  问题：发生了什么？什么时候开始的？多久发生一次？
  目的：建立事实基础，确认问题真实存在
  
第二层：业务影响（Business Impact）
  问题：这个问题对业务造成了什么影响？影响了哪些KPI？
  目的：量化问题的商业后果，建立组织层面的紧迫感
  
第三层：个人利害（Personal Impact）
  问题：这个问题对你个人/团队绩效有什么影响？你的老板怎么看？
  目的：建立个人情感连接，挖掘决策者的个人动机
```

**示例（以IT安全为例）**：

```
第一层 - 表面痛点：
  "最近一次安全事件是什么时候？"
  "平均多久发生一次安全告警？"
  "目前的响应流程是怎样的？"

第二层 - 业务影响：
  "上次安全事件导致业务中断了多久？直接损失多少？"
  "客户对安全事件的反应是什么？有客户因此流失吗？"
  "合规审计如果发现安全漏洞，会面临什么处罚？"

第三层 - 个人利害：
  "安全问题影响你今年的KPI了吗？"
  "董事会/CEO对安全事件的态度是什么？"
  "如果明年再发生类似事件，对你团队的预算和编制有什么影响？"
```

#### 2.4 AECR 异议处理

**定义**：AECR 是处理B2B销售异议的四步结构化方法，将异议视为"客户需要更多信息"的信号而非拒绝信号。

**四步结构**：

| 步骤 | 英文 | 中文 | 操作要点 | 禁忌 |
|------|------|------|----------|------|
| A | Acknowledge | 承认接纳 | 感谢客户提出异议，表示理解关切 | 不要说"我理解但是..." |
| E | Explore | 深度探索 | 追问异议背后的真实原因 | 不要急于解释或反驳 |
| C | Clarify | 澄清回应 | 针对真实原因给出针对性回应 | 不要泛泛而谈 |
| R | Reconfirm | 确认推进 | 确认异议是否解决，推进下一步 | 不要假设异议已解决 |

**常见异议类型及AECR应对示例**：

```
异议1：价格太贵
  A: "感谢您坦诚地分享这个感受，价格确实是重要考量因素。"
  E: "您主要是和哪个方案做对比觉得贵？还是预算本身有限制？"
  C: "如果按3年ROI折算，年化成本其实只有X万，而每年能帮您节省Y万..."
  R: "这样看，投资回报的角度您觉得合理吗？我们下一步安排POC？"

异议2：暂时不需要
  A: "理解，每家公司都有自己的节奏和优先级。"
  E: "您觉得什么时间点会是合适的时机？或者什么条件变化会让这个项目优先级提升？"
  C: "根据我们分析，如果现在不推进，每季度损失约X万..."
  R: "我把这个分析发您，我们下季度初再review一次？"

异议3：已有供应商
  A: "这说明您对这个领域很重视，有成熟的供应商是对业务负责。"
  E: "现有供应商在哪些方面做得好？哪些方面您觉得还有提升空间？"
  C: "我们在[差异化优势]方面有独特价值，可以作为补充方案..."
  R: "是否可以安排一次技术交流，看是否在某些场景下能互补？"
```

#### 2.5 MEDDPICC 资质审查

**定义**：MEDDPICC 是B2B企业级销售中评估商机质量的标准化框架，共8个维度，每个维度0-5分评分，总分决定商机优先级和资源投入策略。

**8要素定义与评分标准**：

| 要素 | 英文 | 定义 | 0分 | 3分 | 5分 |
|------|------|------|-----|-----|-----|
| M | Metrics | 可量化的价值指标 | 无量化 | 有部分指标 | 有完整ROI模型 |
| E | Economic Buyer | 经济决策者 | 未识别 | 已知但未接触 | 已建立关系并认可价值 |
| D | Decision Criteria | 决策标准 | 未知 | 已知部分 | 已知且我方优势匹配 |
| D | Decision Process | 决策流程 | 未知 | 已知流程 | 已知时间线和关键节点 |
| P | Paper Process | 采购流程 | 未知 | 已知流程 | 法律/采购已对接 |
| I | Implicate Pain | 隐性痛点 | 未识别 | 识别了痛点 | 量化了痛点财务影响 |
| C | Champion | 内部支持者 | 无 | 有支持者 | 支持者有影响力和动力 |
| C | Competition | 竞争态势 | 未知 | 已知竞品 | 有明确的竞争策略 |

**评分卡模板**：

```
商机名称：________________  日期：________________
销售阶段：________________  商机金额：________________

| 要素 | 得分(0-5) | 证据/说明 | 下一步行动 | 负责人 |
|------|-----------|-----------|-----------|--------|
| M 指标 | __ |           |           |        |
| E 决策者 | __ |         |           |        |
| D 决策标准 | __ |       |           |        |
| D 决策流程 | __ |       |           |        |
| P 采购流程 | __ |       |           |        |
| I 隐性痛点 | __ |       |           |        |
| C 支持者 | __ |         |           |        |
| C 竞争 | __ |           |           |        |
|------|-----------|-----------|-----------|--------|
| 总分 | __/40     |           |           |        |

评分等级：
  35-40分：A级商机，全力投入
  28-34分：B级商机，重点跟进
  20-27分：C级商机，维持跟进
  10-19分：D级商机，低优先级
  0-9分：  E级商机，暂缓或放弃
```

### 步骤3：按行业和客户规模调整方法论

根据 `industry` 和 `customer_size` 参数，调整方法论侧重点：

| 行业 | SPIN侧重 | Gap Selling侧重 | 关键调整 |
|------|----------|----------------|---------|
| SaaS | 数据孤岛、团队协作效率 | 人力成本节约、响应速度 | 强调实施周期和集成能力 |
| 制造 | 设备效率、质量控制 | 停机损失、良品率 | 强调ROI和运维成本 |
| 专业服务 | 人均产出、项目交付 | 回款周期、客户满意度 | 强调知识管理和标准化 |
| 医疗 | 患者安全、合规 | 医疗事故风险、合规罚款 | 强调合规认证和数据安全 |
| 金融 | 风控、合规、交易效率 | 监管罚款、交易损失 | 强调安全等级和审计能力 |

### 输出示例片段

当输入 `sales_stage=discovery, industry=SaaS, methodology=SPIN` 时，输出：

```markdown
# 销售方法论分析报告

## 1. 场景识别
- 销售阶段：发现需求（discovery）
- 行业：SaaS
- 推荐方法论：SPIN Selling（主）+ Gap Selling（辅助）

## 2. SPIN Selling 提问框架

### 2.1 方法论定义
SPIN Selling 是由 Neil Rackham 基于对35,000次销售拜访的实证研究提出的...

### 2.2 四类问题结构（SaaS行业定制）

**情境问题（占10-15%）**
1. 贵司目前使用什么工具管理客户生命周期？从线索到回款，涉及哪些系统？
2. 销售团队规模？人均管理多少客户/商机？
3. 目前的数据报表体系是怎样的？决策层多久看一次数据？

**难点问题（占20-25%）**
1. 不同系统之间数据打通了吗？是否存在数据孤岛？
2. 销售离职时，客户历史跟进记录能完整移交吗？平均移交周期多长？
3. 管理层能否实时看到每条业务线的健康度？决策滞后周期多长？

**暗示问题（占30-35%）**
1. 如果数据孤岛导致一个客户体验断层，续约率会受多大影响？
2. 新人上手周期2个月，这期间如果老客户无人跟进，潜在流失风险有多大？
3. 决策滞后1周，在一个月内可能错失多少商机窗口？

**需求-效益问题（占30-35%）**
1. 如果新人30分钟就能掌握客户全貌，onboarding效率提升对团队产出意味着什么？
2. 如果决策层能实时看到业务健康度，季度目标达成率能提升多少？
3. 统一的客户数据平台，对跨部门协作效率有多大提升？

### 2.4 使用检查清单
- [ ] 情境问题不超过总数15%，避免变成"审问"
- [ ] 每个难点问题后跟进1-2个暗示问题
- [ ] 暗示问题要让客户自己说出"这确实是个问题"
- [ ] 需求-效益问题要引导客户描述解决方案的价值
- [ ] 全程记录客户原话，用于后续Gap Selling分析
```
