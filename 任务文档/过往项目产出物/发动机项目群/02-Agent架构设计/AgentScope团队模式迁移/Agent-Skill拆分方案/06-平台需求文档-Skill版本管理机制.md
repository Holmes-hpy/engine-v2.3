# 平台需求文档：Skill版本管理与智能回退机制

> 版本：v1.0 | 日期：2026-07-29
>
> 本文档记录在 Agent2.0 架构设计过程中识别的、当前平台尚不支持的关键机制需求，待平台能力成熟后实现。

---

## 一、需求背景

在将86个专家拆分为 Agent + 多个 Skill 的架构中，产生了以下核心诉求：

1. **Skill 独立演进**：Skill 与 Agent 是独立的能力单元，Skill 的版本升级不应影响 Agent 的运行
2. **版本安全回退**：当新版本 Skill 无法达到预期效果时，需要自动回退到之前稳定版本
3. **平替能力发现**：当某个 Skill 被删除或不可用时，Agent 需要能自动寻找功能相近的替代 Skill
4. **简介精准性**：Skill 的 name 和 description 是 Agent 做 Skill 选择的关键依据，必须精准

---

## 二、需求详情

### 需求1：Skill 多版本并存

**当前状态**：每个 Skill 只有一个版本，修改后直接覆盖旧版本。

**目标状态**：

```
Skill名称: 估值计算引擎
├── v2.0.0（最新版，默认启用）
├── v1.3.0（上一稳定版，保留）
├── v1.2.0（历史版本，可查询）
└── v1.0.0（初始版本，可查询）
```

**具体要求**：
- 同一个 Skill 名称下支持多个版本并存
- 默认启用最新版本
- 历史版本保留，不可删除（但可标记为"已废弃"）
- 版本号遵循语义化版本规范（主版本.次版本.修订号）

**实现要点**：
- 存储层：Skill 文件按 `skill-name/v2.0.0.md` 路径组织
- 查询层：按 Skill 名称查询时返回最新可用版本
- 调用层：Agent 调用 Skill 时使用名称（不指定版本），平台自动路由到最新版本

---

### 需求2：自动回退机制

**当前状态**：Skill 出错后需要人工排查和手动切换版本。

**目标状态**：

```
Agent 调用 Skill "估值计算引擎"
    ↓
平台路由到最新版本 v2.0.0
    ↓
执行失败？ → 是 → 自动回退到 v1.3.0
    ↓                    ↓
执行成功？           执行成功？
    ↓                    ↓ 否 → 继续回退到 v1.2.0
返回结果              ↓
                     执行成功？ → 返回结果 + 异常说明
```

**具体要求**：
- 当最新版本 Skill 执行失败时，自动回退到上一个稳定版本重新执行
- 回退最多尝试 3 个历史版本（最新→上1→上2）
- 回退成功后，将异常说明提交给人工审核
- 回退失败后（所有版本都失败），向 Agent 返回明确的错误信息

**异常说明内容**：
- 失败的 Skill 版本号
- 失败原因（错误信息/输出不符合预期等）
- 回退到的版本号
- 回退版本的执行结果
- 建议：是否需要优化新版本 / 是否需要回滚默认版本

**触发条件**：
- Skill 执行抛出异常（超时、内部错误等）
- Skill 输出不符合预期格式（由 Agent 判断）
- 连续 N 次执行结果质量评分低于阈值

---

### 需求3：Skill 平替查找

**当前状态**：Agent 硬编码引用 Skill 名称，Skill 被删除后 Agent 无法工作。

**目标状态**：

```
Agent 调用 Skill "DCF估值模型"
    ↓
平台查找 Skill "DCF估值模型" → 未找到（已删除/已合并）
    ↓
平台平替查找：根据 description 语义相似度 + 分类标签
    ↓
匹配到 "估值计算引擎"（相似度 92%）
    ↓
返回给 Agent："DCF估值模型 不可用，建议使用 估值计算引擎 v2.0.0"
```

**具体要求**：
- Agent 在 prompt 中引用 Skill 名称（不绑版本号），平台负责解析
- 当 Skill 不可用时，平台基于 description 语义相似度 + 分类标签推荐平替
- 平替推荐规则：
  - 同分类下优先（如 B-计算引擎类）
  - description 语义相似度 > 80%（基于 embedding 向量相似度）
  - 功能覆盖度检查（平替 Skill 的输入输出是否覆盖原 Skill 的需求）
- Agent 获得平替推荐后，自行判断是否采纳

**平替关系维护**：
- Skill 合并时自动记录合并关系（旧 Skill → 新 Skill 映射）
- Skill 废弃时手动标记"替代 Skill"
- 平台定期计算 Skill 间的相似度矩阵

---

### 需求4：Skill 简介精准性

**当前状态**：Skill 的 name 和 description 由创建者自由填写，质量参差不齐。

**目标状态**：Skill 的 name 和 description 是 Agent 选择 Skill 的核心依据，必须精准。

**name 规范**：
- 简洁中文，描述"做什么"，4-8个字
- 避免模糊词汇（如"工具"、"助手"、"系统"）
- 示例：`估值计算引擎`（好）vs `估值工具`（差）

**description 规范**：
- 一句话说清楚：做什么 + 适用于什么场景 + 支持哪些参数
- 格式：`[核心功能]，适用于[场景]，支持[参数/变体]`
- 示例：
  ```
  好：执行公司估值计算，支持DCF/可比公司/分部加总三种方法，
      适用于IPO定价、并购估值、投资分析场景，
      支持多场景模拟（乐观/基准/悲观）和敏感度分析
  ```
  ```
  差：一个估值工具
  ```

**description 编写检查清单**：
- [ ] 是否包含"做什么"（核心功能）？
- [ ] 是否包含"适用于什么场景"（适用场景）？
- [ ] 是否包含"支持哪些参数/变体"（能力范围）？
- [ ] 是否避免了模糊词汇？
- [ ] 是否让另一个 Agent 读完后能准确判断"这个 Skill 能不能解决我的问题"？

---

### 需求5：Skill 与 Agent 独立演进

**设计原则**：Skill 变化不应影响 Agent 运行。

**实现要点**：
- Agent 在 prompt 中引用 Skill 名称，不绑定版本号
- Agent 的 prompt 中不出现 Skill 的具体实现细节（只写"调用 Skill X 完成 Y"）
- Skill 升级时，Agent 不需要修改 prompt
- Skill 合并/废弃时，平台通过平替机制保证 Agent 继续工作

**示例**：

```
Agent prompt 中：
  "选择合适的估值方法 → 调用 Skill '估值计算引擎' 执行估值计算"

而不是：
  "使用 DCF 方法，计算未来5年自由现金流，按 WACC 折现..."
  （这是 Skill 内部的执行逻辑，不应出现在 Agent 中）
```

## 三、优先级排序

| 需求 | 优先级 | 理由 |
|------|--------|------|
| 需求4：Skill简介精准性 | P0-立即执行 | 不依赖平台能力，现在就可以做，且是后续所有需求的基础 |
| 需求1：多版本并存 | P1-核心能力 | 是需求2和需求3的基础，需要平台底层支持 |
| 需求2：自动回退机制 | P2-依赖P1 | 依赖多版本并存，提升系统稳定性 |
| 需求3：平替查找 | P3-锦上添花 | 依赖P1和P4，提升系统鲁棒性 |
| 需求5：独立演进 | 架构原则 | 不是独立功能，而是贯穿所有需求的设计原则 |
