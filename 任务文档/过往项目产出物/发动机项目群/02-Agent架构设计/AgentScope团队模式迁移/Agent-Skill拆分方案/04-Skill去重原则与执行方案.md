# Skill 去重原则与执行方案

> 版本：v1.0 | 日期：2026-07-29
>
> 本文档定义348个候选Skill的去重原则，并产出最终去重后的Skill清单。

---

## 一、去重三层次模型

| 层次 | 判定标准 | 处理方式 | 示例 |
|------|---------|---------|------|
| **L1-功能同质** | 输入输出完全一致，仅适用场景/平台不同 | 合并为一个Skill，场景/平台作为**参数** | 抖音脚本模板 + 快手脚本模板 → "短视频脚本模板" |
| **L2-功能互补** | 属于同一分析框架体系，各自解决不同问题 | 合并为一个Skill，内部定义**使用场景选择逻辑** | PEST + SWOT + 波特五力 → "战略分析工具箱" |
| **L3-名称相似但本质不同** | 名字看起来像，但输入输出、执行逻辑、应用领域完全不同 | **保持独立** | "赢单策略师"的MEDDPICC ≠ "Discovery教练"的SPIN |

## 二、Skill分类体系

为便于去重，先将348个Skill归入以下大类：

### 2.1 分类维度

| 大类 | 说明 | 预计数量 |
|------|------|---------|
| **A-模板生成类** | 生成结构化文档/方案/脚本/报告的模板 | ~120 |
| **B-计算引擎类** | 执行数学计算、公式推导、统计分析 | ~72 |
| **C-分析框架类** | 提供方法论框架、分析模型、决策矩阵 | ~58 |
| **D-知识库类** | 提供领域知识、参考数据、规则查询 | ~42 |
| **E-检查清单类** | 提供结构化检查项、审计清单 | ~36 |
| **F-代码模板类** | 提供编程语言特定的代码模式和实现 | ~20 |

### 2.2 各类去重规则

#### A-模板生成类去重规则

| 规则 | 说明 |
|------|------|
| A1: 平台参数化 | 同类型内容模板（如短视频脚本），不同平台（抖音/快手/B站/小红书）→ 合并为1个Skill，平台作为参数 |
| A2: 文档类型统一 | 同类型文档模板（如报告、方案），不同业务场景 → 合并为1个Skill，业务场景作为参数 |
| A3: 粒度检查 | 如果一个Skill只是另一个Skill的子集，合并 |

**平台参数化示例**：
```
合并前：12个
- 抖音爆款视频脚本模板
- 快手账号运营方案模板
- B站中长视频脚本结构模板
- 小红书爆款笔记模板
- LinkedIn帖子草稿模板
- TikTok爆款公式模板
- 微博热搜话题策划模板
- 知乎高价值回答模板库
- Twitter Thread创作模板
- YouTube视频优化审核模板
- Instagram Reels制胜公式
- Reddit AMA策划模板

合并后：3个
- 短视频脚本模板（参数：平台=抖音/快手/B站/小红书/TikTok/YouTube）
- 社交图文模板（参数：平台=LinkedIn/Twitter/微博/知乎/Reddit）
- 直播策划模板（参数：平台=抖音/快手/TikTok）
```

#### B-计算引擎类去重规则

| 规则 | 说明 |
|------|------|
| B1: 公式同源 | 使用相同计算方法的Skill → 合并，输入参数作为配置 |
| B2: 指标归类 | 同一领域的不同指标计算 → 合并为"XX领域指标计算器" |

#### C-分析框架类去重规则

| 规则 | 说明 |
|------|------|
| C1: 框架体系合并 | 属于同一方法论体系的多个框架 → 合并为"XX工具箱"，内部说明使用场景 |
| C2: 互补框架合并 | 解决同一问题不同维度的框架 → 合并，按维度选择 |

**框架体系合并示例**：
```
合并前：5个
- SPIN Selling提问框架
- Gap Selling差距诊断框架
- Sandler Pain Funnel三层漏斗
- AECR异议处理框架

合并后：1个
- 销售方法论工具箱（包含SPIN/Gap/Sandler/AECR四个子框架，按场景选择）
```

#### D-知识库类去重规则

| 规则 | 说明 |
|------|------|
| D1: 领域合并 | 同一领域的不同知识库 → 合并为一个知识库 |
| D2: 避免迷你知识库 | 如果知识库内容少于5条规则/数据，不单独成Skill，合并到Agent或相关Skill中 |

#### E-检查清单类去重规则

| 规则 | 说明 |
|------|------|
| E1: 领域合并 | 同一业务领域的检查清单 → 合并 |

#### F-代码模板类去重规则

| 规则 | 说明 |
|------|------|
| F1: 技术栈聚合 | 同一技术栈的代码模板 → 合并为一个代码库 |
| F2: 最小粒度 | 少于3个代码模式的模板库 → 合并到相关Skill |

## 三、去重后的Skill命名规范

合并后的Skill命名遵循：
- `name`：简洁中文，描述"做什么"，如"短视频脚本模板"
- `description`：包含"做什么 + 适用于什么场景 + 支持哪些参数"，如"生成多平台短视频脚本，支持抖音/快手/B站/小红书/TikTok/YouTube六个平台，按平台自动适配时长、结构和风格"

---

## 四、去重执行流程

1. 将348个Skill按六大类分类
2. 每类内按去重规则逐条检查
3. 识别L1（功能同质）→ 合并
4. 识别L2（功能互补）→ 合并
5. 识别L3（名称相似但本质不同）→ 保留
6. 输出最终Skill清单，标注每个Skill的合并来源
