# 平台教学：Agent 与 Skill —— 从"一个专家"到"Agent + 多个 Skill"

> 版本：v1.0 | 日期：2026-07-28
>
> 本文档面向**智能体平台用户**，通过一个完整的真实案例，演示如何将一个传统的专家提示词拆分为 Agent + 多个 Skill。

---

## 一、先看一个真实案例：投资研究员

### 1.1 改造前：一个 280 行的"大杂烩"

下面是改造前的投资研究员专家文件结构。它把所有东西都塞在了一个文件里：

```
投资研究员.md（280行）
├── 身份定义（"我是投资研究员，14年经验..."）
├── 核心规则（"区分论点和叙事"、"量化下行风险"...）
├── 工作流程（5个阶段：筛选 → 评估 → 深度研究 → 建议 → 监控）
├── 沟通风格（"先说差异化观点"、"对确信度要具体"...）
├── DCF 估值模型模板（含完整表格）
├── 可比分析模板（含完整表格）
├── 财务摘要表格模板
├── 竞争格局分析模板
├── 尽职调查清单（含5大类、20+检查项）
└── 投资研究报告完整模板
```

### 1.2 问题在哪？

| 问题 | 具体表现 |
|------|---------|
| 臃肿 | 280行，用户很难快速理解这个专家能做什么 |
| 重复 | 财务分析师、FP&A分析师、风控师都需要财务分析模板，但各自写了一份 |
| 混淆 | 决策逻辑（"看多论点要写，看空论点更要写"）和模板（DCF表格）混在一起 |
| 难维护 | 改一个财务比率公式，要找所有用到它的专家文件 |

### 1.3 改造后：1个 Agent + 4个 Skill

```
改造前：                         改造后：
┌──────────────┐               ┌──────────────┐
│  投资研究员   │               │ 投资研究员    │  ← Agent（身份+决策）
│  （280行）    │               │ （约80行）     │
│              │               └──────┬───────┘
│  身份+规则    │                      │ 调用
│  +工作流     │        ┌─────────────┼─────────────┐
│  +DCF模板    │        ▼             ▼             ▼
│  +尽调清单   │   ┌─────────┐ ┌─────────┐ ┌─────────┐
│  +报告模板   │   │DCF估值   │ │尽调清单  │ │投资研究 │ ...
│  +可比分析   │   │模型     │ │         │ │报告模板  │
└──────────────┘   └─────────┘ └─────────┘ └─────────┘
                      Skill        Skill       Skill
```

## 二、拆解过程：一步一步来

### 第1步：识别哪些内容可以独立成 Skill

对照原则文档的"四维判定模型"，逐段分析投资研究员的内容：

| 原文内容块 | 可变性 | 可复用性 | 决策含量 | IO明确性 | 判定 |
|-----------|--------|---------|---------|---------|------|
| 身份："我是投资研究员..." | 高 | 仅此角色 | 高 | 无 | **Agent** |
| 规则："区分论点和叙事" | 低 | 仅此角色 | 极高 | 无 | **Agent** |
| 工作流：5阶段 | 中 | 仅此角色 | 高 | 模糊 | **Agent** |
| 沟通风格 | 高 | 仅此角色 | 高 | 无 | **Agent** |
| **DCF估值模型模板** | 低 | 高（财务分析师也能用） | 低 | 明确 | **Skill** |
| **可比分析模板** | 低 | 高（任何估值场景都能用） | 低 | 明确 | **Skill** |
| **尽职调查清单** | 低 | 高（法务、风控都能用） | 低 | 明确 | **Skill** |
| **投资研究报告模板** | 低 | 中（同类角色可用） | 低 | 明确 | **Skill** |

### 第2步：写出 Agent 提示词（精简版）

去掉所有模板细节后，Agent 提示词变得清晰：

```markdown
---
name: 投资研究员
description: 资深投资研究专家，通过严谨的基本面和量化分析识别投资机会、
  评估风险，支持数据驱动的投资组合决策。
version: "2.0.0"
---

# 投资研究员

你是投资研究员，一位拥有14年以上经验的资深投资研究专家。

## 核心能力

你可以调用以下 Skill 来完成专业分析：

| Skill 名称 | 用途 | 何时使用 |
|-----------|------|---------|
| `dcf-valuation` | DCF 估值模型 | 需要对公司进行绝对估值时 |
| `comparable-analysis` | 可比公司分析 | 需要相对估值参考时 |
| `due-diligence-checklist` | 尽职调查清单 | 需要对投资标的做全面尽调时 |
| `investment-research-report` | 投资研究报告模板 | 需要输出完整研究报告时 |

## 关键规则

1. 区分论点和叙事——每个论点需要可量化的支持
2. 始终呈现两面——看多和看空论点必须同样严谨
3. 量化下行风险——每个投资建议必须包含悲观场景
4. 定义投资期限——6个月的交易和5年的投资需要不同框架
5. 披露信心水平——高确信度和投机性头寸需要不同仓位

## 工作流程

1. 理解用户需求 → 确定分析范围
2. 选择合适的 Skill 执行分析
3. 综合 Skill 结果，形成独立判断
4. 以结构化方式呈现结论

## 沟通风格

- 先说差异化观点，再说支撑数据
- 对确信度要具体，不模棱两可
- 量化不对称性，明确风险回报比
```

**对比感受**：从 280 行 → 约 80 行，但决策能力反而更强了。因为 Agent 不再被表格模板淹没，每一行都在聚焦"判断"。

### 第3步：写出 Skill 定义

每个 Skill 独立成一个文件，有自己的 `name` 和 `description`：

**Skill 1：DCF 估值模型**

```markdown
---
name: DCF估值模型
description: 基于自由现金流折现法对公司进行绝对估值，支持多场景分析
  （乐观/基准/悲观），输出加权目标价和敏感度分析。
---

# DCF 估值模型

## 输入要求

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| 公司名称 | 文本 | 被估值公司名称 | 是 |
| 最近年度收入 | 数字 | 单位：百万元 | 是 |
| 收入增长率（近3年） | 数字数组 | 如 [12, 15, 18] | 是 |
| 最近年度FCF | 数字 | 单位：百万元 | 是 |
| WACC | 数字 | 加权平均资本成本，如 0.10 | 是 |
| 预测期 | 数字 | 通常 5 年 | 否（默认5） |

## 执行逻辑

1. 基于历史增长率推算未来5年收入
2. 计算预测期每年FCF = 收入 × FCF率
3. 计算终值 = 最后一年FCF × (1+g) / (WACC - g)
4. 将所有FCF和终值折现到当前，求和得到企业价值
5. 分别按乐观（增长率+20%）、基准、悲观（增长率-20%）计算三个场景
6. 加权平均得到目标价

## 输出格式

| 场景 | 收入CAGR | 终值倍数 | 隐含价格 | 权重 |
|------|---------|---------|---------|------|
| 乐观 | X% | XXx | $X | 25% |
| 基准 | X% | XXx | $X | 50% |
| 悲观 | X% | XXx | $X | 25% |
| **加权目标** | | | **$X** | |
```

**Skill 2：尽职调查清单**

```markdown
---
name: 尽职调查清单
description: 覆盖财务、运营、市场、法律、管理层五大维度的完整尽调清单，
  共20+检查项，适用于投资决策前的全面审查。
---

# 尽职调查清单

## 输入要求

| 参数 | 类型 | 说明 | 必填 |
|------|------|------|------|
| 公司名称 | 文本 | 被调查公司名称 | 是 |
| 尽调阶段 | 枚举 | 初步/中期/最终 | 否（默认初步） |
| 重点关注领域 | 文本数组 | 如 ["财务", "法律"] | 否 |

## 执行逻辑

按阶段输出对应深度的检查清单：

- **初步阶段**：聚焦财务尽调（收入质量、盈利质量、资产负债表）
- **中期阶段**：增加运营尽调（客户访谈、供应商分析、技术评估）
- **最终阶段**：增加法律尽调（知识产权、诉讼、合规）和市场尽调

## 输出格式

```markdown
# 尽职调查报告：[公司名称]
**阶段**：[初步/中期/最终]  **日期**：[日期]

## 财务尽调
- [ ] 收入质量评估——经常性 vs. 一次性收入、客户集中度
- [ ] 盈利质量——现金转化、应计分析、Non-GAAP 调整
- [ ] 资产负债表审查——表外项目、或有负债、债务契约
- [ ] 营运资金分析——趋势、季节性、DSO/DPO/DIO
- [ ] 资本效率——ROIC 趋势、CapEx 需求

## 运营尽调
- [ ] 客户访谈（n=[X]）——满意度、转换可能性、竞品替代方案
- [ ] 供应商分析——集中度、合同条款、定价权博弈
- [ ] 技术评估——架构可扩展性、技术债务、竞争差异化
- [ ] 管理层背景调查——领导力质量、诚信度、执行力历史

## 已识别的红旗
| 发现 | 严重程度 | 影响 | 建议 |
|------|---------|------|------|
| [发现] | [高/中/低] | [描述] | [行动] |
```

## 三、Skill 格式规范

每个 Skill 文件必须遵循以下标准格式：

### 3.1 文件头（Front Matter）

```yaml
---
name: Skill名称（中文，简洁）
description: Skill描述（一句话说清楚这个Skill做什么、产出什么）
---
```

### 3.2 正文结构

```markdown
# Skill名称

## 输入要求
（表格形式，列出所有输入参数：名称、类型、说明、是否必填）

## 执行逻辑
（步骤式描述，按顺序说明执行过程）

## 输出格式
（模板或格式说明，定义最终输出物的结构）
```

### 3.3 关键原则

- `name` 和 `description` 是**必填字段**，放在 Front Matter 中
- 输入要求必须明确参数类型和是否必填
- 执行逻辑用步骤式描述，让调用方理解过程
- 输出格式尽量用模板展示，让调用方知道会得到什么

## 四、总结：Agent + Skill 架构的价值

### 对用户的价值

| 维度 | 之前 | 之后 |
|------|------|------|
| 发现能力 | 用户不知道专家有哪些具体能力 | Skill 作为独立能力单元，可被浏览和搜索 |
| 组合能力 | 一个专家只能用一个 | 用户可以组合 Agent 的决策 + Skill 的执行 |
| 理解成本 | 280行的提示词，要读完才知道能做什么 | Agent 80行讲清角色和决策逻辑，Skill 单独列出 |

### 对平台的价值

| 维度 | 之前 | 之后 |
|------|------|------|
| 复用性 | 同样的分析模板在多个专家中重复定义 | 一个 Skill 定义一次，所有 Agent 共享 |
| 维护性 | 改一个方法要改N个文件 | 改一个 Skill 文件即可 |
| 扩展性 | 新增能力 = 新写一个专家 | 新增 Skill = 让现有 Agent 获得新能力 |
