## 二、QBR模版表（通用版）深度解析

QBR（Quarterly Business Review，季度业务回顾）模版是整个团队事物管理的核心框架，包含 **4个Sheet**：

### 2.1 Sheet1：基本信息

用于记录员工的基础档案信息，包含以下字段：

| 字段 | 说明 |
|------|------|
| 姓名 | 员工姓名 |
| 部门 | 所属部门 |
| 岗位 | 具体岗位名称 |
| 级别 | 职级（参见级别体系） |
| 入职日期 | 入职时间 |
| 直接上级 | 直属领导 |
| 直接下级 | 下属人员名单（如有） |

### 2.2 Sheet2：岗位职责（核心考核表）

这是QBR最核心、最复杂的部分，共 **35行 x 22列**，覆盖两大考核维度：

#### （一）基础业绩

**1. 核心工作内容考核项**（可自定义3大项，每大项下可细分3个子项）

- 每个考核项包含以下跟踪字段：
  - `2025/2026年度目标`：全年目标设定
  - `Q1-Q4计划`：每季度计划
  - `Q1-Q4完成`：每季度实际完成情况
  - `Q1-Q4改进措施`：每季度改进措施
  - `Q1-Q4排名`：每季度排名
  - `执行分解（直接下级）`：任务执行人
  - `考核ABCD`：考核方式（数值/考核）

**2. 具体考核指标示例**（从员工实际填写中提取）

| 指标类别 | 具体指标 | 说明 |

## 四、QBR考核体系运作机制

### 4.1 考核周期

- **年度目标**：每年初设定全年目标
- **季度跟踪**：Q1、Q2、Q3、Q4分别进行计划、完成、改进措施的记录
- **实时更新**：每季度结束后填写实际完成情况

### 4.2 考核维度权重逻辑

从模版设计来看，考核分为 **两大维度、四大模块**：

```
岗位职责考核
├── （一）基础业绩（业务产出）
│   ├── 核心工作内容（开发效率、收入指标等）
│   └── 团队管理（流失率等）
│
└── （二）组织成长（能力建设）
    ├── 招聘（人才引进）
    ├── 培养（人才发展）
    ├── 学习（个人成长）
    └── 培训（知识传承）
```

### 4.3 考核方式

| 考核方式 | 说明 | 适用场景 |
|:--------:|:----:|:--------:|
| **数值** | 量化指标打分 | 招聘数量、收入金额等 |
| **考核** | 定性评估 | 学习完成情况、行为规范等 |

### 4.4 排名机制

每季度对各项考核内容进行排名（`排名`列），用于：
- 横向对比团队成员表现
- 识别高绩效与待改进人员
- 为晋升/调薪提供数据依据

## 七、管理体系特点总结

### 7.1 特点一：双序列职级体系

M（管理）+ A（执行）+ P（专家）三序列并行，为不同类型人才提供发展通道：
- 管理者走M序列
- 执行者走A序列
- 技术专家走P序列

### 7.2 特点二：季度化PDCA循环

每个考核项都遵循 **Plan（计划）→ Do（执行）→ Check（检查）→ Act（改进）** 的循环：
- 每季度初：制定计划
- 每季度中：执行跟踪
- 每季度末：完成评估+改进措施

### 7.3 特点三：量化与定性结合

- **量化指标**：收入金额、bug数、流失率、工作饱和度等
- **定性指标**：学习完成情况、行为规范、培训效果等

### 7.4 特点四：自上而下的目标分解

- 团队负责人（韩伟）承担团队整体收入目标
- 收入目标分解到各组负责人
- 个人目标与团队目标对齐

### 7.5 特点五：组织成长与业务产出并重

不仅考核业务结果（基础业绩），还考核组织能力（招聘、培养、学习、培训），体现长期主义的人才观。

### 10.4 OS 1.0 vs OS 2.0 对比分析

| 对比维度 | OS 1.0 | OS 2.0 |
|----------|-------|-------|
| **定位** | 成熟产品线，功能全面 | 新一代产品，核心能力快速搭建 |
| **任务数** | 70项（细化到具体功能点） | 12组约51子项（按功能分组汇总） |
| **Git提交** | 615次（后端353+前端262） | 248次 |
| **开发周期** | 整个Q2（4月-6月） | 核心开发期约20天（6.10-6.30） |
| **功能广度** | 20个功能分组，覆盖面极广 | 12个功能分组，聚焦核心能力 |
| **完成率** | 100% | 100% |

#### 关键差异解读

**1. 架构演进（OS1.0 → OS2.0）**

OS1.0 Q2期间完成大量基础架构建设，OS2.0在此基础上进行了架构升级：

| 能力领域 | OS 1.0 实现方案 | OS 2.0 升级方向 |
|----------|----------------|----------------|
| 存储 | 多数据库适配（达梦、人大金仓、MySQL） | 全面转向PostgreSQL持久化 |
| 记忆 | 记忆进化核心+DB化生命周期 | 架构级重构（MemoryRouter多后端路由、ChromaDB向量集成、mem0+reme外部后端） |
| 技能 | 技能池DB化+编辑器UI | SQL持久化迁移+第三方导入源生态 |
| MCP | 连接测试+沙箱支持+容器隔离 | 数据源MCP（MySQL/ES/PG/Mongo/ClickHouse）+自动注入Agent toolkit |
| 编排 | 基础A2A智能体协作 | 嵌套团队编排+可取消运行+节点重试+子代理模板自定义 |
| 可观测性 | 智链追踪+Langfuse接入 | Langfuse深度埋点+团队模式追踪优化 |
| 认证 | 第三方登录+RBAC | JWT认证体系 |
| 部署 | docker-compose+K3s | Jenkins+ansible+Docker Compose双模式 |

**2. OS 2.0的创新亮点**

- **Deep Research能力**：联网检索降级能力，智能体可在联网检索失败时自动降级
- **记忆覆盖率飞跃**：单元测试覆盖率从59%提升至98%
- **技能生态拓展**：支持skills.sh / clawhub / skillsmp第三方导入源
- **多数据源MCP**：一套MCP框架接入MySQL、ES、PG、ClickHouse、MongoDB五种数据源
- **嵌套团队编排**：支持子代理模板自定义、团队leader权限上下文继承
