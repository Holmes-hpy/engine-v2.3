# 多Agent架构模式库

> 沉淀时间：2026-07-19
> 来源：智能体深度学习与调研（14轮对话）

---

## 4种原子模式

### PATTERN-001：MsgHub广播模式
- **信息流**：all-to-all 广播
- **类比**：微信群
- **代表框架**：AgentScope
- **特点**：所有Agent在共享消息空间，任何消息全员可见，各自决定是否响应
- **优势**：协作能力强，信息共享充分，自然广播
- **劣势**：Token消耗高（每个Agent处理所有消息），上下文污染严重
- **适用场景**：小团队（3-5个Agent）、头脑风暴、需要互相纠错补充

### PATTERN-002：Isolated Rooms隔离模式
- **信息流**：tree (parent-child) 父子间单向传递
- **类比**：独立办公室
- **代表框架**：Claude Code
- **特点**：每个子Agent有完全独立的上下文窗口，子Agent互不可见，只向父Agent返回结果摘要
- **优势**：上下文隔离，并行效率高，故障隔离
- **劣势**：协作弱，需通过父Agent中转，协调成本高
- **适用场景**：独立任务、敏感数据隔离、并行执行减少等待

### PATTERN-003：Sequential Pipeline流水线模式
- **信息流**：linear A→B→C 线性传递
- **类比**：工厂流水线
- **代表框架**：各框架Pipeline
- **特点**：顺序执行，前一个Agent输出是后一个输入
- **优势**：流程清晰，可预测
- **劣势**：串行瓶颈，一个环节阻塞全链路阻塞
- **适用场景**：标准化流程、步骤固定的任务

### PATTERN-004：Fan-out/Fan-in扇入扇出模式
- **信息流**：map-reduce
- **类比**：项目经理分发任务
- **代表框架**：LangGraph、AgentScope FanoutPipeline
- **特点**：主Agent动态创建子Agent（扇出），并行执行后汇总结果（扇入），子Agent不能再创建子Agent（关键限制：不递归）
- **优势**：天然并行，比预设层级灵活
- **劣势**：只能2层，主Agent成为瓶颈，子Agent间无法直接协作
- **适用场景**：批量处理、并行独立子任务、研究型多角度调研

## 4种工业级策略

### STRATEGY-001：预设层级（Preset Hierarchy）
- **实现**：代码中预先定义所有Agent角色和汇报关系
- **优势**：行为可预测，调试容易，Token可控，不会递归陷阱
- **劣势**：灵活性差，不能动态调整，扩展性差
- **代表**：MetaGPT、CrewAI Sequential/Hierarchical
- **适用**：标准化流程、需求明确步骤固定的任务

### STRATEGY-002：有限扇出（Limited Fan-out）
- **实现**：主Agent动态创建子Agent，但子Agent不能再创建（深度固定2层）
- **优势**：灵活，天然并行，不会递归爆炸
- **劣势**：只能2层，主Agent瓶颈，子Agent间无法直接协作
- **代表**：AgentScope FanoutPipeline、LangGraph Map-Reduce
- **适用**：批量处理、并行独立子任务

### STRATEGY-003：上下文压缩（Context Compression）
- **实现**：3级压缩——摘要压缩（LLM生成摘要）、结构化压缩（JSON/表格）、标签化记忆（Mark标签）
- **优势**：显著减少Token，保留关键信息，可与其他策略组合
- **劣势**：压缩本身消耗Token，过度压缩导致信息丢失，摘要可能引入偏差
- **代表**：AgentScope Memory压缩、LangGraph Checkpointer
- **适用**：长文档处理、多轮对话历史、多层Agent信息传递

### STRATEGY-004：动态子Agent（Dynamic Sub-Agents）
- **实现**：允许动态创建，但三层硬限制——深度限制（2-3层）、数量限制（5-10个）、步骤限制（K步ReAct循环）
- **优势**：最灵活，有限递归避免爆炸，子Agent独立上下文，自动生命周期管理
- **劣势**：实现最复杂，调试困难，成本仍较高，超过2层信息失真严重
- **代表**：Claude Code、LangGraph子图、AgentScope 2.0 Agent Team
- **适用**：软件工程、复杂研究任务、需要深度分解的问题

## 生产级组合模式

### COMPOSE-001：双层混合架构（推荐）
- **Layer 1**：MsgHub（部门经理共享广播，跨部门信息拉通）
- **Layer 2**：Isolated Rooms（部门内员工各自为战，独立执行）
- **信息流**：Layer1广播→Layer2隔离执行→摘要回传→Layer1汇总
- **3个优势**：上下文隔离、天然并行、故障隔离
- **4个挑战**：经理角色信息瓶颈、跨部门依赖处理、摘要质量决定成败、递归深度控制（最多两层）
- **类比**：公司组织架构——全员大会+部门内独立办公室
