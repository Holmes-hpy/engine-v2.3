## 1. 概述

> **重要声明**：本文件为**人工可读规则索引**，维护规则的基本信息（编号、名称、用途、适用场景）。

> 两者以 `_registry.yaml` 为权威来源。

## 3. 规则引用规范

### 3.1 引用格式

在任务执行过程中引用规则时，使用以下格式：

```markdown
根据规则 [G1-项目结构规范](rules/general/project-structure.md) 第 X 节，...
```

### 3.2 规则冲突处理

当多条规则对同一事项有不同规定时，按以下优先级解决：

1. 项目特定规则 > 通用规则
2. 新注册规则 > 旧注册规则（以注册时间为准）
3. 明确引用规则 > 默认规则

## 4. 规则更新流程

### 4.1 新增规则

1. 在对应分类目录下创建新的 `.md` 文件
2. 更新本注册表的对应章节
3. 记录变更到 `docs/decisions/`
4. 同步更新认知闭环知识库

### 4.2 修改规则

1. 编辑目标规则文件
2. 在文件头部更新 `version` 字段（遵循 semver 格式：MAJOR.MINOR.PATCH）
3. 在变更处添加修改标记：`[MODIFIED: YYYY-MM-DD]`
4. 更新 `_registry.yaml` 中的对应规则 `version` 字段
5. 运行 `scripts/validate_rules.py` 检查依赖影响
6. 提交 Git

### 4.3 废弃规则

1. 在规则文件头部添加 `> **状态**: 已废弃`
2. 在本注册表中标记为废弃
3. 保留文件至少一个版本周期

## 6. 跨规则引用变更通知

当某条规则被修改时，必须检查哪些规则引用了它，并生成变更通知。

### 6.1 变更通知格式

```markdown
## 规则变更通知
- 变更规则: {RULE_ID} - {RULE_NAME}
- 变更日期: YYYY-MM-DD
- 变更内容: {简要描述}
- 受影响规则: {RULE_ID列表}
- 需要的操作: {检查并更新/无需操作}
```

### 6.2 自动检查

修改规则后运行 `scripts/validate_rules.py --check-refs`，自动生成变更通知并输出到 `logs/bootstrap/rule-change-notification.md`。
