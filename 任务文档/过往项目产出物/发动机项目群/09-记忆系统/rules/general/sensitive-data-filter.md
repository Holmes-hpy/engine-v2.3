# 敏感数据过滤规则

> **项目**: v1.3.0 (v1.3.0)
> **启用状态**: true
> **生成时间**: 2026-07-16T07:00:00+08:00
> **启动包版本**: 1.3.0

## 1. 概述

本规则定义项目中敏感数据的识别、过滤和处理规范。所有输出（包括日志、交接报告、知识沉淀）在写入前必须经过敏感数据过滤。

## 2. 敏感数据类型

### 2.1 预定义敏感模式

| 类别 | 模式描述 | 正则表达式示例 |
|------|----------|----------------|
| 密钥 | API Key、Secret Token | `[A-Za-z0-9_]{32,}` |
| 密码 | 明文密码 | `(?i)password[:\s]*[^\s]+` |
| 令牌 | Bearer Token、JWT | `bearer\s+[A-Za-z0-9_\-\.]+` |
| 路径 | 绝对 home 路径 | `/Users/[A-Za-z0-9]+/` |
| 邮箱 | 电子邮件地址 | `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` |
| 手机号 | 手机号码 | `1[3-9]\d{9}` |
| 身份证 | 身份证号 | `\d{17}[\dXx]` |

### 2.2 编码混淆检测

除明文匹配外，本规则支持对以下编码形式的敏感数据进行检测：

| 混淆类型 | 特征 | 检测方式 | 示例 |
|----------|------|----------|------|
| Base64 编码 | `[A-Za-z0-9+/=]{20,}` 且非正常文本 | 解码后重新匹配敏感模式 | `c2stdGh5XXXX` → `sk-xxx` |
| URL 编码 | 包含 `%XX` 模式的敏感数据 | 先 URL 解码再匹配 | `%73%6B%2D` → `sk-` |
| 十六进制编码 | 连续十六进制字符 | 转为 ASCII 后匹配 | `736B2D` → `sk-` |
| Unicode 同形字 | 使用外观相似字符替换 | 同形字映射表检测 | `sｋ-ｘｘｘ` → `sk-xxx` |
| 零宽字符插入 | 不可见字符嵌入敏感数据 | 剥离零宽字符后匹配 | `sk\u200B-xxx` → `sk-xxx` |
| 分段输出 | 敏感数据被空格/换行拆分 | 合并相邻疑似片段后匹配 | `s k - x x x` → `sk-xxx` |

**检测流程**：

```
原始文本 → 零宽剥离 → Unicode同形还原 → URL解码 → Base64解码(如匹配特征) → 十六进制解码(如匹配特征) → 分段合并 → 敏感模式匹配
```

**性能约束**：编码混淆检测仅在以下场景启用（避免对大文件全量解码）：
- 日志文件：逐行检测
- 交接报告：全量检测
- 知识沉淀：全量检测
- 交付物文件：仅检测代码块和配置块

**注意**：所有解码操作均在本地内存中执行，不调用任何外部服务。

### 2.4 项目特定模式添加流程

添加项目特定敏感模式必须经过以下三步流程：

1. **定义** — 在本节添加模式名称、正则表达式、所属类别和示例
2. **测试** — 使用 `scripts/sensitive_scan.py --test` 验证模式的准确率和误报率
3. **注册** — 更新规则文件，并在变更日志中记录新增模式

## 3. 过滤策略

### 3.1 策略等级

| 等级 | 名称 | 处理方式 |
|------|------|----------|
| 1 | 阻断 | 发现即阻止输出，记录告警 |
| 2 | 脱敏 | 替换为 `[REDACTED-类别]` |
| 3 | 哈希 | 替换为不可逆哈希值 |
| 4 | 警告 | 允许通过，记录 WARNING 日志 |

### 3.2 默认策略映射

| 敏感类别 | 默认策略 |
|----------|----------|
| 密钥 | 阻断 |
| 密码 | 阻断 |
| 令牌 | 脱敏 |
| 路径 | 脱敏 |
| 邮箱 | 脱敏 |
| 手机号 | 哈希 |
| 身份证 | 哈希 |

## 4. 过滤执行点

敏感数据过滤在以下位置执行：

1. **日志写入前** — `logs/` 目录下的所有日志文件
2. **交接报告生成时** — `rules/output/handoff-contract.md` 定义的输出
3. **知识沉淀写入时** — `memory/knowledge/` 和 `.memory/knowledge.db`
4. **任务状态导出时** — `tasks/` 目录下的 JSON 文件
5. **交付物写入时** — `output/deliverables/` 和 `output/drafts/` 目录下的所有文件

## 5. 过滤日志

所有过滤操作记录到 `logs/sensitive-filter.log`：

```
[YYYY-MM-DD HH:MM:SS] [LEVEL] 文件路径: 发现敏感数据 [类别], 应用策略 [策略]
```

## 6. 开关控制

本规则可通过参数 `true` 控制：

- `true`（默认）— 启用完整过滤
- `false` — 禁用过滤（仅记录 WARNING，不推荐生产环境使用）

## 7. 零API依赖声明

本规则的全部过滤逻辑基于本地正则表达式匹配，不调用任何外部 API 或服务，完全在本地执行。
