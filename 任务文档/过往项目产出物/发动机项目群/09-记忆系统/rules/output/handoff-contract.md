# 任务交接契约

> **项目**: v1.3.0 (v1.3.0)
> **生成时间**: 2026-07-16T07:00:00+08:00
> **启动包版本**: 1.3.0

## 1. 概述

本规则定义任务完成时的交接标准和报告格式。每次任务（尤其是复杂任务或多步骤任务）完成后，必须生成交接报告，确保后续任务或不同 Agent 能够正确接续。

## 2. 交接触发条件

以下情况必须生成交接报告：

1. 任务状态变为 `completed` 或 `failed`
2. 任务执行过程中发生 Agent 切换
3. 任务涉及多个 Phase 或子任务
4. 任务产生需要后续使用的中间产物

## 3. 交接报告格式

### 3.1 文件位置

交接报告存储路径：

```
logs/handoff/{TASK_ID}/handoff-report-{TIMESTAMP}.md
```

简单任务的最小交接信息记录在交接报告头部。

### 3.2 报告结构

```markdown
# 任务交接报告

## 基本信息
- 任务 ID: {TASK_ID}
- 任务名称: {TASK_NAME}
- 项目: v1.3.0 (v1.3.0)
- 执行 Agent: {AGENT_ID}
- 开始时间: {START_TIME}
- 结束时间: {END_TIME}
- 任务状态: completed / failed / blocked

## 执行摘要
{用 3-5 句话概括任务执行情况和结果}

## 已完成工作
1. {具体完成项 1}
2. {具体完成项 2}
3. ...

## 产物清单
| 产物名称 | 路径 | 类型 | 状态 |
|----------|------|------|------|
| {名称} | {相对路径} | {文件类型} | final / draft |

## 已知问题
- {如有问题，逐项列出}
- {如无问题，写"无"}

## 待办事项
- [ ] {后续需要完成的事项 1}
- [ ] {后续需要完成的事项 2}

## 技术债务
- {如有，列出需要后续重构或优化的点}

## 关键决策
- {任务过程中做出的重要决策及理由}

## 上下文状态
{描述当前系统/项目的状态，供后续任务参考}

## 建议的下一步
1. {建议的下一步操作}
2. {备选方案}
```

### 3.3 交接模式

| 模式 | 适用场景 | 字段数量 | 预计填写时间 |
|------|----------|----------|-------------|
| 完整模式 (full) | 跨角色/跨阶段正式交接 | 全部 20+ 字段 | 15-30 分钟 |
| 轻量模式 (light) | 同角色内简单交接 | 4 个核心字段 | 5 分钟内 |

**轻量模式核心字段**：
- 基本信息（任务 ID、名称、状态）
- 已完成工作
- 待办事项
- 已知问题

交接报告中通过 `交接模式: full|light` 字段区分。

### 3.4 交接模式自动判定

| 条件 | 判定结果 |
|------|----------|
| 任务步骤数 ≤ 2 且无跨角色切换 | light |
| 任务步骤数 ≤ 2 且有跨角色切换 | full |
| 任务步骤数 > 2 | full |
| 任务包含子任务 | full |
| 任务产物涉及外部系统对接 | full |
| 其他情况 | light |

判定时机：任务进入"交接"阶段时，根据任务 JSON 中的 `subtasks` 数量和 `role_switches` 字段自动判定。

## 4. 交接验证

### 4.1 自我验证

生成交接报告后，执行者必须检查：

- [ ] 所有产物路径正确且可访问
- [ ] 已完成工作描述准确
- [ ] 待办事项明确且可执行
- [ ] 关键决策有充分理由

### 4.2 接收验证

接收方（下一个 Agent 或任务）必须：

- [ ] 阅读交接报告全文
- [ ] 确认所有产物可访问
- [ ] 理解当前上下文状态
- [ ] 明确下一步工作内容

### 5.1 交接失败处理

如果交接报告缺失或不合格：

1. 标记任务状态为 `handoff_incomplete`
2. 要求执行方补充交接报告
3. 如执行方不可用，由接收方基于现有信息逆向生成交接报告
4. 记录交接问题到 `tasks/completed/handoff-issues.log`

### 5.2 逆向交接

当执行方不可用时，接收方可以基于现有信息逆向生成交接报告：

1. 接收方在 `in_progress` 状态下执行逆向交接操作
2. 逆向交接报告标记为 `mode: reverse`
3. 生成后在任务日志中记录 `[REVERSE-HANDOFF] TASK-NNNN: 逆向交接报告已生成`
4. 原任务的 `handoff_incomplete` 状态变更为 `completed`

## 6. 最小交接原则

即使是最简单的任务，也必须提供最小交接信息：

```markdown
## 最小交接
- 任务: {TASK_NAME}
- 状态: completed
- 产物: {文件路径}
- 备注: {如有特殊注意事项}
```
