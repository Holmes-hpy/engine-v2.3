## 本质认知原则

### P-001：Agent的本质公式
```
Agent = LLM + Tools + Memory + Autonomy（自主性）
Agent = Model × Harness（2026新范式）
```
自主性（Autonomy）是Agent与ChatBot的根本区别，不是"固化提示词"。

### P-002：真正的转折点是Function Calling（2023.06）
- CoT（2022）让LLM"想清楚"
- Function Calling让LLM"能行动"——这才是Agent诞生的真正标志
- 上下文窗口扩展是使能条件，不是原因；即使给ChatBot无限上下文，它仍然只是一问一答

### P-003：Agent本质是闭环控制系统
类似恒温器或自动驾驶：
- 感知 = 传感器（读取环境状态）
- 大脑 = 控制器（决策）
- 规划 = 路径规划
- 记忆 = 状态存储
- 工具 = 执行器（改变环境）
核心循环：感知→决策→行动→观察→感知→...

### P-004：多Agent架构的本质区别是信息流，不是结构
表面看都是"主Agent+子Agent"，但核心差异在信息流方向：
- MsgHub是微信群广播（all-to-all）
- Isolated是独立办公室（tree, parent-child）
- Pipeline是流水线（linear A→B→C）
- Fan-out是项目经理分发（map-reduce）

## 架构设计原则

### P-005：禁止无限递归
递归多Agent架构存在6大现实挑战：上下文爆炸、成本爆炸、通信噪音、协调损耗、递归陷阱、质量退化。工业界必须用策略限制复杂度。

### P-006：最多两层架构
生产级混合架构建议：Layer1 MsgHub跨部门拉通 + Layer2 Isolated部门内各自为战。超过两层，信息失真指数级放大。

### P-007：策略组合而非单一策略
工业界生产级系统从不只用一种策略，而是组合：
- 外层：预设层级（CEO→部门经理）
- 中层：有限扇出（经理→员工并行）
- 内层：上下文压缩（员工结果摘要回传）
- 局部：动态子Agent（特殊复杂任务临时招人）

## 上下文管理原则

### P-008：上下文窗口管理四法则
1. **按需加载SKILL**：每个Agent只加载自己需要的SKILL片段
2. **信息压缩传递**：原始材料→精炼信息表→摘要，层层压缩
3. **并行隔离**：每个Worker独立Session，不是在同一个上下文里加墙
4. **终态依赖显式化**：明确声明谁依赖谁的输出，避免读到半成品

### P-009：Session切换的关键现象
切换到新Agent时：当前窗口占用重置（新Session），但全局累计Token消耗继续增长。这个"当前重置但全局不重置"是理解多Agent上下文管理的关键。

## 工程演化原则

### P-010：AI工程三代演化
```
Prompt Engineering (2023) → Context Engineering (2025) → Harness Engineering (2026)
```

### P-011：递归防护是生死线
Anthropic血泪教训：不加防护，子Agent会为简单查询创建50个孙Agent，瞬间烧光API额度。必须双层防护：
- 静态过滤：子Agent工具列表直接不包含SpawnAgent
- 运行时Guard：检查当前嵌套深度>=最大深度则拒绝

## 侯鹏远个人洞察（来自自学.md）

### P-012：Agent/Memory本质是"剥离"而非"诞生"
Agent和Memory不是新发明，是对原有一体化Prompt+上下文的功能剥离：
- Memory负责存储上下文，独立存放
- Agent = 固化的工作流程 + 思维链加强，赋予"人"的属性（名字、专门职责）

### P-013：工程化本质是抑制幻觉
大模型幻觉一部分来自智力限制，另一部分来自上下文太小记不住——工程化手段（工作流、SKILL、MCP、约束）本质上是在用各种方式约束大模型，抑制幻觉。

### P-014：大模型应用演进 = 上下文窗口放大的过程
Chat → Copilot → LangChain → Agent → 低代码平台，每一步都是因为上下文窗口变大，能塞进更多东西，工程化手段随之升级。
