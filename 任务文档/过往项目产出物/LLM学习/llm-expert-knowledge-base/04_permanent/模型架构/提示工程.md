# 提示工程

## 概述
提示工程是设计和优化输入给LLM的提示，以获得更好、更可靠、更符合预期的输出。

## 基础技巧

### 清晰明确
- 具体要求，避免模糊
- 提供上下文和约束
- 定义输出格式

### 示例：
不好："写点东西关于AI"
好："写一篇300字关于大语言模型最新发展的文章，用通俗易懂的语言，面向非技术读者"

## 核心技术

### Zero-shot Prompting
直接提问，无需示例。
```
问题：什么是Transformer架构？
```

### Few-shot Prompting
提供几个输入输出示例。
```
用户：1+1=？   助手：2
用户：2+3=？   助手：5
用户：5+8=？   助手：
```

### Chain-of-Thought
让模型一步步思考。
```
让我们一步步思考这个问题：
问题：A比B多3，B是10，A是？
```

### ReAct
结合推理和行动，让模型调用工具。
```
思考：我需要查明天的天气
行动：搜索天气
观察：明天晴
思考：用户需要穿着建议
...
```

## 高级技巧

### Role Prompting
给模型分配角色。
```
你是一位资深的Python技术专家，
有10年经验，擅长解释复杂概念。
```

### Structured Output
要求特定输出格式，如JSON、XML、Markdown表格。
```
请用JSON格式输出：
{"title": "", "summary": "", "tags": []}
```

### Prompt Chaining
把复杂任务分解为多个提示。
```
步骤1：分析用户问题的类型
步骤2：提取相关信息
步骤3：生成回答
```

### Self-Consistency
生成多个答案，选一致性最高的。

### Tree-of-Thoughts
探索多个推理路径，类似搜索树。

## 提示策略

### Instruction Tuned模型适用的提示
```
【任务】
【要求】
【格式】
【示例】
```

### 对话模型的提示
- 系统消息设置人设
- 对话历史提供上下文
- 最后一条是当前问题

### 最佳实践

1. **指令明确**
清楚告诉模型要做什么，而不是做什么

2. **分步思考**
Chain-of-Thought可以大幅提升复杂问题的效果

3. **格式规范**
清楚定义输出格式，特别是结构化数据

4. **提供示例**
Few-shot比zero-shot通常更可靠

5. **迭代优化**
测试、调整、再测试

6. **添加约束**
明确告诉模型不要做什么

## 提示工程进阶

```
帮我写一个能够有效回答技术问题的系统提示词。
```

- 用词要具体

- 提供示例
- 格式要明确

### 提示注入防护

- 输出验证

## 常见问题

### 模型不遵循指令
可能原因：
- 指令不够明确
- 模型太小
- 任务太难

解决方案：
- 重新表达指令
- 添加示例
- 调整格式
- 选择更好的模型

### 输出不稳定
- 使用结构化输出
- 温度调低
- 增加示例
- 使用提示链

### 幻觉问题
- RAG补充外部信息
- 要求提供引用
- 明确只回答确定知道的
- 添加"不知道"的选项
