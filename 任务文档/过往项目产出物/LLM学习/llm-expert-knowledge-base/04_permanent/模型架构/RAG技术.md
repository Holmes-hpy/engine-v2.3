# RAG (Retrieval Augmented Generation)

## 概述

检索增强生成（RAG）是一种将信息检索与文本生成相结合的技术，让模型能够利用外部知识回答问题，减少幻觉。

## 工作原理

### 核心流程

1. **索引阶段**
   - 加载文档
   - 文档切分
   - 向量化
   - 存入向量数据库

2. **查询阶段**
   - 用户问题向量化
   - 向量相似度搜索
   - 找到相关文档片段
   - 将相关文档加入上下文
   - 让LLM基于检索信息回答

## 核心组件

### 文档加载

支持多种格式：
- PDF
- Markdown
- HTML
- 数据库查询
- API返回

常用库：
- LangChain Document Loaders
- LlamaIndex Readers
- Unstructured

### 文档切分

切分策略：
- 按字符切分
- 按标题递归切分
- 按语义单元切分
- 固定窗口+重叠

最佳实践：
- 有意义的切分点（句子/段落）
- 适当的重叠（保持上下文连续性）
- 考虑模型上下文窗口大小

### 嵌入模型

将文本转换为向量：
- Sentence-BERT系列
- OpenAI text-embedding-3-small
- Cohere Embed
- MTEB排行榜：评估嵌入质量

建议：
- 选择针对任务优化的嵌入模型
- 考虑数据领域匹配度

### 向量数据库

存储和检索向量：
- **Chroma**：轻量级，本地部署
- **Pinecone**：云服务，托管
- **Milvus**：开源，功能丰富
- **Qdrant**：快速，易用
- **FAISS**：Meta的高效库，不持久化
- **Annoy**：Spotify出品

选择考虑：
- 数据规模
- 部署成本
- 查询性能
- 功能需求

## 检索策略

### 基础检索
- 相似度搜索
- 关键字搜索
- 混合搜索（语义+关键字）

### 高级策略
- **HyDE**：先生成假设回答再检索
- **CoRAG**：查询重写
- **RAG-Fusion**：多次检索+融合
- **多向量检索**：每个文档多个向量

### 重排序
先用快速粗筛，再用强模型精细排序：
- Cohere Rerank
- CrossEncoder
- 小模型专用重排序器

## RAG框架

### LangChain
- 成熟稳定
- 组件化设计
- 大量集成

### LlamaIndex
- 数据优先
- 灵活的索引结构
- 适合复杂数据场景

### 原生实现
- 完全控制
- 按需定制
- 学习成本较高

## RAG评估

### 检索指标
- **Context Precision**：相关内容比例
- **Context Recall**：召回率

### 生成指标
- **Faithfulness**：忠实性，不编造
- **Answer Relevancy**：回答相关性

### 工具
- **Ragas**：RAG专用评估工具
- **DeepEval**：深度评估框架
- **TruLens**：追踪和评估

## 高级RAG

### 查询构造
- Text-to-SQL：自然语言转SQL查询
- 查询图数据库：Cypher查询
- 元数据过滤：按条件筛选

### 工具使用
- Agents可以调用工具
- 自动选择合适的检索策略

### RAG + Agents
- 规划检索策略
- 多步推理
- 验证回答质量

## 最佳实践

1. **文档预处理**：清洗、去重、标准化
2. **合适的切分**：保持语义完整性
3. **质量嵌入**：使用好的嵌入模型
4. **混合检索**：结合关键字和语义
5. **重排序**：提升最终相关性
6. **迭代优化**：根据反馈持续改进

## 常见问题

### 幻觉
原因：检索结果不足或不相关
解决：增加检索量，改进嵌入，重排序

### 时效性
问题：知识库内容过时
解决：定期更新，增加时间过滤

### 成本
问题：嵌入和LLM调用成本高
解决：缓存、批处理、小模型筛选
