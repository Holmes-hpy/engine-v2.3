
# 分布式训练实践指南

## 概述

大模型时代，模型越来越大——从7B到70B到400B再到万亿参数，单张GPU根本装不下。分布式训练就是解决"一个人干不完，大家一起干"的问题。

**一句话总结**：把一个大模型拆成很多份，分给多张GPU（甚至多台机器）一起训练，最后拼起来。

**为什么重要**：
- 模型太大，单GPU装不下
- 数据太多，单GPU训太慢
- 时间就是金钱，早一天训完早一天上线

---

## 分布式训练的类型

### 两种基本范式

```
分布式训练
    ├── 数据并行（Data Parallelism）
    │   └── 每个GPU都有完整的模型，各训各的数据，最后同步梯度
    │
    └── 模型并行（Model Parallelism）
        ├── 张量并行（Tensor Parallelism）
        │   └── 把一层拆成多份，分给不同GPU
        └── 流水线并行（Pipeline Parallelism）
            └── 把不同层分给不同GPU，像流水线一样流转
```

---

### 数据并行（Data Parallelism, DP）

#### 原理

每张GPU都有完整的模型副本，每张GPU处理不同的数据batch，最后把所有GPU的梯度汇总，更新模型。

```
GPU 0: 模型副本 + 数据 batch 0 → 梯度 0
GPU 1: 模型副本 + 数据 batch 1 → 梯度 1
GPU 2: 模型副本 + 数据 batch 2 → 梯度 2
GPU 3: 模型副本 + 数据 batch 3 → 梯度 3
            ↓
        梯度同步（AllReduce）
            ↓
        所有GPU同步更新模型
```

**类比**：4个学生各自做不同的练习题，做完后互相对答案，然后所有人都用统一的正确答案更新自己的知识。

#### 优点
- 简单，容易实现
- 通信量可控（只需要同步梯度）
- 训练速度几乎线性提升（8张GPU≈快8倍）

#### 缺点
- 每张GPU都要存完整的模型，模型太大就装不下
- GPU越多，通信开销越大

#### 适用场景
- 模型不是特别大（能塞进单张GPU）
- 数据量大，想加快训练速度

---

### 张量并行（Tensor Parallelism, TP）

#### 原理

把模型的每一层（比如Transformer的Attention和FFN）拆成多份，每张GPU只存一层的一部分。

```
以线性层 Y = XA 为例：

按列切分A：A = [A1 A2]
   GPU 0 存 A1 → Y1 = XA1
   GPU 1 存 A2 → Y2 = XA2
   最后 Y = [Y1 Y2]（AllGather）

按行切分A：A = [A1; A2]
   GPU 0 存 A1，处理 X 的前半部分
   GPU 1 存 A2，处理 X 的后半部分
   最后 Y = X1A1 + X2A2（AllReduce）
```

**类比**：把一道数学题拆成两部分，一个人算前一半，另一个人算后一半，最后加起来就是答案。

#### 优点
- 能训练超大模型（单GPU装不下的那种）
- 显存占用按并行度线性降低

#### 缺点
- 通信量大，每层都要通信
- GPU之间需要高速连接（NVLink）
- 实现复杂

#### 适用场景
- 模型太大，单GPU装不下
- GPU之间有高速互联

---

### 流水线并行（Pipeline Parallelism, PP）

#### 原理

把模型的不同层分给不同的GPU，数据像流水线一样依次流过每张GPU。

```
GPU 0: 第1-8层  → 输出给 GPU 1
GPU 1: 第9-16层 → 输出给 GPU 2
GPU 2: 第17-24层 → 输出给 GPU 3
GPU 3: 第25-32层 → 最终输出
```

**类比**：工厂流水线——第一个工人做第一步，做完传给第二个工人做第二步，一直传到最后。

#### 气泡问题（Bubble）

流水线有个天然的问题：刚开始和结束时，有些GPU是空闲的，就像水管里的"气泡"。

```
时间 →
GPU0: ██████░░░░
GPU1: ░██████░░░
GPU2: ░░██████░░
GPU3: ░░░██████░
     ↑
  气泡（空闲时间）
```

**解决方法**：把一个大batch拆成很多小batch（micro-batch），让流水线尽量充满。

#### 优点
- 支持超大规模模型
- 通信量比张量并行小（只在层间传输激活值）

#### 缺点
- 有气泡，利用率不是100%
- 实现复杂

#### 适用场景
- 超大规模模型训练
- 机器之间网络不是特别快的情况

---

### 混合并行：3D并行

实际训练大模型时，通常不是只用一种方式，而是三种结合起来用，叫"3D并行"。

```
一台机器内（8张GPU）：
  - 张量并行（TP=8）：每层拆成8份
    或者
  - 数据并行（DP=8）：8个副本

多台机器间：
  - 流水线并行（PP）：不同层放不同机器
  - 数据并行（DP）：多组流水线并行处理不同数据

典型配置（训练70B模型）：
  PP=4（4台机器做流水线）
  TP=8（每台机器8张GPU做张量并行）
  DP=2（2组这样的配置做数据并行）
  总共：4 × 8 × 2 = 64张GPU
```

## 关键优化技术

### 混合精度训练（Mixed Precision）

#### 原理

用FP16（半精度）做前向和反向传播，用FP32（单精度）存模型权重和做梯度更新。

**为什么能行**：
- FP16显存占一半，速度快一倍
- 权重更新需要高精度，所以用FP32存权重
- 梯度累积也用FP32，避免精度损失

#### 损失缩放（Loss Scaling）

FP16的表示范围小，梯度太小的时候会变成0（下溢）。解决方法是把loss乘一个大的数（scale factor），反向传播后再除回去。

---

### ZeRO优化（Zero Redundancy Optimizer）

DeepSpeed的招牌技术，解决数据并行中"每张GPU都存完整模型"的浪费问题。

| 级别 | 优化内容 | 显存减少 | 通信量 |
|------|---------|---------|--------|
| **ZeRO-1** | 分片优化器状态 | ~4x | 少量增加 |
| **ZeRO-2** | 分片优化器 + 梯度 | ~8x | 中等增加 | |
| **ZeRO-3** | 分片优化器 + 梯度 + 权重 | ~Nx（N=GPU数） | 较多增加 | |

**类比**：
- 普通数据并行：每个人都带完整的工具箱（很重）
- ZeRO：大家把工具凑一起用，谁需要什么就传过去

---

### 激活重计算（Activation Checkpointing）

#### 原理

反向传播需要中间激活值，但存激活值太费显存。激活重计算的思路是：前向时不存所有激活值，反向时需要哪个再重新算哪个。

**权衡**：用计算换显存——多花20-30%的计算时间，省一大笔显存。

**类比**：就像考试时不把所有公式都背下来（费脑子），而是现场推导（费时间）。

---

### 梯度累积（Gradient Accumulation）

#### 原理

显存不够跑大batch？那就分多次跑，每次算的梯度累积起来，到一定次数再更新。

```
正常：大batch → 算梯度 → 更新权重
梯度累积：小batch1 → 算梯度 → 存起来
         小batch2 → 算梯度 → 加起来
         小batch3 → 算梯度 → 加起来
         ...
         累积够了 → 更新权重
```

**效果**：等效于大batch，但只需要小batch的显存。

## 训练技巧与最佳实践

### 学习率与Batch Size

| 现象 | 原因 | 解决方法 |
|------|------|---------|
| loss震荡不收敛 | 学习率太大 | 调小学习率 |
| loss下降很慢 | 学习率太小 | 调大学习率 |
| 多卡训练效果变差 | batch变大了，学习率没跟上 | 线性缩放学习率 | | | （batch翻倍，lr也翻倍） | | | |

### 学习率调度

训练时学习率不是一成不变的，通常是：
1. **warmup**：先从小学习率慢慢升上去（防止初期不稳定）
2. **稳定训练**：用设定的学习率训练
3. **衰减**：后期慢慢降低学习率，让模型收敛更精细

**常见调度器**：
- CosineAnnealing（余弦退火）
- LinearWarmup + CosineDecay
- LinearWarmup + LinearDecay

## 常见问题排查

| 问题 | 可能原因 | 排查步骤 |
|------|---------|---------|
| 显存溢出（OOM） | 模型太大、batch太大 | 1. 减小batch size 2. 开梯度累积 3. 开激活重计算 4. 用ZeRO-Offload | | | 5. 换成显存更大的GPU方案 | | | |
| 训练速度慢 | 数据IO瓶颈、通信瓶颈 | 1. 检查GPU利用率 2. 检查数据加载速度 3. 检查通信占比 | | | 4. 增大batch提高利用率 | | | |
| 多卡比单卡还慢 | 通信开销太大 | 1. 减少通信频率 2. 增大batch 3. 检查网络连接 | | | 4. 用更高效的并行策略 | | | |
| loss不下降 | 学习率不对、数据有问题 | 1. 调学习率 2. 检查数据 3. 检查模型结构 | | | 4. 检查损失函数 | | | |
| 多卡效果比单卡差 | 学习率没调、BN同步问题 | 1. 线性缩放学习率 2. 用SyncBatchNorm | | | 3. 增加warmup步数 | | | |

## 总结

分布式训练是大模型时代的必备技能，核心是用"多人协作"的思路解决单GPU不够用的问题。

**核心认知**：
1. 没有"最好"的方案，只有"最适合"的方案——根据你的模型规模、硬件条件、预算来选
2. 速度和显存是一对矛盾——想省显存就要牺牲速度，想快就要多花钱
3. 分布式训练不是简单的"人多力量大"——通信开销、气泡、调试复杂度都会增加
4. 选框架要看生态和团队熟悉度——适合团队的才是最好的

**选型建议**：
- 初学者/快速验证 → DeepSpeed（文档全、社区大、上手快）
- 极致性能追求 → Megatron-LM（英伟达官方、性能最强）
- 中文生态/低成本 → Colossal-AI（国产、优化方案多、中文支持好）
