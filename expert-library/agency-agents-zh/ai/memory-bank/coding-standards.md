# 编码规范

## 通用原则
1. 代码必须具有可读性和可维护性
2. 遵循DRY(Don't Repeat Yourself)原则
3. 保持函数和类的单一职责
4. 编写有意义的注释
5. 所有代码必须通过代码审查

## 命名约定
- **文件命名**: kebab-case (小写字母+连字符)
- **变量命名**: camelCase (小驼峰)
- **常量命名**: UPPER_SNAKE_CASE (大写蛇形)
- **函数命名**: camelCase (小驼峰)
- **类命名**: PascalCase (大驼峰)
- **组件命名**: PascalCase (大驼峰)
- **CSS类命名**: kebab-case (小写字母+连字符)

## 代码风格
- 使用2个空格缩进
- 每行代码不超过80个字符
- 语句末尾必须加分号
- 使用单引号(')而非双引号(")
- 大括号必须与语句在同一行
- 运算符前后必须有空格

## Git规范
- **分支命名**: feature/功能名 / bugfix/问题描述 / hotfix/紧急修复
- **提交信息格式**: type(scope): description
  - type: feat, fix, docs, style, refactor, test, chore
- 每个提交应该只包含一个逻辑变更
- 提交前必须运行代码检查和测试

## 测试规范
- 单元测试覆盖率不低于80%
- 所有公共API必须有测试用例
- 测试用例应该清晰、独立、可重复
- 使用描述性的测试名称

## 安全规范
- 永远不要在代码中硬编码密钥和密码
- 所有用户输入必须进行验证和清理
- 防止SQL注入和XSS攻击
- 遵循最小权限原则
