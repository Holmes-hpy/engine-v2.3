# 规则体系说明

> **版本**: v2.3.0
> **规则数量**: 7+1（7个核心规则 + 1个注册表）
> **入口文件**: 根目录 `rules.md`（LLM 首先读取的跳板文件）

---

## 规则文件清单

本项目采用**扁平化**规则体系，所有规则文件直接放在 `rules/` 目录下，不再分子目录。

| 编号 | 文件 | 内容 | 优先级 |
|------|------|------|--------|
| 00 | `00-meta.md` | 元规则：规则优先级、冲突解决、扩展协议 | P0 |
| 01 | `01-llm-behavior.md` | LLM行为约束：方案优先、反问不猜 | P1 |
| 02 | `02-project-structure.md` | 项目结构与命名规范 | P2 |
| 03 | `03-task-execution.md` | 任务状态机与生命周期 | P3 |
| 04 | `04-knowledge.md` | 知识沉淀、捡破烂、三层挖掘机制 | P4 |
| 05 | `05-output.md` | 产出物管理与不可变原则 | P5 |
| 06 | `06-hallucination-prevention.md` | 大模型幻觉防控：置信度标记、魔鬼代言人 | P6 |
| - | `_registry.yaml` | 规则注册表（机器可读的规则索引） | - |

---

## 规则加载顺序

1. LLM 先读根目录 `rules.md`（跳板文件）
2. `rules.md` 指向 `rules/` 目录下的全部规则文件
3. 按编号 00→06 顺序读取
4. 同时读取 `_registry.yaml` 和 `项目使用指南.md`

---

## 规则优先级

```
00-meta > 01-llm-behavior > 02-project-structure > 03-task-execution > 04-knowledge > 05-output > 06-hallucination-prevention
```

冲突时编号小的规则胜出。

---

## 规则变更

1. 修改规则文件内容
2. 更新文件头部的版本号和 changelog
3. 更新 `_registry.yaml` 中的对应条目
4. 同步更新根目录 `rules.md` 和 `项目使用指南.md`（如有需要）
