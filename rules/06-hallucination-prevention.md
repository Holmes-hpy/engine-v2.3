# 大模型幻觉防控规则

> **版本**: v2.3.0
> **优先级**: P6
> **说明**: 本文件定义 LLM 输出中的幻觉防控机制，包括置信度标记、输出自检清单和魔鬼代言人反向论证。仅做第一步（规则层 + Prompt 模板层），后续工具层和多 Agent 交叉验证按需自行扩展。

---

## 0. 前置声明

本规则提供的防护是**辅助性**的，不能替代人工判断。规则和 Prompt 能降低幻觉风险，但不能消除。提出问题的用户是最终决策者，LLM 输出永远是参考材料而非权威结论。

---

## 1. 置信度标记机制

### 1.1 标记定义

所有 LLM 生成内容中涉及事实性断言、数据、结论的部分，必须按以下三级标记置信度：

| 标记 | 含义 | 触发条件 |
|:---:|------|------|
| **[可靠]** | 有明确上下文或检索来源直接支撑 | 检索相似度 ≥ 0.7，或 Prompt 中提供了原文 |
| **[推断]** | 基于上下文合理推断，但无直接原文支撑 | 检索相似度 0.4-0.7，或基于上下文片段逻辑推理 |
| **[推测]** | 上下文覆盖不足，偏差可能性较大 | 检索相似度 < 0.4，或上下文无相关信息 |

### 1.2 阈值标准

**RAG 检索场景**：以向量检索的余弦相似度（cosine similarity）或 Reranker 分数为判断依据。

```
相似度 ≥ 0.7  → [可靠]
相似度 0.4-0.7 → [推断]
相似度 < 0.4  → [推测]
```

**非检索场景（纯 LLM 生成）**：以模型自评估为判断依据。在输出前追加一句自问：

> "以上内容中，哪些断言有明确的上下文支撑？哪些是基于训练知识的推断？哪些属于推测？"

模型须在回答中明确区分。

### 1.3 输出格式要求

**如果整段内容置信度一致**，在段落开头统一标记：

```
[可靠] 以下内容基于提供的上下文，有明确证据支持：
...正文...

[推断] 以下内容基于上下文片段推断，建议核实：
...正文...

[推测] 以下内容上下文覆盖不足，偏差可能性较大：
...正文...
```

**如果同一段中置信度不一**，逐句标记：

```
[可靠] 上下文明确提到，2024年营收为1.2亿元。
[推断] 按此增速推算，2025年营收可能达到1.5亿元。
[推测] 该增速可能受行业政策影响，但上下文中未提供相关政策信息。
```

### 1.4 不适用场景

以下场景不需要置信度标记：
- 纯代码生成（代码正确性由编译器/测试验证）
- 情感交流、闲聊
- 用户明确说"不需要标记"
- 纯格式转换类任务

## 2. 输出前自检清单

每次 LLM 输出前，必须逐项确认以下清单。发现问题的项，在输出中明确标注。

### P0 强制检查（必检）

- [ ] 所有数值是否来自提供的上下文或用户输入？（不是来自训练数据）
- [ ] 所有引用是否有明确来源？（人名、文档名、链接等）
- [ ] 是否存在"可能/也许/大概"等模糊表述但未标注置信度？
- [ ] 是否编造了不存在的文档、章节、链接、人名？
- [ ] 是否在上下文不足时强行给出了确定答案？

### P1 建议检查（尽力）

- [ ] 是否存在与之前回答矛盾的内容？
- [ ] 是否将时间先后关系错误表述为因果关系？

## 3. 魔鬼代言人（反向论证）机制

### 3.1 触发条件

**触发场景**（必须执行）：

| 场景 | 典型示例 |
|------|------|
| 方案设计 | "帮我设计一个用户认证系统" |
| 架构讨论 | "微服务和单体哪个更适合" |
| 分析报告 | "分析这个市场的竞争格局" |
| 调研结论 | "调研了三款工具，结论是..." |
| 决策建议 | "我该选 A 还是 B" |

**不触发场景**：

| 场景 | 原因 |
|------|------|
| 简单问答/事实查询 | 不涉及判断 |
| 纯代码生成（非架构选择） | 编译器/测试验证 |
| 情感交流/闲聊 | 过度设计 |
| 用户明确说"不需要" | 尊重用户 |

### 3.2 执行步骤

```
第1步：生成正方方案/分析/结论
第2步：声明切换视角 → "现在切换为魔鬼代言人视角，审视上述内容。"
第3步：执行反方论证（必须满足 3.3 节 P0 核心要求）
第4步：给出综合评估（必须满足 3.4 节 Q4 要求）
第5步：恢复正方视角，确认最终输出
```

### 3.3 P0 核心要求（强制执行）

| 编号 | 要求 | 检查标准 |
|:---:|------|------|
| **F1** | **核心假设摧毁** | 找出正方方案最依赖的假设，分析如果该假设不成立，方案是否仍然有效。不能挑不重要的小假设，必须挑最关键的。 |
| **F2** | **极端情景推演** | 推演最坏情况下的后果。不是"可能发生什么"，而是"如果最糟的情况发生，会怎样"。 |
| **F3** | **利益相关者视角切换** | 至少从一个正方方案未覆盖的视角（运维/用户/攻击者/监管者/财务等）进行分析。 |

### 3.4 P1 质量要求（尽力执行）

| 编号 | 要求 | 检查标准 |
|:---:|------|------|
| **Q1** | **带推理路径** | 每个反方观点必须附带从前提→推导→结论的完整链条。禁止空洞反对（如"可能有问题""也许不对"）。 |
| **Q2** | **篇幅控制** | 反方论证占正方内容的 20%-50%，最低不少于 100 字。正方内容短于 200 字时，反方论证可超过 50%。 |
| **Q3** | **优先级排序** | 呈现最关键的 1-3 个反方观点，其余一句话概括。不追求面面俱到。 |
| **Q4** | **综合评估** | 必须给出：倾向性判断 + 关键验证点 + 置信度。置信度与反方论证深度挂钩——如果反方论证因篇幅受限而简化，置信度必须相应降低。 |
| **Q5** | **虚假平衡防护** | 区分"合理替代观点"与"已证伪立场"。后者需标注"与主流共识相悖，仅供参考思考边界"。如果确实找不到有分量的反方论据，诚实说明，不要强行编造。 |

### 3.5 输出格式模板

```
---

## 魔鬼代言人 | 反向论证

> 以下内容专门挑战上述方案的假设与逻辑，目的是发现盲点，不代表最终结论。

**核心假设挑战**
[如果{核心假设}不成立，会怎样...]

**替代视角**（从{未覆盖的视角}出发）
[该视角下看到的问题...]

**极端情景**
[最坏情况推演...]

**综合评估**
倾向：{正反平衡后的判断}
置信度：{高/中/低}（因{理由}）
决策前需验证：
1. {关键验证点}
2. ...
```

## 4. 局限性声明

1. **本规则非银弹**：规则和 Prompt 能降低幻觉风险，但不能消除。尤其在非检索场景（纯 LLM 生成），置信度标记依赖模型自评估，可靠性有限。
2. **阈值需领域校准**：0.4/0.7 为通用建议值，不同领域（法律/医疗/金融）可能需要不同阈值。
3. **反向论证可能引入新幻觉**：反方观点本身可能包含事实性错误，用户需保持同等程度的质疑。
4. **本规则仅实现第一步**：规则层 + Prompt 模板层。如需自动化幻觉检测（SelfCheckGPT/DeepEval）或多 Agent 交叉验证，需自行扩展。
