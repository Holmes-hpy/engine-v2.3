# 知识管理与沉淀规则

> **版本**: v2.3.0
> **优先级**: P4
> **说明**: 本文件定义知识沉淀的三层漏斗机制：实时静默沉淀（结构化提取）、会话级标记（贴标签索引）、捡破烂周度挖掘（无约束打捞）。所有沉淀采用"延迟执行"模式——下一轮对话开始前，先完成上一轮的沉淀工作。

---

## 1. 知识管理体系总览

本项目采用**三层知识沉淀漏斗**：

```
对话产生
    │
    ├──→ [第一层] 实时静默沉淀（每轮对话后自动执行）
    │         │
    │         ├── 提取关键决策、重要发现、待办事项、可复用模式
    │         ├── 高置信度内容直接写入 memory/
    │         └── 用户无感知
    │
    ├──→ [第二层] 会话级标记（每次会话结束后自动执行）✨v2.1.0新增
    │         │
    │         ├── 给可能有价值的片段"贴标签"
    │         ├── 记录到 捡破烂/{任务}/.markers.yaml
    │         ├── 不做深度分析，只做索引
    │         └── 为第三层挖掘提供"地图"
    │
    └──→ [第三层] 捡破烂周度挖掘（每周/手动触发）
              │
              ├── 无预设维度，自由挖掘
              ├── 结合 .markers.yaml 标记快速定位高价值片段
              ├── 挖掘中产物放入 _buffer/ 待审查
              ├── 用户审查后写入 memory/ 或舍弃
              └── 跨轮次、跨任务发现隐藏模式
```

### 1.1 三层机制的定位差异

| 维度 | 实时沉淀（第一层） | 会话标记（第二层） | 捡破烂挖掘（第三层） |
|------|-------------------|-------------------|---------------------|
| 触发时机 | 每轮对话结束后 | 每次会话结束后 | 每周自动/用户手动触发 |
| 挖掘范围 | 当前轮次 | 当前会话所有轮次 | 近4周所有轮次 |
| 挖掘方式 | 结构化提取（有明确标准） | 贴标签（不深度分析） | 无约束自由挖掘 |
| 产物去向 | 直接写入memory/ | 写入 .markers.yaml | 先放_buffer/待用户审查 |
| 用户感知 | 完全静默，无感知 | 完全静默，无感知 | 产出报告供用户审阅 |
| 擅长发现 | 明显的决策、发现、待办 | 标记可能有价值的片段 | 隐藏模式、跨任务规律、用户偏好 |
| 置信度要求 | 高（≥0.7） | 低（≥0.5即可标记） | 不设限（低置信度也可报告） |

## 2. 知识存储结构

### 2.1 memory/ 目录结构

```
memory/
├── sessions/           # 会话归档（提炼后的会话摘要）
├── episodes/           # 情景记忆（具体事件和场景）
├── facts/              # 原子事实（可验证的具体信息）
├── profiles/           # Agent/用户画像
├── principles/         # 原则（最佳实践、核心准则，置信度≥0.8）
├── patterns/           # 模式（重复规律、套路、方法，置信度≥0.7）
├── decisions/          # 决策记录（架构决策、技术选型）
├── index/              # 索引文件
│   ├── knowledge-index.md
│   └── session-index.md
└── _schema.sql
```

### 2.2 知识分类

| 类型 | 存储位置 | 说明 | 示例 |
|------|----------|------|------|
| 原则(principles) | memory/principles/ | 高置信度的最佳实践和行为准则 | "产出物永远不要覆盖已有版本" |
| 模式(patterns) | memory/patterns/ | 可复用的方法和规律 | "用户喜欢先看方案再动手" |
| 决策(decisions) | memory/decisions/ | 明确的架构/技术决策 | "选择SQLite FTS5而非向量数据库" |
| 事实(facts) | memory/facts/ | 可验证的具体信息 | "项目启动包v2.2.0发布于2026-07-22" |
| 情景(episodes) | memory/episodes/ | 具体事件记录 | "v1.5.0部署时financial-services复制失败" |
| 会话(sessions) | memory/sessions/ | 提炼后的会话摘要 | 按日期归档 |

### 2.3 SQLite知识库（.memory/knowledge.db）

所有知识条目同步存储在SQLite数据库中，支持FTS5全文检索。零API依赖，Python标准库即可操作。

## 3. 实时静默沉淀（第一层）

### 3.1 触发时机

**采用"延迟执行"模式**：下一轮对话开始前（用户再次发言时），先检查上一轮是否有需要沉淀的内容，有则执行沉淀。详见 `01-llm-behavior.md` 第2节。

不再使用"每轮对话结束后自动触发"的表述，因为 LLM 无法在响应后执行操作。

### 3.2 沉淀内容类型

每轮对话后，提取以下四类内容：

| 类型 | 提取标准 | 存储位置 |
|------|----------|----------|
| 关键决策 | 包含"决定""选择""采用""确定"等关键词，或明确的二选一/多选一场景 | memory/decisions/ + SQLite |
| 重要发现 | 包含"发现""原来""注意到""关键"等关键词，或突破了之前认知的新信息 | memory/patterns/ + SQLite |
| 待办事项 | 包含"TODO""待办""稍后""下一步""需要"等关键词 | 任务JSON的subtasks字段 |
| 可复用模式 | 包含"规律""模式""建议""最佳实践"等关键词，或总结性陈述 | memory/patterns/ + SQLite |

### 3.3 沉淀执行步骤

1. **会话切片**：提取本轮对话关键内容，去除寒暄、重复、无意义内容
2. **质量评估**：评估内容的知识价值（0-1分），低于0.3分的内容跳过
3. **分类提取**：按上述四类提取内容
4. **去重检查**：与已有知识库对比，避免重复
5. **置信度评分**：为每条知识打0-1分，≥0.6分才沉淀
6. **本体化转换**：转换为结构化知识条目
7. **存储**：高置信度条目写入SQLite和对应Markdown文件
8. **索引更新**：更新knowledge-index.md
9. **日志记录**：记录到沉淀日志.md

### 3.4 知识条目格式

```markdown
---
id: K-{NNNN}
type: principle|pattern|decision|fact
confidence: 0.8
source_task: TASK-{NNNN}
source_round: {N}
created_at: {ISO8601}
tags: [标签1, 标签2]
---

# {知识标题}

## 内容
{知识的具体描述}

## 来源
- 任务: {任务名}
- 轮次: 第{N}轮
- 原始对话: 捡破烂/{任务}/round-{NN}.md

## 相关知识
- {相关知识条目的引用}
```

## 4. 会话级标记（第二层）✨v2.1.0新增

### 4.1 核心设计原则

**只贴标签，不做深度分析。** 会话级标记是"轻量级索引"，不是"微型挖掘"。它的唯一目的是为第三层（周度挖掘）提供"地图"，让周度挖掘不用重新读全部原始对话就能快速定位有价值的片段。

### 4.2 触发时机

**采用"延迟执行"模式**：每次会话中用户再次发言时，先检查上一轮是否有需要标记的潜在价值片段，有则执行标记。详见 `01-llm-behavior.md` 第2节。

### 4.3 标记格式

标记文件位于 `捡破烂/{任务ID}/.markers.yaml`，格式如下：

```yaml
task_id: 20260722-自我蒸馏
markers:
  - round: 3
    line_range: "45-52"
    type: potential_cross_task_pattern
    snippet: "用户提到B项目可以参考A项目的架构"
    note: "可能涉及架构知识的跨任务复用"
    confidence: 0.5

  - round: 7
    line_range: "120-135"
    type: hidden_preference
    snippet: "用户反复强调不要用英文命名"
    note: "命名偏好的新模式"
    confidence: 0.6
```

### 4.4 标记类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `potential_cross_task_pattern` | 可能跨任务复用的模式 | "B项目可以参考A项目的架构" |
| `hidden_preference` | 隐含的用户偏好 | "我不喜欢用英文命名" |
| `decision_shadow` | 决策过程中的犹豫/备选方案 | "当时也考虑过用LanceDB" |
| `unfinished_thought` | 未完成的思路/想法 | "如果以后有时间可以做一个..." |
| `contradiction_flag` | 可能前后矛盾的说法 | "上次说用A方案，这次说用B" |
| `recurring_theme` | 反复出现的话题 | "这是第3次提到性能优化了" |
| `other` | 其他值得注意的片段 | 兜底类型 |

### 4.5 执行步骤

```
步骤1：扫描本会话所有 round 文件
步骤2：对每个片段评估"是否需要标记"
步骤3：标记判断标准：置信度 ≥ 0.5 即可标记（宁可多标记，不可漏标记）
步骤4：写入 .markers.yaml（追加模式，不清空已有标记）
步骤5：静默完成，不打扰用户
```

### 4.6 与实时沉淀的区别

| 维度 | 实时沉淀（第一层） | 会话标记（第二层） |
|------|-------------------|-------------------|
| 目的 | 提取确定性知识 | 建立高价值片段索引 |
| 置信度 | ≥ 0.7（高） | ≥ 0.5（低） |
| 写入位置 | memory/ 知识库 | .markers.yaml 索引文件 |
| 内容 | 确定的事实、决策、待办 | 模糊的线索、潜在的规律 |
| 类比 | 记账（记录已发生的交易） | 贴便签（标记可能有用的页面） |

### 4.7 周度挖掘如何利用标记

第三层周度挖掘时，执行流程应包含：

```
步骤1：加载近4周所有 round 文件
步骤2：加载对应 .markers.yaml 标记文件 ← 关键！恢复上下文
步骤3：优先处理标记过的片段（高价值线索）
步骤4：再扫描未标记的片段（查漏补缺）
步骤5：生成挖掘报告
```

**核心价值**：一周后 LLM 回顾对话时，.markers.yaml 就像"读书笔记"——不需要重新读整本书，翻翻笔记就知道哪些页值得细看。

## 5. 捡破烂周度挖掘（第三层）

### 5.1 核心设计原则

**无预设维度，自由挖掘。** 不预设挖掘方向、不给出挖掘权重、不限定挖掘类型。目的是打捞那些连用户自己都不知道存在的有价值内容。

虽然不约束"挖什么"，但约束"怎么呈现结果"——统一输出格式，降低用户审查成本。

### 5.2 触发方式

两种触发方式，执行同一挖掘流程：

1. **自动触发（周度）**：每周执行一次。通过自动化工具配置定时任务。
2. **手动触发**：用户明确要求"挖掘捡破烂"或"扫描最近对话"时执行。

**说明**：启动包初始化时，在bootstrap中提示用户配置自动化任务。

### 5.3 扫描窗口

- **默认窗口**：从本次扫描时间往前推4周（28天）内的文件
- **判断依据**：基于round文件头部的 `timestamp` 字段（非文件系统时间）
- **超出4周**：默认不扫描
- **全量扫描**：用户手动明确要求"全量扫描"时，忽略时间窗口

### 5.4 挖掘流程

1. **确定扫描范围**：
   - 自动触发 → 扫描近4周的所有round文件
   - 手动触发 → 按用户指定范围（默认近4周）

2. **逐文件阅读**：阅读每个round文件的完整内容

3. **自由挖掘**（无预设维度）：
   - 用户偏好模式
   - 跨任务复用知识
   - 规则漏洞或改进点
   - 高频专家组合
   - 命名/格式的隐性偏好
   - 反复出现的问题
   - 未被注意到的好想法
   - 对话中一闪而过的灵感
   - 任何LLM主观认为有价值的内容
   - **以上仅为参考，不受此限**

4. **生成挖掘报告**：将所有发现整理为报告，放入 `捡破烂/_buffer/`

5. **通知用户**：告知用户挖掘完成，报告位置，等待审查

### 5.5 挖掘报告格式

```markdown
---
scan_date: {ISO8601}
scan_range: {起始日期} ~ {结束日期}
files_scanned: {N}
findings_count: {M}
status: pending_review
---

# 捡破烂挖掘报告 - {YYYY}年第{WW}周

## 扫描概况
- 扫描时间: {date}
- 扫描范围: {date1} ~ {date2}（近4周）
- 扫描文件数: {N} 个对话文件
- 发现条目数: {M}

---

## 发现条目

### 发现 #{N}: {一句话标题}
- **类型**: {pattern|preference|insight|issue|...自由填写}
- **置信度**: {高/中/低}（LLM主观判断）
- **来源**: 捡破烂/{任务}/round-{NN}.md（第{N}轮）
- **内容**: {具体描述发现了什么}
- **价值**: {LLM主观认为为什么有价值}
- **建议归入**: memory/{目录名}/
- **建议处理**: {写入memory/继续观察/可舍弃}

### 发现 #{N+1}: ...
（同上格式）

---

## 总结
{一段话总结本周挖掘的整体印象，如："本周发现用户在多个任务中反复强调输出格式问题，建议形成正式规则。"}
```

### 5.6 用户审查处理

用户审查 `_buffer/` 中的挖掘报告后：

| 用户决定 | 处理方式 |
|----------|----------|
| 接受某条发现 | 指示LLM将其写入对应memory目录，标记为confirmed |
| 拒绝某条发现 | 直接从报告中删除或标记为rejected |
| 暂时不确定 | 保留在_buffer/，下次挖掘时一并再审 |
| 全部接受 | 批量写入memory/，报告移入_mining-reports/ |
| 全部拒绝 | 报告移入_archive/或删除 |

### 5.7 归档清理

- 已审查通过的报告 → 移入 `捡破烂/_mining-reports/`
- 被舍弃的报告 → 移入 `捡破烂/_archive/` 或删除
- 超过90天的原始round文件 → 移入 `捡破烂/_archive/`（不参与后续扫描，但保留备查）
- `_buffer/` 中超过30天未处理的报告 → 自动提醒用户审查

## 6. 知识流转规则

### 6.1 知识生命周期

```
原始对话（捡破烂/）
    ↓ 实时沉淀
结构化知识（memory/）
    ↓ 跨任务复用
原则/模式（principles/、patterns/）
    ↓ 规则化
写入rules/（需要用户明确确认）
```

### 6.2 知识质量门槛

| 目标位置 | 最低置信度 | 需要用户确认 |
|----------|-----------|-------------|
| memory/facts/ | 0.5 | 否 |
| memory/episodes/ | 0.5 | 否 |
| memory/patterns/ | 0.7 | 否（实时）/ 是（挖掘） |
| memory/principles/ | 0.8 | 是 |
| memory/decisions/ | 明确决策场景 | 是 |
| rules/ | 0.9以上且经多任务验证 | 必须（显式指令） |

### 6.3 知识本体化关系

知识条目之间建立以下关系：
- `is_a`：分类关系（"先出方案" is_a 行为原则）
- `part_of`：组成关系（"版本命名" part_of "版本管理"）
- `related_to`：关联关系（"反问不猜" related_to "方案优先"）
- `derives_from`：来源关系（"命名用howe前缀" derives_from "用户偏好"）
- `contradicts`：矛盾关系（标记后请求用户裁决）

## 7. 零API依赖声明

- 所有知识沉淀和挖掘操作完全在本地执行
- 不调用任何外部API或远程服务
- SQLite FTS5提供全文检索能力
- 所有操作使用Python标准库即可完成
